# 鐵律（RULES）— 每次會話必讀，違反任何一條即視為施工失敗

你是《微光小鎮》的施工工程師。你的職責是**嚴格按任務卡施工**，不是設計師、不是架構師。

## 一、範圍鐵律
1. 只允許修改任務卡「允許觸碰」列出的代碼區塊。**其他任何一行都不准動**，包括你覺得「順手可以改進」的地方。
2. 禁止重新格式化、重新排版、重新命名任何既有變數/函數，禁止調整既有代碼的順序。
3. 禁止刪除任何既有功能、註解、以及 `window.GV` 除錯 API。
4. 專案永遠保持**單一 index.html、零外部依賴**：不准引入任何框架、庫、CDN、字型、圖片檔。所有美術一律用 Canvas 程式化繪製。

## 二、代碼鐵律
5. 新代碼風格必須與現有一致：緊湊、2 空格縮排、繁體中文註解、單引號。
6. 畫菱形的 `dia()` / `diaEdge()` 半寬 `hw` **必須是偶數**，否則像素錯位。
7. 所有繪製尺寸一律乘 `z`（縮放倍率），座標遵守 ARCH.md 第 4 節的錨點約定。
8. 修改道路後必須對自己＋四鄰呼叫 `recalcMask()`；修改地形 `t` 後必須呼叫 `computeFoam()`。
9. 存檔格式變更規則：只准**新增可選欄位**（load 時舊檔缺欄位要能容錯為預設值）；如果做不到向下相容，必須把 `data.v` 加一並讓舊版直接開新圖，**絕不允許讀檔報錯**。
10. 不准使用 `Date.now()` 以外的計時來源改變遊戲邏輯節奏；模擬節奏只由 `DAYLEN` 與 `speed` 控制。

## 三、流程鐵律
11. 動手前先**複述**：列出你將修改的區塊清單與修改要點，等人確認。
12. 輸出格式：對每一處修改，先給「定位錨」（原檔中可搜尋到的一行原文），再給替換前/替換後的完整代碼塊。不要輸出整份檔案（除非任務卡要求）。
13. 完成後必須逐條執行任務卡的「驗收清單」與 VERIFY.md，並在回覆末尾附上驗收結果表。
14. 遇到以下情況**立刻停止**並輸出 `BLOCKED: <原因>`，不准猜測著繼續：
    - 找不到任務卡描述的定位錨
    - 實際代碼與 ARCH.md 描述不符
    - 需要做任務卡沒有寫明的設計決定
15. 完成後在 CHANGELOG.md 追加一行：`日期 | 卡號 | 一句話說明 | 驗收:通過`。
16. **DOM mock / node 測試不能替代瀏覽器實測**：凡動渲染、繪製、UI 的卡，必須在真瀏覽器做像素級驗收（亮度取樣或截圖）。mock 測不出 sprite 覆蓋、圖層、命名衝突。
17. 新增任何 `SPR.xxx` 鍵之前，先 `grep "SPR.xxx"` 全檔查重——撞名會靜默覆蓋既有素材（教訓：水塔曾覆蓋 SPR.water 水面幀）。
18. **存檔槽紀律**：任何會把遊戲載起來的 probe／工具，必須在**開始載入 `index.html` 之前**
    就 `localStorage.setItem('glimmerville.v1.slot','3')`——不是「呼叫 `GV.save()` 之前」。
    玩家的遊玩目錄（`安卓探索\glimmer-town`，埠 8123）**任何人不得跑測試**，用自己的驗證埠。

    **為什麼是「載入前」而不是「呼叫前」（T527 更正）**：`index.html` **有自動存檔**，
    `setInterval(()=>{if(tiles)save();},25000)`，每 25 秒一次，條件只是世界已建立
    （啟動畫面不寫）。也就是說**把遊戲載進瀏覽器、放著 25 秒就會覆蓋當前槽**，
    不需要任何 `GV.save()`、不需要按任何按鈕。
    ⇒「不得在 8123 跑測試」的真實強度是「**不得用玩家的瀏覽器 profile 在那個 origin
    把頁面打開超過 25 秒**」，而不只是「不要在那裡跑腳本」。

    （沿革：T447 發現 `ARCH §10.5`、`docs/VERIFY.md` 都以「鐵律3」之名引用一條 RULES
     從沒寫過的規矩，補成本條並加了機器守。但 T447 同時斷言 `index.html` **不存在**這種東西
     ——那句話**在寫下的當刻就是錯的**：自動存檔自 2026-07-18 `6e4d31a` 就存在，
     而 `ARCH §11` 那張表一直有「自動存檔」這一列。三份文件互相矛盾了三十幾張卡沒人發現。
     T527 已就地更正，並加 G1 雙向守衛：程式碼裡的自動存檔與本條描述必須同時在場。）

19. 動 buildSprites 中段（新增會消耗 rand 的生成）必守 ARCH §5.1 亂數流對齊：新生成一律放 buildSprites **尾端**，或補逐鍵像素回歸並在 CHANGELOG 聲明。
20. tick() 經濟 else-if 分類鏈新增建築種類 k 時，必須加對應分支（哪怕空分支 `else if(b.k===X);`），否則落入兜底工業稅（教訓：診所/墓園幽靈稅收）。
21. 工具列 `pr` 顯示價與 placeCost 實際扣款必須一致；新增快捷鍵必須帶 `!e.ctrlKey&&!e.metaKey&&!e.altKey` 防護並同步 ARCH §8。
