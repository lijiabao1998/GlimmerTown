# P03 Vessel Navigation & Berthing 1.0, independent candidate

Based on accepted P02 `b0dc527966bf0d55c6b124a2dd99488e30c8a213`. Main, Pages and paused direction are unchanged. No new cargo economy or fluid simulation.

Run `npm ci --ignore-scripts`, `node navigation-test.cjs`, `node build.cjs`, then serve this directory on a local preview port. Open `native-preview.html`. The vessel controls live in the existing expandable preview panel. Play runs both vessel and empty cranes; pause/resume/reset/seek are deterministic. Use “全航道” to see boundary entry/exit and “靠泊畫面” for quay detail. Nothing saves to player storage. Generated HTML is delivered as a CI artifact, not production deployment.

The native 72x72 candidate map has water from row 35 to its actual lower boundary; the retained 26x23 harbor region contains exactly 208 water cells. Navigation reads actual native tile types, roads and buildings. It does not invent a screen-space path or mutate tiles. A heading-aware A* uses straight segments and radius-4 quarter turns, rejecting each edge unless the entire 5x1.4 hull fits a continuous conservative swept envelope. The exterior portal is limited to the actual connected boundary opening. The same hull dimensions bound the visible vessel.

The approximately 126.812-second loop includes waiting, inbound, deceleration/berthing, six-second dwell, unberthing and outbound. After the complete hull leaves the map, the off-map queue changes heading for the next cycle; no visible teleport occurs. Acceleration is an explicit synthetic trapezoidal speed profile, not claimed hydrodynamics. The 17-pixel ship maximum remains below the P02 spreader's minimum 20-pixel height. Geometry tests remain independent from visual sorting evidence.

Rendering uses native projection and the native object depth queue. Only ship faces are generated for the current time; port atlases are not rebaked. Separate P03 OFF restores actual P02 pixels; the unchanged P02 tests retain P01-C rollback. Main fingerprints and tests are copied verbatim into the candidate regression orchestrator, with generated P03 runtime as the overlay. Official workflow also runs the unchanged 42-check and 44-check browser suites from P02.

`failures/` preserves the initial rejected turn radius and build failure. `chromium-p03/result.json` records raw paired synchronous timings, p95 tails, cold planning/startup, full real-time cycle rAF, caches, bake counts and simulation-state checks. These are evidence, not new relaxed production gates. New art requires normal review before any eventual formal release. P04/P05 are not implemented.
