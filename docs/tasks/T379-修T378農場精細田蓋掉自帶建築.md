## 覆核方法的缺口（本卡最該記的一條）

T378 覆核時我做了 atlas 指紋全比對，結論「204 變動鍵、零不可解釋漂移」。
那條檢查證明的是「**沒有不該變的鍵變動**」，**不是**「該變的鍵變對了」。
k22 的 16 個鍵本來就在預期變動清單裡，所以指紋比對對這個回歸**結構性失明**。

而 T378 卡面第 100-108 行我自己寫過：「放大後…**不得蓋到農場自帶的穀倉／建築（各變體自查）**」——
施工者沒自查，我覆核時也沒驗。**指紋比對必須配一條「預期變動鍵的視覺正確性」檢查**，
否則「零漂移」只是「壞的地方剛好在白名單裡」。這條寫進 COLLAB（見下）。

## 要改什麼（三處，範圍極小）

### 1. `index.html`：k22 的 doFarm 參數回復

```js
// 現況（T378）
doFarm('22_1_'+v,68,148,52,26,CCLASS[v]);
// 改回
doFarm('22_1_'+v,68,148,30,15,CCLASS[v]);
```

**為什麼是回復而不是另尋尺寸**：自帶建築就坐在田心 `(68,132)` 上，任何放大都吃掉更多。
要同時兼顧「田大」與「不蓋建築」必須**移動田的位置**（像 k53 把四塊作物擺在農莊四周），
那是逐變體的美術工作 ⇒ **另卡**。本卡只做「證明可行的最小回歸修復」。

「大空地中央擠一小塊田」是我在 T378 卡面的**美學推測**，不是玩家回報；
玩家實際回報的是遮蔽。**真 bug 優先於推測改良。**

### 2. `test_fixde.js`：修 T378 的 K4 斷言（必要的既有斷言修改）

T378 加了 `assert(/doFarm\('22_1_'\+v,68,148,52,26,CCLASS\[v\]\)/.test(html), 'T378：k22 doFarm 精細田應放大至 hw52/hh26')`。
回復參數會讓它紅 ⇒ **本卡明示授權修改該行**，改為釘住 `30,15` 並在訊息裡註明 T379 回歸原因。

### 3. `test_fixde.js`：新增 L1 守衛（防這一類回歸）

**靜態幾何守衛**（Node 端 canvas 是樁，量不到像素，所以改算幾何 —— 這是可行且會咬的）：

1. 從 `doFarm('22_1_'+v,68,148,HW,HH,…)` 解析 `HW/HH`；
2. 從 k22 各變體區塊解析 `fillRect(ax±dx,ay±dy,w,h)` 得建築矩形；
3. 逐列計算矩形與田菱形（中心 `(68,132)`）的交集面積；
4. 斷言 16 變體**合計覆蓋 ≤ 2400 px**（實測基線 2289，留 5% 餘裕）。

先斷言「解析到 16 個變體、每個變體 ≥1 個矩形」防空過。
