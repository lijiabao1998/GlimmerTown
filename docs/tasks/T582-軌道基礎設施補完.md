## 2. 手法（六件，全烘焙＋繪製端條件，零亂數、零模擬改動）

1. **軌道橋補完**：把道路橋已驗證的四件照搬到 `railBridge`／`tramBridgeT`——底面陰影條、
   橋面朝連接方向四向延伸（修掉相鄰橋格之間的斷面）、橋墩＋腳座、側護欄。
   幾何常數直接複用 `:3763-3783`，不自創。輕軌橋用冷色系與重軌橋區分。
2. **車擋與孤立格收頭**：`popcount(m)<=1` 時在格心沿軸畫車擋（加厚枕木堆＋擋塊＋紅白斜紋反光板）；
   `m=0` 另補一段短軌樁，讓孤立格從「一塊爛泥」變成「還沒接上的鐵路」。
3. **輕軌凹槽**：`railTrack` 加 `cfg.groove`，在鋼軌內側 1px 畫暗溝，把註解宣稱的東西真的畫出來
   （順帶讓輕軌與重軌在遠景就分得開）。
4. **道碴坡腳與鋼軌接地**（T567 收邊語彙搬到軌道）：道碴橫向邊緣加第三色坡腳暗帶、
   鋼軌落點正下方補接地陰影、枕木下緣補落影。只在 `ballast` 分支內，輕軌不受影響。
5. **架空線吊點對齊**：接觸網從 `tramTrack`（64×32，畫不到橫臂高度）移出，改為獨立的
   `SPR.tramWire[m]`（64×24，以負 y 偏移繪製），讓線**落在橫臂／絕緣子那一列**。
   `tramTrack` 的 `cfg.wire` 關閉。
6. **夜光接線**：街燈與橋燈的掛點條件擴到軌道格與軌道橋（`t.rail`／`t.railBridge`／`t.tramBridge`），
   沿用既有的 `SPR.bridgeLamp`＋`SPR.railWashWarm/Cool` 與 `streetHash` 稀疏閥。
   **零新增素材鍵**——這一件是純繪製端條件，且天然符合「先有燈具，才有光」（燈具 sprite 已存在且日間可見）。

## 3. 明確不動

模擬層（`updTrains`／`updTrams`／路網拓撲／`tramMask`／`railMask` 的產生與存檔）一律不動；
`t.rail`／`t.tram` 的旗標語意不動；道路／建築／植被／水岸素材不碰；
`tools/`／六哨兵／健康地板／T523 預算常數／亂數流不動。
**`SPR.rail` 生成處的 `speck(...,30,rand)` 消耗 30×3 次抽數，新增件一律零抽數**，否則亂數流位移。

## 4. 驗收（檔尾 T582 塊）

沿用 T581 建立的台架與判準（那套台架會**複製／鏡射／記顏色與 alpha／數裁切面積**）：

- **G1 橋樑四件齊備**：`railBridge`／`tramBridgeT` 必須有橋墩、護欄、底面陰影、四向延伸；
  以**與道路橋同源的幾何常數**比對（不是各寫一份），並斷言橋面覆蓋到格邊。
- **G2 收頭釘**：`popcount(m)<=1` 的遮罩必須有車擋落筆；`m=0` 不得再是空菱形。
- **G3 凹槽釘**：`tramTrack` 必須有凹槽色，且**重軌不得有**（雙向釘，防止一套幾何兩邊套）。
- **G4 道碴收邊釘**：坡腳第三色與接地陰影必須在場；輕軌（`ballast:false`）不得出現道碴色。
- **G5 吊點對齊釘（本卡核心）**：接觸網的螢幕 y 必須落在 `tramPole` 橫臂／絕緣子的同一列，
  誤差 ≤1px——**用兩者的實際繪製偏移算，不是各自重算一遍**（T581 G8 假釘判例）。
- **G6 夜光接線釘**：軌道格與軌道橋必須取得到燈具掛點；且**燈具 sprite 必須在日間可見**
  （先有燈具才有光——不得只 push 光而不畫燈）。
- **G7 零亂數**：新增段剝註解掃描，並斷言 `SPR.rail` 生成處的 `speck` 抽數未變。
- **G8 落點在畫布內**：沿用 T581 的 runtime 裁切偵測——任何落筆被畫布邊界吃掉即紅。
- **G9 指紋**：既有非軌道族零變動；軌道族的變更鍵數與新增鍵數**實測後記入卡面**。
- 紅源（位元法，最少六案，逐案「首紅 == 目標釘」）：
  ①拔橋墩→G1；②`m=0` 回空菱形→G2；③凹槽色改成鋼軌色→G3；
  ④接觸網 y 偏 2px→G5；⑤夜光掛點條件改回只有 `t.road`→G6；⑥新增件畫到畫布外→G8。
- `verify.py` ALL GREEN、PASS 只增不減、toolchain 綠、六哨兵位元恆等、T523 落筆不超紅線。
