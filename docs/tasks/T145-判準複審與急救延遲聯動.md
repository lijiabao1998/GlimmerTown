# T145 判準 5/6 複審＋急救延遲聯動（誠實補全）
版本：v4.0 ｜ 難度：★★ ｜ 前置：T119（服務派遣）、T129（壅堵場）｜ 建議模型：Sonnet

## 背景
超越判準 5 要求「交通壅堵持久場落地：load 場可重建、視覺染色、幸福懲罰、**且急救到場延遲與之聯動**」。T129 做了前三項，但「急救延遲聯動」未明確驗證——若服務車輛（救護車/消防車）移動不受 roadLoad 降速影響，則此條未完整達成。本卡誠實複審並補全。

## 定位錨
- `updCars` 車速降速（T129：`speed*=clamp(1-...load...)`）
- 服務派遣：`updDispatch`/`updAmbulances`/`updFireTrucks`（T119）、車輛移動
- 壅堵 `roadLoad`/`ROAD_CAP`（T129）

## 允許觸碰
- 稽核服務車輛移動路徑：確認其行進是否經過 roadLoad 降速。若服務車輛用獨立移動邏輯未吃壅堵降速，則**最小補接**：服務車輛所在路段 load 過載時同樣降速（複用 T129 折減公式），使壅堵真實延長急救/消防到場時間→損失加大，形成因果懲罰。
- 新增 `GV.svcResponseSample()` 或等效鉤子：可觀測某次派遣的到場 tick 數，供驗證壅堵前後差異（判準17 可觀測）。
- 稽核判準 6（地價 LAND 接財富/稅/圖層），確認完整。

## 硬性不變量
- **無壅堵（load=0）時服務車輛到場時間與改動前逐位元一致**（降速係數在 load≤cap 恆為 1）。
- 服務車輛仍必達目標（壅堵只延遲，不阻斷路徑）。
- 不消耗額外 R()；不改派遣目標選擇邏輯。

## 本卡驗收
1. 三件套照常。
2. 注入單一過載主幹道，該路段上的救護車/消防車到場 tick 數 > 無壅堵基準（GV 觀測到場延遲差異）；覆蓋外或無壅堵時到場時間不變。
3. 無壅堵城同種子位元回歸與基準一致。
4. 更新 docs/SURPASS.md：判準 5（含急救延遲聯動證據）、判準 6 誠實標記達成狀態。
