## 起因

fp（T643）與 ART_PINS（T646）釘的是「每張精靈圖」的像素，看不到繪製時才決定的東西：夜燈與光暈、倒影、遮擋與淡出、畫布合成順序、閥漏關的繪製路徑。標準 §3.3「每張新圖都要有逃生閥，閥關時整幀畫面與改動前逐位相同」到現在只有各批自己的台架在驗（release634／635），新批次沒有共用的機器檢查。T639 也承諾「非美術卡畫面零變、改圖時 CI 自動出接觸表」，業主看接觸表點頭＝`owner_ok`。

## 做什麼

1. 新 `tools/pages/frame-compare.cjs`：同一個釘版 Chromium 裡，base（`git show <base>:index.html`）與 head 各開分頁，畫同一組場景，逐幀比畫布 RGBA（頁內 sha256）。
   - 場景（不跑模擬，換玩法的卡不會連帶改畫面）：seed22、seed777 兩座存檔城市（`docs/tasks/t603-shots/fixtures`），消防局與園區、住商工、設施、工業四張陣列（直接寫地塊，按位置選款的批次每種放三份）。
   - 狀態：4 視角×晝夜、秋、雪晝夜；seed22 另加夜空遠景。每頁 67 幀。
   - 凍結：停模擬、清空行人車輛、星星固定、時鐘歸零；動畫細節層與冬季炊煙關掉（它們用 `Math.random`）。每幀畫到連續兩次逐位元組相同為止（按需烘焙跨幀收斂，最多 8 次）。
   - 判定（卡頭由 `tools/scope.py` 給）：
     - 純 revert 跳過；
     - base 在兩個獨立分頁必須逐幀相同，每幀要收斂——否則量具不穩，結束碼 3；
     - head 和 base 有任何一幀不同，卡頭 `owner_ok` 空就紅（非美術卡要畫面零變；美術卡要業主看接觸表點頭）；
     - 卡頭 `valve` 寫了逃生閥：head 打開這些閥後必須和 base 逐幀相同，否則紅（閥漏關）；
     - 有不同的幀就出接觸表：base｜head｜head+閥｜差異（紅），下面一列是差異區域放大。
   - `--self-test`：判定、卡頭解析、注入點的純函式測試，validate 會跑。
2. CI 新 `frame` job：比照 fp 用釘版 Playwright Chromium；工具優先取 base 的版本（base 還沒有就用 head 的，同 T643／T646 的起步）；接觸表與報告上傳成 `Town-main-frame-<sha>`；gate 加上 frame。
3. 文件：AGENTS（業主看接觸表點頭＝owner_ok）、標準 §3.3、COLLAB 分道說明。
