## 三件（業主已裁定，不得更改方向）

### 件一：`#toolcats` shrink-to-fit 修正

絕對定位元素只給 `left:50%`、不給 `right`/`width` 時，shrink-to-fit 可用寬度＝
**從 50% 到右邊界＝視窗一半**；`translateX(-50%)` 只是視覺推回中央，`max-width:96vw` 從無機會生效。
實測 `576÷2=288`＋內距 → `clientW=293`、`scrollW=392`、溢出 99px、**9 類只見 6 類**。

修法：加 `width:max-content`。實測後 392px、溢出 0、**9/9 可見**、仍置中。

### 件二：工具列摺疊／展開

業主原話：「手機無論多大豎版一列，然後右上角嘛，點開，最多三行，整齊排列，
然後橫屏幕最多一行，最多點開兩行。」

| 方向 | 預設 | 展開上限 |
|---|---|---|
| 直版 | 1 列 | **3 行** |
| 橫屏 | 1 列 | **2 行** |

展開鈕置於工具列**右上角**。預設緊湊、展開是明確動作（優於「永遠換行」，
因為工具少的類別不該平白長高）。

### 件三：`#info` 橫屏置中縮放

業主原話：「橫屏的不管多少屏幕，明細面板保留一定程度置中縮放。」
橫屏時 `#info` 改為水平置中、寬度隨視窗縮放並設上限，不再貼左下角。

### 件四：`#rci` 需求明細面板

`#rci`（日期旁三根需求條）是 **HUD 唯一沒有明細面板的指標**——
實測 `cursor:auto`、無任何事件綁定，六個晶片都有 `cursor:pointer` 與 `chipPanel` 分支。

資料源可完全分解（index.html:10873-10876）：

```js
dem[1] = clamp(jobSurplus*.7 + happyAdj*.3, -1, 1)              // 住宅
dem[2] = clamp((pop/max(1,czone) - 3)/6, -1, 1)                 // 商業
dem[3] = clamp((jobsC*.8 - jobsI)/40 + (indSubsidy?.15:0), -1, 1) // 工業
```

面板需逐項列出驅動值，直接回答「為什麼我的住宅不長」。
