## 為何不是重做 T265

`k62` 的玩法早已完成：T265 已交付 2×2 焚化發電廠、垃圾容量／供電／污染／垃圾車／存讀閉環；T266 已補資訊層；T267 已補 AI 選址決策。

現版 `SPR.bld['62_1_0']` 有精細靜態蒸汽，但刻意是 `smoke:[]`。原因是既有 `updSmoke()` 會呼叫 `ri()` 與 `Math.random()`；把 k62 接進去會改變含 k62 城市的亂數流。T363 只補「看得出它正在運轉」的視覺層，**不改也不重算任何垃圾、供電、污染或 AI 邏輯**。

## 目標

讓完工的 k62 在城市裡一眼可辨：

1. 垃圾量大於 0 時，煙囪上方出現低頻、半透明的淨化排氣；它是 draw-time 決定性圖樣，不是粒子狀態。
2. 夜間有低強度、可辨識的航標紅燈／汽機房冷光節奏，表現「夜班仍在運轉」。
3. `garbage===0` 時不畫活動排氣；靜態建築本體仍完全保留。這只讀既有狀態，絕不改變垃圾量或處理速率。
4. 提供總 A/B 開關 `window.__noWteFx`，供像素驗證與效能回退使用。

## 設計契約

1. 只對完工 root 生效：`b.k===62 && !b.ref && b.age>=9`；ref 格絕不可重複畫。
2. 動態排氣只在 `garbage>0`、`animOn`、非遠景 LOD、且 `!window.__noWteFx` 時畫出；位置、相位、透明度只可由 `visT`、格座標與 `streetHash()` 推導。
3. 排氣是直接 draw-time 幾何，**不得** push 進 `smokes[]`／`fxParts[]`，不得寫入 tile、building、世界狀態或存檔。
4. 夜班燈光只在既有 k62 結構範圍內加亮；排氣本身不可加入 `nightSprites`、`rdecGlow` 或污染圖層。
5. `__noWteFx=true` 時所有 T363 新像素皆為零；它不入存檔、不改 `animOn`、不影響既有 T265 靜態 sprite。
6. 同一個世界在開關前後，除 canvas 像素外，money／garbage／garbCap／powerCap／POL／建築資料與存檔 bytes 必須完全不變。
7. 若無法在既有 render 路徑達成以上契約，輸出 `BLOCKED`；不得以接入隨機粒子管線作為替代方案。
