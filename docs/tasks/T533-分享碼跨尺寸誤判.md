# T533 分享碼跨尺寸誤判（T262 遺留債；「朋友的大地圖城市你貼不進來」）

**日期**：2026-08-19　**發卡**：Claude（業主授權：自己玩→出卡→施工→合併）

## 0. 來源與實測

這條債在 **T412 收債時就入了檔**（「importShareCode 跨尺寸誤判（T262 遺留）」），本輪玩測兌現。

情境＝「朋友把他 108×108 的城市分享碼傳給你，你在 72×72 的世界裡貼上」：

| 步驟 | 結果 |
|---|---|
| ③ 同尺寸匯入（72 碼 → 72 世界） | ✅ true（基線正常） |
| ④ 跨尺寸匯入（108 碼 → 72 世界） | ❌ **false，玩家看到「分享碼無效」** |
| ⑤ **同一份 108 資料**直接寫槽走 `load()` | ✅ **true、N=108**——load 開得起來 ⇒ 拒絕是匯入閘門自己的誤判 |

## 1. 根因：同一條規則兩處各寫一份，T262 只更新了一份

T262 把地圖尺寸做成可變時，`load()` 的驗證改對了：
```js
const vlen=(dd)=>{const dn=+(dd&&dd.n)||72;return dd&&dd.v===1&&(dd.ter||'').length===dn*dn;};
...
{const dn=+(d.n)||72;if(dn!==N){N=dn;allocGrids();}}   // 任何合法存檔都能開
```
但 `importShareCode` 的閘門**忘了改**，還在用**當前執行期的 N**：
```js
if(!(d.v===1&&d.ter&&d.ter.length===N*N)){toast('分享碼無效','bad');return false;}
```
⇒ 尺寸不同的合法分享碼一律被拒。**與 T530（RDEP 判定 AI 有、玩家端沒有）、T518（七個死開關）
同一族病：同一條規則在兩處各寫一份，其中一份被忘記。**

## 2. 落地（T530 同型解法：抽單一真相源）

1. 抽 `saveShapeOk533(d)`＝「v===1 且 ter 長度等於**存檔自己宣告的** n²（缺 n＝72）」，
   `load()` 的 `vlen` 與 `importShareCode` 的閘門**都改讀它**。
2. 匯入成功後 `load()` 原本就會依 `d.n` 切換 N（T262 已做），零額外工作。
3. **不動 2,000,000 上限**：實測 216×216 成熟城分享碼 140,076 字＝仍有 93% 餘裕，上限沒問題。

## 3. 驗收計畫

- **G1（靈魂）交叉一致性**：形狀判定全檔只准寫一次（`dn*dn` 恰在真相源一處；
  `ter.length===N*N` 零處）——這條擋的正是本卡要修的病復發。
- **G2 行為（跨尺寸）**：108 城的分享碼在 72 世界匯入必須成功，且匯入後 `N===108`、
  步進一天後 pop 與來源城一致。
- **G3 行為（基線＋負向）**：同尺寸匯入照樣成功；**畸形碼（ter 長度與宣告的 n 不符）必須照樣被拒**
  ——單向放寬不准把驗證整個放掉。
- **G4 既有失敗保護不變**：垃圾碼／版本不符不覆蓋槽位（既有測試已在，跑綠即可）。
- 六哨兵位元恆等（匯入不在 tick 路徑）。
- 紅源：①匯入閘門改回裸寫 `N*N` → G1／②真相源退化恆真 → G3 畸形碼測試咬／
  ③load 的 vlen 自己再寫一份 `dn*dn` → G1 計數釘咬。
