# T416 — 就近站派遣(服務車輛派遣效率;DeepSeek 能力測試卡:開放設計面,中大型)

業主直令出複雜卡測試 DeepSeek。本卡與 T415 相反:**不鎖行,鎖目標與紅線**——
設計決策由施工方做,並在卡面「設計裁決」節寫清理由。這正是考題。

## 目標(定量,T411 已量測的開場白)

T411 定案:服務車輛(救護/消防/警察)單案平均壽命地板 **~28 遊戲日**,主因=
`updDispatch` 的**站點隨機挑選**(`sts[vri(sts.length)]`,平均跨半城行程)。
本卡改「**就近站派遣**」:為候選案挑最近站出車。**目標=壽命地板砍半**(28→15 前後,
以覆核方 800 天 A/B 量測為準)。

## 開工前必讀(這些卡面裡埋著會咬你的守衛,讀完再動手)

`docs/tasks/` 下:T402(vri 隔離+G2「恰 20 處」全帳守衛+G4 雙生子)、
T406(**roll-then-mask 先例**:骰照擲、結果覆寫=帳不動)、T409/T410(派遣呼叫行

## 設計自由度(你決定,卡面寫理由;覆核會審你的「為什麼」)

1. **距離度量**:Manhattan/Chebyshev/路網 BFS?注意這在幀路徑逐 spawn 執行,
   成本要論證(站點數 ≤ ~15,候選 ≤ ~30,量級自己算)。
2. **適用車隊**:救護/消防/警察三家 dispatch 型顯然適用;**垃圾/回收車是巡遊型**
   (candidates=路面格,到站再挑下一點)——就近語義對它是否成立,要論證,錯用=退修。
3. **vri 帳**:換掉 `sts[vri(sts.length)]` 會動 T402 G2「vri 恰 20 處」全帳。兩條路:
   a) roll-then-mask(T406 先例):`vri(sts.length)` 照擲、結果被最近站覆寫=帳不動;
   b) 真移除+G2 帳連帶重釘(20→N)+守衛文案更新。
   擇一並論證(提示:兩條路對「未來又有人動 vri」的防禦力不同)。
4. **配對策略**:現行是「隨機站×隨機案」逐車配對。就近化後,「案挑站」還是「站挑案」?
   多案搶同站怎麼辦?(不要求最優匹配,要求語義清楚+無餓死)。
