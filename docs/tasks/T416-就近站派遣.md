# 【施工結果】(DeepSeek, 2026-08-04，tip b59d74f 之後)

## 設計裁決節（覆核審「為什麼」的地方）

### ①距離度量 = **Manhattan（|dx|+|dy|）**
- **為什麼不是路網 BFS**：車的移動模型是每幀動一格（`c.x+=Math.sign(c.tx-c.x);else if(c.y!==c.ty)c.y+=Math.sign(c.ty-c.y)`）——曼哈頓步進，到場幀數精確等於 |dx|+|dy|。用 Manhattan 度量＝與實際行為**逐幀一致**（T416 G2b 實測：5 格案 max=41 幀、25 格案 208 幀，線性吻合 1 幀/格×車速倒數）。
- **BFS 反而失真**：車**不走路網**（曼哈頓穿格，無視水域/路網），路網 BFS 度量的「最短路」與車實際走的曼哈頓直線不一致——選了「正確的路網站」可能不是「實際最先到的站」。
- **成本**：每 spawn 一次全對掃描 = cand×sts ≤ 30×15 = 450 次加減，微秒級；while 迴圈最多補 cap（車隊 ≤ 40 上限、實際 2-8）次 → 每幀最壞 ~3600 ops，相對既有幀路徑（N² 掃描）可忽略。

### ②適用車隊 = **dispatch 型就近化；巡遊型（垃圾/回收）維持隨機**
- **論證為什麼垃圾車就近語義不成立**：垃圾車 cand=全市路面格（數百格），ti 只是「巡遊錨點」非「案」——onArrive 到一個路面格後再挑下一個路面格（巡遊覆蓋）。若對 ti 做「最近站」：車被鎖在站附近少數路面格 → 全城遠端垃圾無人清 → **覆蓋語義破壞**（救護/消防/警察的案是固定位置需求點，就近=更快到達；垃圾的「案」是整個路面空間，就近=覆蓋塌陷）。
- 實作：函式內 `const isCruise=arr===recycleTrucks` 區分（呼叫行原文釘不動）。垃圾車仍從隨機站出發——省站程不是它的性能指標，覆蓋均勻才是。

### ③vri 帳 = **第三條路：帳 20 不動**（dispatch 分支零 vri、巡遊分支保 vri）
- **為什麼不選 roll-then-mask**：a) 假骰（vri 骰了但結果被覆寫）＝T413b C8 譴責的「no-op 佔位=用註冊口數字說謊」形態；b) 致命漏洞：未來有人「拿掉 mask 恢復隨機」——vri 呼叫還在（帳仍 20），G2 **完全失明**。
- **為什麼不選真移除+重釘**：動 T402 既有位元契約（20→18＋文案），擴大 diff 風險；且重釘後「帳 18」的語義是「updDispatch 無 vri」——但垃圾車巡遊**本來就需要 vri**（隨機路面格是巡遊本體），重釘是在為「正確保留 vri」付稅。
- **我的方案**：dispatch 分支純決定性（0 vri），巡遊分支保 vri（2 vri，**真用**）→ 帳 20 恆等、G2 一字不動。防禦力（破壞性案1 活體證明）：未來任何人把 dispatch 改回隨機 → 帳 22 ≠ 20 → **G2 當場紅**。比 roll-then-mask 強（假骰下恢復隨機帳不變=失明）、比重釘乾淨（零既有守衛改動）。

### ④配對策略 = **案挑站・最近案優先（greedy 吞吐；三輪覆核由 max-min 更正）**
- **案挑站 vs 站挑案**：站挑案（每站挑最近案）會讓近站被近案搶光、遠站空轉 miss 案（站數量級 < 案）；案挑站（每案配最近站）語義與目標一致——「為候選案挑最近站出車」。
- **max-min（最遠案優先）為什麼被否決（三輪覆核四臂 800 天）**：壽命地板由**最遠的案**決定（max 距離），乍看挑「離最近站距離最大」的案先服務＝max-min 公平。但車隊容量受限時（cap=min(車隊 2-5, 站數)），把稀缺的車派給最遠案 ⇒ 每台車被綁最久 ⇒ **單位時間清案數崩塌**；佇列才是壽命地板大頭，不是行程。四臂 C（max-min+保流）vs D（最近案優先+保流）唯一差異是排序方向一個字元：seed301 −20% vs **−48%**、seed22 +3% vs **−43%**（廢棄日 2187→11、人口 574→4641，犯罪→廢棄→經濟死亡螺旋被打斷）、seed7 +27% vs **−15%**。
- **「無餓死」擔憂無實據**：廢棄日=案件活過 15 天門檻的積分＝餓死直接代理，greedy 下 seed22 廢棄日 11（vs max-min 1978）——清得夠快，佇列自然排空，餓死不成立。出卡方措辭「不要求最優匹配，要求語義清楚+無餓死」把施工方推向公平性優先，實測顯示該約束在容量受限系統下反效果（三輪覆核③已更正）。
- **多案搶同站（二輪退修更正：接受站點重用）**：覆核方直接探針顯示兩案可從同一最近站出車（站點重用）——車隊 cap ≤ 站數（target=min(cap,sts.length)）保證車數不超站數，但**不消耗站**（多案可共用最近站）。這是刻意接受的設計：站是「出發點」不是「配額」，多車從同站出發處理不同案是正確語義（站本身就是車庫，出多輛車理所當然）；真正要防的是「同案被多車重複鎖定」（配對後消耗，G3/G4 咬）。原文案「另一案配次近站」與實作矛盾，**二輪退修修正為站點重用**。
