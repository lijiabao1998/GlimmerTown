# T518 死開關修復（七個政策點不動）＋UI 綁定行為守衛

**日期**：2026-08-18　**發卡**：Claude（業主授權：自己玩→出卡→施工→合併）
**性質**：**玩測抓到的 shipped bug 修復**——玩家端 v11.146 現正發生。

## 0. 現象與證據（行為量測，非源碼推論）

真瀏覽器逐一點擊 📊 面板裡 62 個政策 checkbox、每次點擊後比對 `GV.pol()` 快照：

```
✅ 點得動 55
❌ 點不動 7：polcongChg451 polrentCtrl452 pollvt453 polminWage454
              polecMix457 polaggCluster458 polcleanAir459
```

**死掉的正好是 T451/T452/T453/T454/T457/T458/T459 七張城市科學卡的政策**——
玩家在面板上勾它們，什麼事都不會發生。

## 1. 根因

T514（科學政策指揮台）把政策列改成 `sciCard514` 卡片，checkbox 的 DOM id 由
`polDomId514(pk)` 產生＝`SCI_DOM_ID514[pk] || ('pol'+pk)`。

- Grok 波（T464-T510）的 51 張卡當初就用 `'#pol'+polKey` 命名 ⇒ 與 fallback 恰好一致 ⇒ 存活。
- 我的七張（T451-T459）用的是縮寫 id（`#polCong451`／`#polClean459`…），**既不在
  `SCI_DOM_ID514` 表內，也不等於 `'pol'+polKey`** ⇒ `polToggle` 綁到一個**不存在的元素**上。
- 連帶：**T459 的 `recomputePolAll459()` after 回調一起死了**——那正是 T459 G1d 立來防的
  staleness（開了空品管制但污染場不重掃）。

## 2. 為什麼 5,608 條守衛全綠卻沒抓到

七條 `polToggle('#polCong451',…)` 的**原文都還在**，守衛（含 T459 G1d）驗的是原文在場。
**原文在場、它指向的 DOM 元素不在場**——這是「假綠」的系統級版本：
*守衛守著一條指向不存在元素的字串*。同型教訓已有三次（T446 空跑守衛、T437 raw.some 假綠、
T456 pop 釘假綠），本次是第四次，且第一次真的傷到玩家。

## 3. 修復（消除「兩份 id 真相」）

七處 `polToggle` 的選擇器改為由 `polDomId514(polKey)` 導出——**DOM id 只有一個真相源**。
不動任何 fx 常數、不動 tick、不動存檔 ⇒ 六哨兵位元恆等。

## 4. 新守衛型：UI 綁定行為釘（本卡真正的產出）

`G_ALIVE`：開啟 📊 面板，**逐一 click 每個 `.sciCard514` checkbox，斷言 `GV.pol()` 真的翻轉**，
零死開關；並專驗 `cleanAir459` 點下去後 `polSum` 立降（after 回調確實跑到）。
探針紀律寫進守衛：**每次點擊前重新查詢元素**（面板每次 toggle 都重繪，快取住的元素會脫離 DOM——
第一版探針就是這樣量出「61 個假死」）。

紅源三案：①把某一條 polToggle 的 id 改回舊縮寫 ⇒ 該開關死 ⇒ G_ALIVE 紅；
②拆掉 cleanAir 的 after 回調 ⇒ polSum 不降 ⇒ 紅；③守衛自身快取元素（不重查）⇒ 誤報 ⇒ 證明紀律必要。
