## 0. 這張卡為什麼存在（我上一張卡的判定是在不完整的母體上做的）

T439 的卡面、CHANGELOG 條目與 `docs/tools/art_wall.html` 的說明裡，我逐字寫了三次：

> `isoBox` 是**全檔唯一**的牆面落筆口。

**那句話是錯的。** `index.html:1629` 還有 `boxUnit(g,ng,cx,by,hw,h,cL,cR,cTop,opts)`——
T425I 的「`isoBox` 極緻升級」，**19 個呼叫點**，自己畫左右兩片牆：

```js
// ①左面（受光）5 級色階
const rampL=[shade(cL,2),shade(cL,1),cL,shade(cL,-1),shade(cL,-2)];
// ①右面（背光）5 級色階
const rampR=[shade(cR,-2),shade(cR,-3),shade(cR,-4),shade(cR,-5),shade(cR,-6)];
```

註解自己就寫著**左面受光、右面背光**，而且不是靠傳進來的顏色決定——
是 `rampL` 往亮加、`rampR` 一路往暗減，**由構造決定**。

而 T439 量到 `isoBox` 的主體牆面是 **108 個鍵、108 右受光、0 左受光**。

⇒ **這個檔案裡有兩個牆面畫法，受光方向是相反的**，而我上一張卡的母體只涵蓋其中一個。
T439 的判定（「調研的前提成立」）在它自己的母體內仍然成立，但**「全檔唯一」這句話要撤回**，
而且「全城光照是否自相矛盾」這個更大的問題，**答案很可能是：是，而且矛盾就在這兩個畫法之間。**

**這一條是我自己回頭查出來的**，不是覆核給的——但它同時說明一件事：
T439 那句「唯一」我一次都沒有驗證過，只是讀了 `isoBox` 的內容就下了全稱判斷。
