# T550 面板圖表解析度（背板像素沒跟著裝置像素比走）

**日期**：2026-08-21　**發卡**：Claude（**業主回報**：「圖表分辨率非常模糊，修復這個問題」，附截圖）

## 0. 實測（以 `--force-device-scale-factor=2` 重現業主的 HiDPI 條件）

| 圖 | 背板像素 | CSS 尺寸 | 實際需要 | 放大倍率 |
|---|---|---|---|---|
| `#histCv`（城市頁 T112 迷你圖） | 260×80 | 262×82 | 524×164 | **2.02×** |
| `#trCv_money/net/pop/happy`（趨勢頁 T450） | 252×96 | 407.5×156.5 | 815×313 | **3.23×** |

`ctx.getTransform()` 回 `a=1, d=1`＝**完全沒有 DPR 縮放**；
掃描背板發現最右繪製欄 x=248 / 背板寬 252＝內容確實填滿背板，
所以畫面上看到的就是一張 252 寬的圖被硬拉到 815 裝置像素——業主截圖裡的糊就是這個。

## 1. 根因（趨勢圖是兩層疊加）

```html
<canvas id="trCv_money" width="252" height="96" style="display:block;width:100%">
```

1. **CSS 橫向拉伸**：`width:100%` 讓元素填滿格欄（實測 407.5 CSS px），但背板仍是 252
   ——**即使在 DPR 1 的螢幕上也已經是 1.6× 模糊**。
2. **無 DPR**：HiDPI 再乘一次，合計 3.23×。

`#histCv` 沒有 `width:100%`，所以只中第二條，2.02×。

**對照**：主畫布 `#game` 從第一天就做對了（`resize()`：`cvs.width=Math.round(cvs.clientWidth*DPR)`），
科技樹也有 `techScale343()` 的 DPR 處理。**房規早就存在，這兩張面板圖只是從來沒接上。**

## 2. 為什麼這張卡是安全的

`drawHistChart` 只被 `showStats()` 的綁定呼叫；`trendCell450`／`showTrendPanel450` 只被趨勢分頁與
其範圍鈕呼叫。**兩者都不在 `tick()` 路徑**，零 `R()/ri()` 消耗，不動存檔格式。
⇒ **六哨兵位元恆等**。

## 3. 落地

1. **共用尺規 `fitCanvas550(cv)`**（比照 `resize()` 房規）：
   - 讀 `clientWidth/clientHeight`（**內容框**，不含邊框——`getBoundingClientRect` 會多算 2px 邊框）
   - `cv.width=round(cssW*dpr)`、`cv.height=round(cssH*dpr)`，`dpr=clamp(devicePixelRatio,1,4)`
   - `g.setTransform(dpr,0,0,dpr,0,0)`＝**繪圖碼繼續用 CSS 像素座標，一行都不用改寫**
   - 回 `{g,W,H}`（W/H 為 CSS 像素）
   - **面板隱藏時 `clientWidth` 為 0**，回退到屬性尺寸（否則 `canvas.width=0` 整張圖消失）
2. `trendCell450` 改吃真實 CSS 寬高（不再寫死 252×96）——順帶讓折線**真的畫滿格欄**。
3. `drawHistChart` 同樣走 `fitCanvas550`。
4. `showTrendPanel450` 把 `showInfoPanel()` **移到繪製迴圈之前**：面板還是 `display:none` 時
   量不到寬度（這是第 1 點回退存在的原因，但正確時序讓它走正常路徑）。
5. 視窗縮放後重繪：既有 `resize()` 尾端加一行，趨勢/城市面板開著時重新量尺並重畫
   （**只重畫既有 canvas、不重建 HTML**，避免拖曳縮放時整面板重排）。

**比例自洽**：canvas 是替換元素，CSS 高由內在比例導出（252:96 → 407.5:155.2）。
新背板等比放大 ⇒ 比例不變 ⇒ **版面零位移**，不需要釘死 style 尺寸。

## 4. 驗收計畫

- **G1（靈魂）DPR 行為釘**：造境已知 CSS 寬 → `canvas.width === round(cssW*dpr)`；
  `ctx.getTransform()` 的 a/d 必須等於 dpr。DPR 1 與 2 各驗一次（雙向，防寫死 2）。
- **G2 座標空間**：`trendCell450` 收到的 W 是 **CSS 寬**而非裝置寬——繪製最右點不得超過 CSS 寬
  （防「背板放大了但畫布內容只佔左上角」這個相反的失敗型）。
- **G3 兩張圖都修**：`fitCanvas550(` 呼叫點計數釘涵蓋 histCv 與 trCv 兩條路徑。
- **G4 隱藏時不炸**：`clientWidth=0` 造境 → 背板必須回退到屬性尺寸，不得為 0 或 NaN。
- **G5 零亂數**：新增碼機械掃（鐵律2）。
- **G6 六哨兵位元恆等**。
- **行為證明**：重跑量測探針，六張圖（1 迷你＋4 趨勢，DPR 1／2 各一輪）放大倍率必須全部 = 1.00。
- 紅源：①拔掉 `*dpr` → G1 應紅；②拿掉 `clientWidth=0` 回退 → G4 應紅；
  ③`trendCell450` 收裝置寬而非 CSS 寬（畫布只填左上角）→ G2 應紅。

**刻意不做**：不改圖表的視覺設計（配色／字級／`d232 d261` 標籤位置／零線）——
本卡只修解析度，任何美術改動都是另一個決定。
