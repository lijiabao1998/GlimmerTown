## 0. 缺陷（已上線玩家部署，我親手複驗）

`index.html:12826`：

```js
if(!b||(b.k>3&&b.k!==127))continue;
```

`b.pw`／`b.wa` 的**每日重算**只跑 `k=1/2/3` ＋ `k=127`（社宅）。
全檔 `b.pw=` 的寫入端只有 `:12828`／`:12832`，`b.wa=` 只有 `:12835`，**全部在這個迴圈裡**。

而 `healthStrip430`（`:18263-18264`）**無條件**讀它們：

```js
h.push({ic:'⚡',nm:'電',state:b.pw?'good':'bad',txt:b.pw?'正常':'未供電'});
h.push({ic:'💧',nm:'水',state:b.wa?'good':'bad',txt:b.wa?'正常':'未供水'});
```

⇒ **所有 k≥4 的建築**（服務／公共／農牧／地標／工業加工／購物中心…）：
- ⚡格永遠 `good`（因為放置時硬寫 `pw:true`，全檔 **111 處**），**不隨 T432 電網分區變動**；
- 💧格永遠 `bad`（`b.wa` 從來沒被設過，`undefined` 是 falsy；全檔 `wa:true` 只有 **2 處**）。

T430 卡面 §6.4 自訂的「真瀏覽器供電／斷電兩態實拍」**從未交付**，
而作者唯一的樣本（k=63 溫室，`pw=true`／`wa=false`）恰好就是這類假資料，卻被寫成「每格與真實數據吻合」。

### 0.1 我另外查到的、比顯示層更深的一層（**本卡不修，留痕**）

`b.pw` **不只顯示層在讀**：

| 行 | 讀者 | 影響 |
|---|---|---|
| `:12744` | `if(b&&b.k===57){fpN++;if(b.pw)procCapU+=40+((b.lv||1)-1)*20;}` | **食品加工廠（k=57）的加工容量**按「永遠有電」計 |
| `:12752` | `if(b&&b.k===65){mallN++;if(b.pw)nComG284+=3;}` | **購物中心（k=65）的商品供給**按「永遠有電」計 |

這兩處是 **k≥4**，讀到的是放置時硬寫的 `pw:true`，**永遠不會因為斷電而變 false**。
⇒ 這不只是顯示問題，**模擬層也在用一個永遠為真的值**。

**本卡不碰它**：修它＝改 `tick()` 的行為＝**必破兩釘**，需要業主批准重釘。
本卡只讓**顯示層停止說謊**，並把這一層寫進帳本等業主決定。
