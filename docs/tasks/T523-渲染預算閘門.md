# T523 渲染預算閘門（每幀落筆數：把今天的量法變成永久的絆線）

**日期**：2026-08-18　**發卡**：Claude（業主授權：自己玩→出卡→施工→合併）
**性質**：量測基礎設施卡——**不改任何渲染輸出**，只把量法寫死進閘門。

## 0. 今天量到什麼（以及為什麼不寫效能卡）

長局玩測發現成熟城 `forceDraw` 在 headless 要 190-250ms，看起來很嚇人。但追下去：

1. **headless 的時間量測不可信**：基準樣本 220/262/242/288/242ms；交錯 A/B（各 5 輪中位數）
   顯示關掉任一特效的差值全在 ±8ms 內，甚至有「關掉反而變慢」——那是雜訊，不是熱點。
   第一版逐一關閥的量法（先量基準再逐一量）更是被冷啟動騙了：**任何一個閥都「省 56ms」，
   三個一起關卻只省 58ms**。
2. **改用確定性儀器**（攔截 canvas 呼叫計數，與 GPU/時序無關）才得到可信數字：

| 城市 | 每幀落筆 | 主要來源 |
|---|---|---|
| 空城 | **1,684** | beginPath 545／fill 505／drawImage 301 |
| 100 天（pop 773） | 5,330 | fillRect 1,092／drawImage 623 |
| 300 天（pop 6,553） | **15,936** | fillRect 3,419／save+restore 5,436／drawImage 2,453 |
| 600 天（pop 6,890） | 14,233 | 同上 |

微雕美術層佔比（確定性差分）：`LivedIn421` 14.4%、`DistrictTexture424` 11.6%、
`Rooftop425` 6.4%、`FacadeMemory426` 5.3%、`MicroLife429` 3.1% ＝**合計約 41%**。
縮放 LOD 有效：zoom 0.5→11,222／1→14,233／2→7,959／3→6,096。

**結論：14K 呼叫/幀對有 GPU 的瀏覽器不算誇張，我沒有證據說玩家端現在有效能問題**——
所以本卡**不做**任何渲染優化（那會是有像素回歸風險的大手術，不能憑 headless 的髒數字動手）。

## 1. 本卡做的事：把量法變成閘門

新增 `GV.drawCensus523()`：攔截 canvas 2D 呼叫、跑一幀 `forceDraw`、還原攔截，回傳
逐項與總計（**攔截即還原、零殘留；draw 本身已由 T422 G4 證明零亂數**）。

閘門用**上限**而非精確值（headless 幀內容會隨動畫時間微幅浮動，精確釘必 flaky——T444 教訓）：

- 空城一幀 ≤ **3,000**
- 300 天城一幀 ≤ **25,000**
- 兩者必須單調（城市長大不會變少）＋非零

意義：未來任何人加一層美術，如果讓每幀落筆翻倍，**閘門會在合併前咬住**，而不是等玩家喊卡。

## 2. 驗收計畫

- G1 `drawCensus523` 攔截後必須還原原生方法（**紅源：不還原 ⇒ 後續量測污染**）。
- G2 行為：空城與 300 天城的落筆數落在預算內、且 300 天 > 空城。
- G3 零副作用：census 前後 `GV.stats()` 與六哨兵不變（量測不得改變世界）。
- 紅源三案：預算調到現值以下（閘門必紅）／攔截不還原（G1 紅）／census 消耗亂數（零亂數釘紅）。

## 3. 施工紀錄（Claude 全鏈；起點 master `268b5c7` → v11.152，PASS 5,775）

### 3.1 落地

`GV.drawCensus523()`：攔截 20 個 canvas 2D 方法、跑一幀 `draw(.016)`、**立刻還原**，
回傳逐項計數、總計與 `restored` 旗標。

### 3.2 兩件自捕（都是本季一路在修的同一族毛病，這次犯在自己手上）

1. **還原判準寫錯**：第一版把「還原乾淨」定義成「沒有自有屬性」——瀏覽器的 ctx 方法在原型上，
   但**套件的 ctx 是 stub、方法就是自有屬性**，於是套件裡永遠判定沒還原。
   改成「還原後取到的函式必須與攔截前**同一個**」（`cx[nm]===seen[nm]`），兩種環境都對。
2. **預算校準錯對象**：第一版照真瀏覽器數字設 3,000／25,000，但**閘門跑在套件裡**
   （stub 渲染路徑，實測 585／2,587）⇒ 有 10 倍餘裕＝**閘門咬不到任何東西**。
   改為照套件實測校準（1,200／6,000，約 2 倍成長餘裕），並把兩套數字的差異寫進守衛註解。
3. **G3b 第一版是空跑**：寫成 `window.GV.rngPeek ? … : null`——鉤子不存在就整條略過。
   改成不可跳過的機械掃（census 函式體零亂數）。

### 3.3 驗證

- 套件：空城 585／300 天城 2,587（均在預算內、單調遞增）、`restored===true`、
  量測前後 `stats()` 逐字相同、六哨兵位元恆等。
- 真瀏覽器：空城 **832**／300 天城（pop 2,376）**4,755**；**連拍兩次計數完全一致**（確定性）；
  量測前後畫布 PNG **916,498 bytes 對 916,498 bytes（差 0）**＝攔截沒有破壞渲染。
