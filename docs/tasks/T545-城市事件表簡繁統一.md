## 0. 實測（災害全家桶玩測的順帶發現）

災害玩測讀 `CITY_EVENTS` 表（T299 城市事件，每 ~37 天觸發、toast＋統計面板顯示）時發現：

| 段 | 條數 | 文字 |
|---|---|---|
| T299 原批（harvest…festival） | 6 | 繁體 ✓ |
| 中段擴充批（springfest…fakenews） | **40** | **簡體**（新春庙会/流感大爆发/经济衰退潮/谣言恐慌…） |

全遊戲 UI 是繁體（委託/礦場/玩法指南…），事件 toast 卻交替蹦出簡體——同一個功能裡
「🎆 煙火大會」和「🦠 流感大爆发」並存。全檔簡體字掃描確認：**玩家可見的簡體只有這一表**
（另有繪圖程式註解區 4375–4650 行的簡體，玩家看不到，刻意不動）。

## 1. 為什麼這張卡是安全的

只改 `name`/`desc` 字串（字級簡→繁，不改措辭、不動 id/days/tax/food/happy 任何數值）。
事件的數值欄位**在 tick 路徑**（稅收/食物/幸福乘數、day%37 決定性觸發）⇒
**六哨兵位元恆等本身就是「數值零改動」的守衛**；字串只進 toast/面板。

## 2. 落地

40 條 name+desc 逐條字級轉繁（例：庙会→廟會、爆发→爆發、艺术→藝術、龙舟→龍舟、
盗窃→盜竊、恶性通胀→惡性通脹、虫害泛滥→蟲害氾濫、堵车→堵車…）。
措辭不動（「排长队→排長隊」照轉不改寫）；簡繁同形字（堵/慌/淹…）自然保留。

## 3. 驗收計畫

- **G1（靈魂）簡體字黑名單掃描**：`CITY_EVENTS` 表切片不得含任何黑名單字
  （~70 個無歧義簡體專用字：发庆丰满张灯电厂龙会车来国…；刻意排除簡繁同形/歧義字
  如 堵、面、云——「面」在繁體是臉/表面，只有麵食義才轉「麵」）。
- **G2 條數釘**：表恰 58 條（6＋40＋12）——防轉換時整條丟失。
- **G3 id 抽查**：springfest/fakenews/moonfest/quake 等 id 原樣在場——防 id 被誤轉。
- **G4 六哨兵位元恆等**＝數值欄位零改動的行為證明（cityEvent 乘數在 tick 路徑）。
- 紅源：①任一條 name 回簡體 → G1 應紅；②刪一條 → G2 應紅。
