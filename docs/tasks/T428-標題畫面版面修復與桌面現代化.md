### 4.1 為什麼不能用 `scrollHeight` 做 before/after 比較（R05 發現）

改動前 `#start` 是 `justify-content:center` ＋ `overflow-y:auto`：內容溢出時被截在**滾動起點之上**，
而 `scrollHeight` **算不到那一段**。逐子節點實測（844×390）：

| | justify | 最高 top | 最低 bottom | 真內容高 | scrollHeight 報的溢出 |
|---|---|---|---|---|---|
| 改動前 | `center` | **−199** | 589 | **788** | 215（低報 199） |
| 改動後 | `safe center` | 8 | 648 | **640** | 266 |

所以「215 → 266」看起來是退步，真相是改動前低報。
**可比的量是「真內容高 ＝ 最低 bottom − 最高 top」**（與置中方式無關）：
844×390 **788→640**、375×667 **942→735**、390×844 **941→826**。
另外 `aboveOrigin`（被截在上緣之上、滾不回來的量）直接就是本卡要修的東西：改動前 199／145／56 → 改動後 **0**。

### 4.2 判準（`docs/tools/ui_probe.html`，需同時給 `a=` 與 `b=` 才算完整）

**全尺寸硬條件**（缺元素／缺 `b=` 一律**不算通過**，不得靠「元素不存在所以沒被切」過關）：

| 不變量 | 目標 |
|---|---|
| 水平溢出（`scrollWidth−clientWidth`，邊界用 `clientWidth` 不用視窗寬） | **0**，且無元素右緣越界 |
| `#logo` | 存在；可見時 `y ≥ 0` 且寬 ≥ 112px；被既有 `max-height:520px` 規則隱藏可接受 |
| 難度四顆 | 顆數 ≥ 4 且相異 y 數 **= 1** |
| 主按鈕 `.startPrimary` | 存在且**完整落在首屏** |
| 絕對下限（防「整頁 scale(.4) 全綠」） | 主鈕 h ≥ 40、任何可視鈕 h ≥ 30、`.help` 字級 ≥ 11px |
| 真內容高不退步 | `after ≤ before` |
| 上緣不可達 | `after aboveOrigin = 0` |
| 展開態不退步（**真的點開🎯戰役再量**） | `after 真內容高 ≤ before` |
| 觸控不退步 | `after 最小鈕高 ≥ before` |
| 行距不退步 | `.help` 的 computed line-height `after ≥ before`；`normal` 直接判紅（＝宣告被丟棄） |
