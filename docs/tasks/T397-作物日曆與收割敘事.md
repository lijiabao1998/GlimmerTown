# T397 — 作物日曆與收割敘事(農業美術三期 R3)

業主原文:「生長階段拉細:翻耕壟線→出苗→拔節→成熟→**割茬+草捆**→冬雪蓋捆。關鍵是
『收割留痕』——現在成熟後大概是直接輪回,加一個割茬期+散落草捆,秋天的田就有故事了。
還能跟既有系統白嫖聯動:豐收節事件時全圖進收割態…美術直接掛在模擬真值上,零新機制。」

## 現況(偵查 wf_65f5580a 已證)

`SPR.farmGrow[sea 0..2][stage 0..1][key]` 兩階(稀疏小苗 / 半高株);draw 端
`gst=Math.floor(((day+Math.floor(streetHash(o.x,o.y,777)*12))%12)/4)` 三段各 4 天,
gst<2 取 farmGrow、gst===2 取 base/farmSea(成熟)。**成熟後直接跳回小苗,零收割痕跡。**
冬季(sea===3)走 farmSea[3] 雪田,不參與生長階段。

## 設計

1. **新增第四階「割茬」**:`SPR.farmGrow` 擴為 stage 0..2,`stages()` 迴圈改 `[0,1,2]`,
   `stagePlant` 新增 `st===2` 分支——壟上留 1px 短茬(暗黃)+ 依 `streetHash` 決定性
   散落草捆(3×2px 塊,每格數個)。週期 12→16 天,四段各 4 天:
   `gst=Math.floor(((day+Math.floor(streetHash(o.x,o.y,777)*16))%16)/4)`
   選圖:gst 0/1 → farmGrow[sea][gst];gst 2 → base/farmSea(成熟);**gst 3 → farmGrow[sea][2]**。
2. **豐收節聯動(掛模擬真值,零新機制)**:`cityEvent` 為 `harvest`(或 `autumnbounty`)
   期間,全圖強制 gst=3(收割態)。cityEvent 是決定性狀態(streetHash 觸發,不消耗亂數),
   故不破壞任何確定性。這讓「城市正在慶祝豐收」與「田裡真的在收割」對得上。
3. **記憶體核算**:farmGrow 由 3季×2階×16 = 96 張增至 3季×3階×16 = 144 張,
   +48 張 136×150 ≈ +4MB。可接受(對比相位變體法的 +26MB)。
4. 冬雪蓋捆(業主原文最後一段)本卡**不做**:那需要改 T229 farmSea[3] 的 remap 色表,
   與雪田管線耦合,單獨評估。本卡只做春夏秋三季的割茬。
