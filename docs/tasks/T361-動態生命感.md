# T361 — 動態生命感：船・飛機・季節粒子

## 出卡背景

玩家在 T356 欽定素材擴充順序 **①③②⑤**（④音頻暫緩）：
①素材圖鑑（T356 ✅ 已完）→ **③動態生命感＝本卡** → ②建築生成器資料化 → ⑤地形肌理。

現狀盤點（對著 v9.6 代碼查證）：

- 城市有港口 k18、遊艇碼頭 k90、釣魚碼頭 k97、機場 k19、國際機場 k114，
  但**水面永遠空無一船、天空永遠沒有飛機**——`SPR.boat/ship/plane` 皆不存在。
- 既有動畫框架可直接借用：T152 `animOn` 統一開關＋多幀 sprite 管線
  （`SPR.flag/parkFtn/radar/windRotor/warnBlink/bird` 六組）、T154 天氣視覺
  `wxUp` 開關、T136 `season()` 春夏秋冬四值、T155 載具變體的
  `streetHash` 決定性選型、T344c 車輛每節獨立 `dep` 深度排序。
- 本卡為 **Grok 首卡**：三個子項各自獨立驗收、獨立可併，任一子項
  BLOCKED 不影響其餘子項交付。

## 目的

讓城市「活起來」：港口有船进出、機場有飛機起降、季節有氛圍粒子。
全部為**純視覺層**——不動經濟、不動存檔、不動模擬邏輯。

## 子項

### T361a 船舶

- 港口 k18／遊艇碼頭 k90／釣魚碼頭 k97 存在時，在其鄰近水域生成移動船隻：
  貨輪（港口）、遊艇（遊艇碼頭）、釣魚小船（釣魚碼頭），各至少 1 個 sprite。
- 船隻只在水格（`t` 水域）上移動，比照既有車輛/火車的 objs 框架推進位置；
  生成與路徑必須決定性（`streetHash`／格座標函數），不得消耗 `R()`。
- 每艘船獨立 `dep` 參與遮擋排序（T344c 教訓：整列共用 dep 會穿前景物件）。

### T361b 飛機

- 機場 k19／國際機場 k114 存在時，有飛機可見：起降循環或定期橫越天空
  （可參考 `SPR.bird` 的天空層做法），至少 1 個多幀或帶方向變化的 sprite。
- 出現時機決定性（例如以日數/格座標 hash 決定班次），不得 `Math.random()`。

### T361c 季節粒子

- 依 `season()` 切換：春＝花瓣（公園/樹附近飄落）、夏＝夜晚螢火蟲
  （水邊/公園，僅夜間）、秋＝落葉。冬季已有降雪（T154），本卡不做。
- 粒子在 draw-time 以 `visT`＋格座標決定性函數推導位置（比照 T152/T154 做法），
  **不得在 buildSprites 中段新增任何消耗亂數的生成**（鐵律18）。

## 不變量

1. **零亂數流位移**：buildSprites 新增生成一律放**絕對尾端**（T275 還原點前），
   且全部決定性；新增靜態守衛斷言本卡代碼段禁 `R()`/`ri()`/`rand()`/`Math.random()`。
2. **新 SPR 鍵先查重**（鐵律17）：動手前 `grep` 全檔確認 `boat/ship/plane/petal`
   等擬用鍵名無撞名。
3. **A/B 開關**：提供 `window.__noLife` 總開關，關閉後日間畫面與 v9.6 逐像素一致
   （比照 `__noTrainSpr`/`__noNature`/`__noSpot` 慣例）。
4. 日間 `nightDepth===0` 時螢火蟲零繪製；`animOn` 關閉時船/飛機/粒子行為
   與既有動畫開關語義一致。
5. 存檔逐位元相容：同一存檔在本卡前後載入，模擬結果（人口/金流/稅收）
   不得有任何差異。
6. 繪製尺寸一律乘 `z`；錨點遵守 ARCH §4；`dia()` 半寬偶數（鐵律6/7）。
