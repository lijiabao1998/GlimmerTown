## 三、出卡缺陷更正（覆核者自己的錯，本節取代卡面對應段落）

### 1. 🔴「地墊菱形格數必須等於 4161」是**循環自我檢核**，真值是 4224

卡面要施工者「先斷言菱形格數 == 4161」。4161 是連續范數 `|dx|+2|dy| ≤ 64` 的整數解數；
`plate`→`dia`（`index.html:1017-1025, 1178`）實際光柵是：

```js
const hh=hw>>1;
for(let i=0;i<hh;i++){const w=(i+1)*2;
  g.fillRect(cx-w,ty+i,w*2,1); g.fillRect(cx-w,ty+hw-1-i,w*2,1);}
```

⇒ 逐列 `x ∈ [cx-w, cx+w-1]`（**右邊少 1 px**），總量 `8·Σ(i+1) =` **4224 px**，
`y 84..147`（**沒有 y=148**），最寬列是 **y115 與 y116**，頂/底列各 4 px，
光柵對稱中心 **(67.5, 115.5)** 而非 (68,116)。與范數模型的對稱差 **129 px**。

出卡時的「實得 4161 ✓」只證明了「范數區內的格子都不透明」，**沒有證明地墊等於范數區** ——
用同一個模型去驗自己。**正確的地墊真值請用上面的 `dia()` 迴圈重建，不要用范數近似。**

### 2. 「剛好貼齊」四個字要刪掉；`ay=140` 解析上更乾淨，但**渲染無差異**

依 `dia()`／`field()` 逐列重算：

| 選項 | 田面 | 跑出地墊光柵 |
|---|---|---|
| `ay=144 hw40`（卡面預設、已交付） | 1633 px（1.78×） | **19 px**（y128 起每列右緣溢 1） |
| `ay=140 hw40` | 1633 px（1.78×） | **0** |
| `ay=148 hw30`（v11.1） | 919 px | 0 |

原因：`dia` 逐列右邊少 1 px 而 `field` 對稱，所以任何整數 cx 都做不到「田完全落在地墊內」。
**「田必須完全在地墊內」不可寫成二值不變量**，否則施工者會追一個不存在的 bug。

**但實測結果推翻了「ay=144 是壞選項」**：在最終精靈裡量田土色落在光柵外的像素，
v0/v4/v9/v15 皆 **0 px**；下半溢出 324 px 且**與 v11.1 完全相同**（田土色 0）——
那 19 px 被 `clipBase` 與畫在上層的農莊套件完全吸收。⇒ **不因此退修。**

### 3. 🔴 禁止觸碰 #6 與卡面自己的指令硬碰硬（T374 同型錯誤）

卡面命令「移除變體塊裡與作物重複的補丁」，同時禁止「除 K4/K1/L1 外修改既有斷言」。
但 v12-v15 落在 `test_fixde.js:3672-3875` 的離線光柵重播範圍內，且：

- **四個像素探針全部釘在要被移除的作物美術上**（`3794-3799`）
- **`hitSources274` 要求 13 個來源色全部被最終 base 命中**（`3839/3848/3862-3867`），
  其中 **12 色是作物美術**

⇒ 移掉補丁必紅。**本節明示授權**：施工者可改 `test_fixde.js` 的 T274 探針座標（3794-3799）
與來源色表（3816-3867），**或**把 v12-v15 排除在「移除補丁」之外 —— 二者擇一並在卡面記明。
已交付版採第二條路（保留探針像素），合法。

### 5. L1 必須分類「建築 vs 作物」，並自證量到了東西

L1 的 regex 命中 93 個字面矩形，其中 **55 個是建築**（小屋／穀倉／溫室／桶／箱／蜂箱）、
**38 個是該變體自己的粗田／作物／田埂**（本來就該被精細田蓋掉）。建築矩形所在行號：

```
4468 4469 4476 4477 4481 4489 4490 4491 4492 4501 4502 4512 4521 4522
4532 4542 4552 4553 4562 4572 4582 7334 7335 7336 7337 7354 7355 7356
7357 7373 7374 7375 7376 7391 7392
```

另外 L1 必須有一條 self-check 證明它真的量到東西（例如「建築矩形總數 ≥ N」）——
否則「把美術全刪」也會讓覆蓋量歸零而 PASS，量不到任何東西也綠。
已交付版把 `blocks++` 提到 rects 檢查之前並內建 mutant 證明，避免了自我失效，
但 **v0-v11 目前確實是「沒有東西可量」**，補回招牌物件後這條分類就是必需品。

### 6. 阻塞規則「指紋出現非 k22 鍵就停手」訂得太硬

實際發生了：`bld/2_2_11` 日層 hash 從 `9448db9a` → `dbbe01fb`。查證結論是**雜訊，不是事故**：

- 二分定位到 H3（v12-v15 搬美術）；H4（田參數）與 H2（v0-v11）都不造成
- 差異僅**日層 3~4 個像素**，且那些像素**半透明**（alpha 121/180/194，玻璃窗）；
  不透明數 2648、bbox、逐列剖面、前 12 色全部相同
- 機制：canvas 內部存預乘 alpha，`getImageData`/`putImageData` 往返對低 alpha 像素有 ±1 捨入
- 排除流位移：若是位移，`stampRoof`（`index.html:7683`，在改動之後）會讓 k1/k2/k3 共 108 鍵
  一起變，實際只變 1 鍵；且新碼零亂數 token、`cv(`/`plate` 數不變
- 對照組：在 master 上把 v15 一條紫帶改窄 1px → `22_1_15` 指紋變、`2_2_11` **不變**
  ⇒ 也不是「任何農場改動都會擾動」

**規則改為**：非目標鍵變動時，先判斷差異是否僅限半透明像素的 ±1 捨入
（不透明數／bbox／逐列剖面／主要色全同，差異像素 alpha<255）；
若是則記錄放行，否則停手。**這條已寫進 `docs/COLLAB.md`，適用於之後每一次覆核。**
