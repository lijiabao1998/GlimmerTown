## 為什麼現在做

v10.3 已有三條真實鏈，但統計面板目前只零散顯示「工業品」：

1. `supplies` → `goods` → 商業供貨倍率（T140／T284）。
2. 原油 → `fuel` → 工業／貨運相關稅率倍率（T364b）。
3. 礦石 → `steel` → 升級費 `.85`／造船耗鋼／港口貨運收益（T364b）。

玩家看不出煉油廠、鋼鐵廠、造船廠是否真的運轉，也無法判斷庫存或收益為何改變。本卡只補「可觀測性」，讓已有的深度成為可做決策的內容。

## 玩家面板契約

在既有統計面板新增一個標準 `statTab()` 分區（名稱可微調，但內容不得縮減或另造規則）：

- **資源與工業品**：通用原料 `supplies`、工業品 `goods/goodsCap283()`、本期售出 `gFlow284.use`、商業供貨倍率 `gFlow284.mul`。
- **原油與燃料**：燃料庫存 `fuel`、本期精煉 `fuelMade`、現行工業／貨運倍率 `fuelTaxMul`／`freightTaxMul`。
- **礦石、鋼材與造船**：鋼材庫存 `steel`、本期冶煉 `steelMade`、本期耗鋼 `steelUsed`、工業倍率 `steelTaxMul`、真實升級費折減 `STEEL_UP_DISCOUNT`、造船啟動時的貿易倍率與港口收益 `shipTradeTaxMul`／`shipPortGold`。

只要城市沒有任何相關來源／加工建築，且上述存量與流量全為零，整個 T369 分區必須隱藏，不能讓新城市先看到一張空產業報表。判定應複用 `showStats()` 已計出的建築計數與既有 state，**不得另掃地圖或新建快取**。

`gFlow284.gain` 是既有的供貨快照（含既有庫存語意），不是新的「本期生產量」來源；若顯示它，標籤必須忠實表達既有語意，不得誤稱為今日產量。所有數字直接讀既有變數，不得在 UI 重新推演稅率或產量公式。

## 驗收清單

1. **空城靜默**：新世界／無相關產業時，統計 HTML 不得出現 T369 分區；無 `NaN`、`Infinity`、`undefined`。
2. **真跑資料一致**：沿用或建立 T364b 完整鏈場景，推進後開統計面板；每一個顯示數字都與同一時刻的既有 state／`GV.goods()`／`GV.chain346()` 相等，不可用硬編碼預期值替代資料對照。
3. **零副作用**：開啟／關閉統計面板前後，`money`、`hist`、存檔字串與核心 `GV.stats()` 不變；面板只讀。
4. **語意守衛**：靜態斷言新增區塊沒有 `R()`／`ri()`／`rand()`／`Math.random()`，且未伸入 `tick()`、存讀檔、繪製或旋轉錨點。
5. **瀏覽器實拍**：在施工者自己的車位端口（非 8123）拍一張完整三鏈城市統計面板，確認手機寬度／窄視窗不截字、倍率與單位可讀、Console 0 error。
6. `python tools/verify.py` 必須全綠，PASS 只增不減；版本只在完整交付時升至 10.4。
7. 施工者交付後由**非作者**覆核並從 canonical master 執行 `python tools/merge_bay.py <bay> --deploy`；未經覆核不得自行合併或部署。
