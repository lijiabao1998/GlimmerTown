# T515　開始畫面與面板導覽結構化

## 0. 出卡理由

T428 解決了開始畫面在矮視窗「置中後上端不可達」與桌面只用窄欄的問題，
但把編輯器、難度、挑戰、偏好設定與戰役仍當成 `#startMore` 的平級子項；
桌面三欄 grid 因此按插入順序把它們拉成 **280 → 240 → 310 → 1040 → 520 → 240px**
的無規律節奏。挑戰甚至比主 CTA 更寬，玩家看不出哪些是開局、哪些是附加玩法。

全局掃描也找到同型問題：`#info` 在窄直式視窗仍只取 `max-width:70vw`，
統計五分頁、指南八分頁與歷史／趨勢操作列把多個互動元件硬塞進單列。
本卡只收這兩個「缺少語義群組與窄寬排版規則」的 UI 根因；不把 HUD、工具列、
T514 政策指揮台或資料表重構混進來。

## 2. 合約：要做什麼

### A. 開始畫面：外層仍三欄，內層才有結構

`#startMore` 在桌面仍保留 T428 要求的三欄 grid；它只負責外框，不能再直接排列異質按鈕。
新增無 id 的語義 `section.startSection515`：

1. `startConfig515`：既有「難度」標籤／四鈕 + 新可見「快速設定」標籤／既有五張設定卡。
2. `startExtras515`：既有 `#bEditorMode` 與既有 `#bCampaign` 收進 `.startAltRow515`；
   既有 `#scMenu` 留在同 section 內、仍由 campaign 控制。
3. `startChallenge515`：既有「挑戰」標籤 + 新 `.startChallenges515`，其中**恰好**放既有 `#bCh1–3`。

桌面：設定區跨兩欄、其他玩法跨一欄、挑戰跨全欄；挑戰內部三等欄，單卡不得再被拉成滿版條。
手機：sections 單欄、挑戰單欄；既有 `#scMenu{max-height:220px;overflow-y:auto}` 不變。
每個既有按鈕的 id、文案、順序語義、onclick/event handler、localStorage 鍵及開局行為必須逐字保留。

### B. 共用資訊面板：具名控制群組，不碰通用 `.row`

1. 直式窄寬的 `#info` 亦採既有安全居中寬度模型（`width:min(560px,92vw)`／`max-width:92vw`），
   不動 landscape T372 的無 transform 置中契約。
2. 新增具名 `.panelTabs515`：統計五分頁保留 `techTabs343`，成為 `techTabs343 panelTabs515`；
   指南八分頁也用此類。窄寬採可預期 grid，不橫向推出面板。
3. 新增具名 `.panelAction515`／`.panelMeta515`：趨勢的 30/90/365、城市歷史的 30/90/365
   分別成為可換行的操作群與說明群。既有 `trR*`、`histR*` id 與事件不可變。
4. `showInfoPanel()` 的唯一 display 寫入、`statsTabs343()` 的既有 id/class、指南陣列順序、
   `guideTab` 分支與所有模擬資料來源不動。

  五設定卡同寬；config/extras/challenge 的群組與垂直順序可讀；戰役清單仍內捲可達。
