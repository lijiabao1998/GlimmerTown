## 重構規格
1. 新增資料表（第 2 節 buildSprites 之前）：
```js
const PARTS={  // 部件函數註冊表：每個部件 (g,ng,ctx8) => void，ctx8={ax,by,hw,h,rty,wl,rf,v,rand}
  pyramidRoof, flatParapet, waterTank, antenna, aviationLamp, chimneySmall, chimneyBrick,
  door, glassFront, awning, signBoard, roofBillboard, setbackTop, rollupDoor, sawtoothMonitor,
  storageTank, hazardStripe, corrugate, panelLines, balconyRows, yardDeco, cratesDeco, windowsStd
};
const DRAFTS=[ // 每行一棟建築外觀
  {k:1,lv:1,hw:20,h:14,parts:['pyramidRoof','chimneySmall','door','windowsStd','yardDeco'],win:{gx:6,gy:8,litP:.55}},
  ... // 覆蓋現有 k1-3×lv1-3、k4 公園（獨立保留）、k5-9
];
```
2. 施工方式：**逐塊搬移**——把現有 if(k===1&&lv===1){...} 等分支的代碼原樣搬進對應部件函數（座標邏輯不變），主迴圈改為讀 DRAFTS：查表 → plate → isoBox → 依 parts 順序呼叫部件 → outlineSprite → 註冊 SPR.bld[key]。**像素輸出必須與重構前完全一致**（見驗收 1）。
3. 變體 v 的處理：DRAFTS 行內 wl/rf 取 PAL（保留 PAL 表），部件函數內原有的 v 條件邏輯保留。
4. k=4 公園、樹、裝飾等非建築 sprite 不在本卡範圍。
5. 完成後在 DRAFTS 表尾**示範擴充**一行新外觀：k=2 lv=2 的第 4 變體「花園商場」（既有部件組合＋新 trim 色），並把商業 lv2 的 v 上限改 4（生成處 `b.k===2&&b.lv===2?ri(4):...` 或統一擴——自行選最小方案）。這一行是「資料驅動生效」的活證明。
6. ARCH.md 第 5 節由你更新（本卡例外允許動 docs/ARCH.md）：部件清單＋「加一種建築外觀」的三步教學。

## 硬性不變量（最重要的一卡，逐條核）
- SPR.bld 的鍵、每個 sprite 的 {img,night,ax,ay,w,h,smoke} 介面零變更；draw()/tick() 等呼叫方零改動。
- **像素回歸**：重構前先在瀏覽器把全部 SPR.bld sprite 逐鍵 toDataURL 存基準（寫進 localStorage 或臨時檔），重構後逐鍵比對——除示範新增行外 **100% 位元一致**（smoke 偏移陣列也逐值比對）。不一致就修到一致，修不到就回滾 BLOCKED。
- 單檔零依賴；載入時間增幅 <20%。
