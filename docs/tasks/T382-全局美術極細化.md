## 安全面總則（X1 以注入實證過的完整版 —— 逐條有實驗依據）

> 「既有塊內加純 fillRect 細節＝安全」**字面成立但有四個洞**，完整規則：

1. **只在「最後註冊」的塊內加細節。** hero 覆寫（T151/T148，後寫贏）讓 k24/k25/k32/k36/k42/k51 與多數服務建築 v0 的**基座塊是死圖** —— 改了畫面零變化、套件照綠（X1 實證）。這些鍵的細化走**尾端 T382 加蓋 pass**（插在 T368 塊之後、`R=__savedR;` 之前）或 hero 塊內；`HERO_PIX` 表本體禁動。
2. **`plate`/`speck`/`windows` 呼叫一次都不准加、不准刪。** X1 最大洞：多呼叫一次 `plate()`（吃 78 抽 spriteTexRand）⇒ **套件全綠、兩釘不動、但其後所有紋理消耗點斑點全部重排＝瀏覽器大面積漂移,Node 全盲**。同理多一次 `windows()`（吃共用 rand）。⇒ **瀏覽器 atlas T0 指紋 diff 是與兩釘同級的紅線**，不是輔助檢查。
3. **windows() 的幾何常數（hw/h/w/ht/gx/gy）全凍結** —— 每扇窗吃 1 次共用 rand，窗數=純幾何函數，動常數＝改消耗次數＝其後所有亮窗全變。k6 的 `rand()<.65` 行與 k7 的 windows 呼叫行被 T378 K3 **逐字釘**。
4. **隨機紋理的合法路徑＝塊內獨立 LCG**（固定字面種子 `mulberry32(0x...)`，X1 實證兩釘不動、T272 九點守衛不咬；先例 k17 `wr`/k7 `wrand`/k9 `rd`）。但書：命名不得為 `rand`；不得**替換**既有共用流消耗點（只准新增獨立的）。
5. **fillStyle 鏈**（X1 洞 6a）：插入點的下一句若是**裸 fillRect**（依賴上一行 fillStyle），插入後必須補回原 fillStyle。動工前先掃該塊有無裸 fillRect。
6. **新色不得撞季節表鍵**，除非「入冬蓋雪」正是意圖且記卡面。FKEYS 畫布（22_1_*／53_1_0）上用新色必須人工比對 SUM/AUT/WIN(+353/274) 全部鍵的聯集 —— Node 端 remap 是 no-op，撞色**完全靜默**（X1 實證），只有瀏覽器四季目視抓得到。
7. **不越 footprint 下緣**：多格鍵越界被 clipBase 建圖時清 alpha（細節無聲蒸發＝死工）；1×1 鍵直接溢鄰格。覆核以 `GV.sprFootAudit()`==0（瀏覽器）把關。上緣垂直結構合法。
8. **位元凍結島**：T229 季節段（live 與備份逐 byte 比對，**加一行註釋都紅**，X1 實證）、T273/T274 段界、所有字面釘行（K3/K4/K5/F22/doFarm-53/`//sig` 行）、各測試切片錨點字串；尾端新 pass **連註解都不得含 `R(`/`ri(`/`rand(`/`Math.random` 字樣**（切片以字串定界）。
9. **禁 `sc` 縮放路線**：`test_fixde.js:1176` 硬斷言既有 120 座不得出現 sc —— 「2× raw 畫布」捷徑只屬 k121-123/T364c-d 既有件，本卡細化一律原解析度。
10. **每批施工前後 `grep -c` 逐 token 快照**：`R(`/`ri(`/`rand(`/`spriteTexRand`/`Math.random`/`plate(`/`windows(`/`speck(` 計數必須相等 —— 這是每批的自查零成本紅線。
