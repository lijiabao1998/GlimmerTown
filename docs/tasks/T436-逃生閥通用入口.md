## 0. 缺陷（自驗，不是轉抄）

全檔 `__no*` 開關共 **107 個**，其中 **73 個完全沒有寫入端**——
只有讀取端與 `test_fixde.js` 裡「這個字串必須存在」的斷言。

（夜班盤點報告說 17 個，我自己掃出來是 73 個。**數字以本卡的實測為準**，
掃法：`(?:window\.)?__noX\s*=(?!=)` 算寫入、其餘算讀取。）

| 有寫入端的正確範例 | 怎麼做的 |
|---|---|
| `__noBadge` | `index.html:1251-1253` 讀 `localStorage SAVEKEY+'.badge'` |
| `__noNightCity` | `:1256-1258` 讀 `SAVEKEY+'.nightcity'` |
| `__noTitle428` | T428 補的 URL `?noT428=1` ／ localStorage |
| `__noSelfOutline434` | T434d 補的 URL `?noSelfOutline=1` ／ localStorage |

其餘 **73 個**的卡面都寫著「一刀關閉」「緊急回退」，但**在正式產物裡撥不動**：
玩家與覆核者都沒有任何辦法讓它們為真。這正是 T428 G12 專門為此加守衛的那個病，
而 T427／T429／T430／T431 四波完全沒有比照。

## 1. 做什麼（一個入口，不是 73 個）

逐個補 73 個寫入端既笨重又容易漏。改成**一個通用入口**：

```
?no=Life,Cloud,Rot        →  window.__noLife = window.__noCloud = window.__noRot = true
localStorage SAVEKEY+'.no' = "Life,Cloud"   （同效，持久）
```

- 放在既有偏好區（`index.html:1251` 一帶）**之後**、`buildSprites`（1848）之前
  ⇒ 連「烘進 sprite 像素」那一類（`__noBadge` 註解說明的那種）也來得及生效。
- **名稱白名單化**：只接受 `[A-Za-z0-9_]+`，組成 `'__no'+name`，不做任何 eval。
- **不改任何既有開關的預設值**：沒給參數時，行為與改動前逐位元相同。
- 零亂數消耗 ⇒ 兩釘結構上不受影響。

**不做**：不動任何一個開關的讀取端、不改任何預設、不碰 `tick()`。
