# T527 自動存檔的真相（RULES 第 18 條建立在一個從未成立的前提上）

**日期**：2026-08-19　**發卡**：Claude（業主授權：自己玩→出卡→施工→合併）

## 0. 事實

T526 收尾時 `arch_map --fix` 印出這個錨點：

```
index.html:22126  setInterval(()=>{if(tiles)save();},25000);
                  // 世界尚未建立（啟動畫面）時跳過自動存檔
```

`git log -S "if(tiles)save()"` 追出它自 **2026-07-18 `6e4d31a`**（FIX-G/H/I 側線任務）就存在。
T447 是 **2026-08-14**。所以 T447 寫進 `docs/RULES.md` 與全局記憶的這句：

> 「`index.html` **沒有自動存檔**，全檔 `save()` 只在存檔按鈕的處理器裡呼叫一次，
>  所以『把遊戲載起來放著』不會覆蓋任何槽」

**在寫下的那一刻就是錯的**——不是過期，是從未成立。

而 `docs/ARCH.md` §11 那張表**一直有**「自動存檔 | `setInterval(()=>{if(tiles)save();},25000);`」
這一列。三份文件互相矛盾了三十幾張卡沒人發現——**與 T447 自己收的那條債完全同型**
（T447 收的是「三份文件互相引用一條不存在的鐵律」，它自己又製造了一條反向的）。

推測 T447 為什麼會量錯：全檔 `save()` 有數百處是 canvas `ctx.save()`，
自動存檔那行是**裸呼叫** `save()`，在雜訊裡被淹掉了。

## 1. 為什麼要緊（風險的實際形狀）

RULES 18 的防護點是「呼叫 `GV.save()` 之前先釘槽 3」——它假設**只有顯式呼叫會寫存檔**。
真相是：**把 index.html 載進瀏覽器、放著 25 秒，就會寫入當前選定的槽**，
不需要任何 `GV.save()`、不需要按任何按鈕。

⇒ 「在玩家目錄（8123）不得跑測試」這條，過去被理解成「不要在那裡跑腳本」；
   真實強度是「**不要在那個 origin 用玩家的瀏覽器 profile 把頁面打開超過 25 秒**」。

**本季實際曝險為零**，但那是靠兩層與這條結論無關的獨立保險：
① 所有探針跑實驗複本（127.0.0.1:8234）而非玩家目錄；
② 每次拋棄式 `--user-data-dir`，localStorage 依 origin+profile 分割、跑完即刪。

## 2. 順路發現：RULES 有兩條都編號 18

`docs/RULES.md` 第 30 行（存檔槽紀律，T447 新增）與第 37 行（buildSprites 亂數流對齊，既有）
**都是 18**，其後全部連號偏移。T447 插入時撞號了。

   「**載入前釘槽**」——`localStorage.setItem` 必須在 iframe/page 開始載入 index.html **之前**。

   （這是「文件與程式碼互相矛盾三十張卡沒人發現」的直接對策。）
