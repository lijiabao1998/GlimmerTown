## 0. 病灶：釘問錯了問題

業主 09-03 定調：「舊釘對目前的高速迭代已經不足以滿足內容增長」。本卡把這句話變成程式。

六哨兵（`seedPin444`）是**混沌系統終點的精確值**釘。它同時被當成兩件事用：

- **決定性**——同碼同種子必得同結果（抓亂數流位移）。這個目的今天仍然成立，精確恰等是對的形狀。
- **健康度**——AI 城會長大。大家以為有，其實從來沒有。

高速迭代下兩者命運相反：任何內容變動都推動終點值，釘每卡必響，唯一處置是重釘。
**一個永遠響、永遠重釘的釘只記錄歷史，不偵測任何東西。**

T574 是實例：seed301 400 天人口 6801→288（−96%）、12 種子 400 天 pop<500 由 4/12 惡化到 8/12。
Codex 卡面如實揭露，業主授權重釘，六哨兵隨即「吻合」——決定性回來了，健康度的屍體被一起埋掉。
**系統沒有一個位置能讓「8/12 崩城」擋住合併。**

## 1. 手法：單向地板（棘輪），與 PASS 棘輪同形

本專案其他的釘全都不是點值，而且都運作良好：

| 既有釘 | 形狀 | 內容增長時 |
|---|---|---|
| fp／SPR_PINS 1,383 鍵 | 逐項可稽核 diff | 不斷；產出「變更 N 鍵」供對帳 |
| T523 落筆 7500 | 天花板 | 只在真的越線才響 |
| PASS 棘輪 | 單調不減 | 只增不減，永不誤報 |
| ARCH 行數 ±10% | 帶 | 內容長大不響 |

**六哨兵是唯一一個用混沌終點精確值的，也是唯一一個註定每卡必斷的。**
本卡不改它（決定性職責保留），而是在**同一次模擬**上疊加一組單向地板：

1. `docs/HEALTH-PINS.json`——健康度地板的**單一來源**，含每項的 `floor`、`measured`（立釘當日實測）、
   `target`（v11.186 舊版實測，標示我們掉了多少）、`history`（每次調整的日期／方向／授權原話）。
2. `test_fixde.js` 新增 `healthFloor575()`：斷言 `actual >= floor`。
   **一律取用既有三顆哨兵城的同一次 400 天模擬**（量 `GV.stats()`，零額外模擬成本、零額外亂數）。
3. 量測項（全部來自 `stats()`，零掃描）：`pop`、`buildings`、`roads`、`zones`、`poweredBld`。

**為什麼地板設在 T574 之後的谷底而不是舊版高點**：地板設在 6801 會讓套件今天就紅、擋住一切合併，
那不是偵測器是路障。棘輪的語意是「**從今天起不准更差**」；階段二每修好一段就上調一次地板，
`target` 欄把 6801 這個目標留在檔案裡不讓它被忘記。

### 防止靜默下調

地板值只寫在 JSON、不寫在 test 檔（避免重釘時順手改掉）。三道守衛：

- **結構釘**：JSON 必須存在、三顆種子齊全、每項有 floor/measured/target/history。
- **溯源釘**：每個 `floor` 必須等於該項 `history` 最後一筆的 `value`——**下調地板必須留記錄才能通過**。
- **行為釘**：地板值真的被讀入並用於斷言（把 JSON 的 floor 調高一格必須立刻紅）。

### 本卡沉澱

1. **一個永遠響、永遠重釘的釘只記錄歷史，不偵測任何東西**（業主 2026-09-03 定調）。
   釘要先分清問的是「還是同一個程式嗎」（決定性，精確恰等）還是「這遊戲還好玩嗎」（健康度，單向帶）。
2. **地板要放在資料檔而不是斷言裡**——放在 test 檔就會在重釘時被順手改掉；放在 JSON 並用溯源釘
   綁住 history，下調就必須留下人看得懂的一筆。
3. **多指標優於單指標**：R6 證明 pop 上升的同時 buildings 可以崩掉。
4. 五項指標全部取自既有 `GV.stats()`，掛在既有三顆哨兵城的同一次 400 天模擬上＝**零額外成本**。
   新釘不必然昂貴，昂貴的是把它跑成另一次模擬。
