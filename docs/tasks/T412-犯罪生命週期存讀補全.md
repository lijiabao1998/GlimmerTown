# T412 — 犯罪生命週期存讀補全(第三波小 bug 包;純正確性,零新機制)

業主直令「你出卡,你施工,你合并,即便如此,也要嚴格遵守施工紀律」。
T410/T411 把犯罪生命週期做活之後,三個既存不對稱從潛伏變成玩家看得見的說謊。

## 三條 bug(施工前逐一驗明,錨點在手)

1. **`crimeDays` 無存檔通道**:save 有 cm/sk/skd/dt/dtd(犯罪旗/病/病日/死/死日)
   五通道,唯獨沒有犯罪天數;load 於 18852 還原 crime 旗後倒數從 0 重起
   ⇒ **存讀檔就能洗白危房,15 天廢棄倒數形同虛設**。
2. **手動處理不歸零倒數**:`crimeBtn`(16526)與 `GV.clearCrime`(19340)都只
   `crime=0`;警車到場(13647)卻 `crime=0;crimeDays=0` ⇒ **玩家親手處理比等警車
   「虧」=獎勵倒掛**(T410 之後警車真的會來,倒掛才被看見)。
3. **廢棄狀態雙重錯層**:寫入是 `b.abandoned`(建築,12394),save 卻讀
   `t.abandoned`(地塊,18712)——該地塊欄位**從未被任何人寫過=存檔永遠寫 0**;
   load(18827)又還原到地塊層 ⇒ 廢棄建築讀檔後復活照常繳稅(12517/12521 的
   `!b.abandoned` 停稅判定失效)=經濟靜默腐蝕。

## 修法(全部照既有模式,零新形態)

1. 新通道 `cmd`,逐字抄 `skd` 模式:save `String.fromCharCode(48+min(15,crimeDays))`
   (T390 tre 字元碼先例;**上限 15=廢棄門檻**,唯一消費者是 `>=15` 判定,≥15 一律存 15
   語義精確保留);load 挨著 18855 的 skd 應用迴圈,同款容錯(舊檔缺 cmd=0,與現狀等價)。
2. `crimeBtn` 與 `GV.clearCrime` 各補 `crimeDays=0`,與警車到場對齊(三個清案路徑
   同語義)。
3. save 的 `ab` 通道改讀建築層 `t.bld&&!t.bld.ref&&t.bld.abandoned`;load 挨著 cm
   應用迴圈加建築層還原(`b.k<=3` 防禦閘同 cm)。地塊層 `abandoned:` 欄位保留不動
   (死欄位,無讀者,最小侵入);舊檔 ab 全 0=還原無事(與現狀等價,遺失的資料救不回,無回歸)。

## 影響邊界

三處改動全在存讀路徑+UI 按鈕路徑,**不在 400 天 tick 序列裡** ⇒ 兩釘不破(套件為
機器證明)。零新全域(建築欄位隨建築整體重建=鐵律7 免疫)。存檔 schema 純增量,
雙向容錯(舊檔缺 cmd 缺省 0;新檔多 cmd 舊版讀取器不識則忽略——驗證 d.* 讀取慣例)。
**無需飽和量測**:本卡不改任何「發生時機」機制(T408 判準),正確性由往返案證明。
**附帶觀察入檔(不修)**:廢棄時 crime 旗不清(12394),T410 後警車會對廢棄殘骸
出勤浪費行程——屬派遣效率題,留給就近站派遣卡一併考慮。
