# T554 路緣點擊遮擋修復（玩測 P2-1）

**日期**：2026-08-22　**發卡**：業主直令「出卡並嚴格遵守施工紀律」（玩測報告 bay-kimi/playtest-0822/findings.md）
**施工**：Kimi　**風險**：中（輸入命中路徑，三卡中最深；依 LOOP 慣例最後施工）

## 0. 實證（玩測實錘，證據鏈完整）

在道路「下緣」相鄰格畫住宅區：
- 點該格**幾何中心**（`GV.w2v((x-y)*32,(x+y)*16+16)` 權威座標）⇒ 不放置、不扣款、無提示；
- 同一格**中心下移 12px**（菱形下半）⇒ 放置成功；
- 遠處乾燥格單擊即中；(25,1)、(24,5) 等鄰格正常。
- 同格同工具同狀態、唯一變因是像素位置 ⇒ 命中判定被道路偽 3D 貼圖覆蓋區域攔截（疑似按渲染像素/精靈框命中，而非純數學逆變換），把「畫在路邊格」誤判成點在道路上 ⇒ 靜默拒絕。

## 1. 修復方向（定位錨）

- 先考古：找到 canvas 指標事件的格子解析路徑（mousedown/click → 逆等距變換或像素拾取），確認攔截機制為何（預期兩種可能：①像素拾取被路體吃掉；②數學命中後有「點擊目標=道路」的短路分支）。
- 修復原則：**畫設施類工具（分區/建築）的格子判定以數學逆變換為準**；道路自身的選中/查看行為不受影響。若根因是②短路分支，僅對「放置類工具」放行到正確格子；若根因是①拾取緩衝，改用數學命中或修正拾取優先級。
- **靜默失敗兜底**：任何放置失敗（含地形/資金不足以外的原因）至少給一次輕量提示（toast 或閃紅），杜絕無聲吞操作。此項為本卡第二紅線。

## 2. 允許觸碰／禁區

- 允許：index.html 指標事件→格子解析段、放置類工具的命中分支、失敗提示、test_fixde.js 守衛、CHANGELOG、sw.js（僅 bump）。
- 禁區：亂數流（鐵律2）、tick 模擬、繪製層像素輸出（SEEDPIN/指紋契約——不得改動任何 sprite 繪製）、存檔格式、相機控制手感。

## 3. 驗收

- G1【行為】於道路下緣相鄰格中心座標派發放置（Node 可用與遊戲同源的命中函式；若命中在 DOM 層則真瀏覽器 CDP 座標點擊）：住宅區必須放上（zones +1）。
- G2【迴歸】點道路本身仍是道路語意（查看/選中不誤觸發放置到鄰格）。
- G3【提示】放置被拒時必有可觀察回饋（toast DOM 出現或等效旗標），靜默路徑清零。
- 紅源二案：還原命中短路 ⇒ G1 紅；移除失敗提示 ⇒ G3 紅。
- 三根 SEEDPIN 位元恆等＋全套件 PASS 不低於現行基準／0 FAIL；真瀏覽器 8125 槽3 重演玩測原場景（路緣畫區成功）截圖。
