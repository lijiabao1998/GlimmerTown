# T265 垃圾焚化發電廠 k62（垃圾處理 × 能源回收）
版本：v5.0 ｜ 難度：★★★ ｜ 前置：T253/T257 電源升級、T119 垃圾車 ｜ 施工模型：GPT

## 目標
新增 2×2「垃圾焚化發電廠」k62，把垃圾處理與中型基載電力合成一座高成本、高污染的複合設施。玩法參考 Cities: Skylines 系列「垃圾車收運 → 焚化處理 → 蒸汽發電」語義，但沿用本作既有的全城垃圾容量模型，不新增垃圾庫存或新的每日亂數。

## 平衡定稿
- 尺寸 2×2；造價 $1800；就業 12；維護費 $10/天。
- 垃圾容量：固定 +100；升級只擴充發電機組，避免同時淘汰垃圾場／回收中心的容量定位。
- 供電容量：Lv1 60，每升 1 級 +8（Lv10 為 132）；可獨立啟動電網。
- `UP_MAX[62]=10`、`UP_JOB[62]=0`：升級只擴充處理／發電設備，不產生幽靈就業。
- 高污染設施：`POL_SRC[62]={r:7,p:44}`，峰值與範圍都高於一般電廠，拆除需對稱撤印。
- 作為垃圾車出勤來源及 `garbLocal` 道路距離來源，與垃圾場 k8 並列。

## 定位錨
- `KNAME`／`COST`／`TOOLS`；`canPlace()`／`placeCost()`／`doPlace()`。
- `computePower()`；`POL_SRC`／`rebuildCov()`。

- `buildSprites` 絕對尾端；`test_fixde.js` 的 SV／SVK／tampered 與 T265 專項。

2. 不改現有 k1..61 的數值、分支順序與 sprite 鍵。
3. sprite 只在 `buildSprites` 絕對尾端生成；只用局部繪圖／局部 PRNG／`streetHash`，不得消耗全域 `R()`／`ri()`。
4. 存檔零格式變更：沿用既有 `bl` root tuple；`MSZ[62]=2` 供 load 重建 3 個 ref 格。
5. 第二經濟迴圈必須有 `else if(b.k===62);` 空守衛，任何等級 money/fin 不得 NaN。
6. 放置／拆除污染蓋印對稱；undo、load、newWorld 後重建結果一致。
7. 完工線 `age>=9`；瀏覽器像素驗證須先 `GV.step(12)`。
8. 垃圾容量與供電必須由同一 k62 root 精確計數一次，ref 格不得重複計數。
9. 中低畫質、無 k62 的固定種子城市模擬不得因本卡新增任何額外主亂數消耗。
10. 不刪除任何資料夾；不讀寫 localhost 的玩家 s1/s2。
