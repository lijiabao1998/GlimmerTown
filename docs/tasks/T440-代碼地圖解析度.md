## 0. 這張卡為什麼存在

T437／T438／T439 三張卡的收尾都寫了同一句話：「ARCH §1 仍有約 **19%**（4,084 行）未測繪」。
**那個數字沒有量法。** 我寫了三次，卻從來沒有定義過「測繪」是什麼意思——
這正是 T437 自己那張卡在罵的東西（「數字沒有量法就會騙人」），而我在同一份文件的收尾裡連犯三次。

實際去查：§1 有 77 列，錨點命中行從 32 到 21306。若把「未測繪」理解成
「相鄰兩列錨點之間 ≥400 行的空白」，那是 **13,645 行（62%）**，不是 19%。
兩個數字都不對，因為**「覆蓋」根本不是這張表的正確概念**：
每一列標的是一個**區段起點**，下一列之前的東西都算它的；表不會「漏掉」行，只會「太粗」。

所以真正該問的不是覆蓋率，是**解析度**。

## 1. 定義（寫死在這裡，任何人都能重算）

> **§1 的解析度 ＝ 相鄰兩列錨點命中行的最大間距**（含最後一列到檔尾）。
> 今天實測：**最大 4,070 行**（`FIX-B 尾端區起點` 5220 → `加蓋層 pass 群` 9290）。
> 一個 4,070 行的「區段」等於沒有指路——那正是 T437 想修的病，只是換了個形態。

目標：把最大間距壓到 **≤600 行**，並且**進守衛**，讓它不能再默默變粗。

## 2. 落地

| 4 | 把 ARCH 表頭那句「19% 未測繪」換成上面的解析度定義與實測值，並留下更正記錄 |

## 3. 驗收

`arch_map --check` 綠且解析度 ≤600；破壞式紅源（把某一列刪掉讓間距超標）必紅；
`tools/verify.py` ALL GREEN、PASS 只增不減；**不動 `index.html`**（兩釘與部署不受影響）。

這張卡不是去補測繪，是去把那個數字換成一個能被別人算出同一個值的東西。

### 5.2 挑錨點時自己抓到的兩個問題

1. **第一版有兩個候選是 `/* ==========…`——那串字在檔裡不只一處。** 拿不唯一的字串當錨點就是指錯路。
   加上「錨點字串在 `index.html` 必須恰好出現一次」之後才重挑。
2. **第一版只收頂層函式與 `===== 橫幅 =====`**，而 `buildSpritesS6` 那類巨型函式**內部**兩者都沒有，
   3236→4854 中間 1,619 行補不進去。實際去看那段，裡面有大量 `/* T382：… */` 逐項註解——
   同樣是檔內既有原文、同樣唯一。**是我的候選集太窄，不是那段沒有東西可指。**

### 5.3 G3 第一版是錯的（破壞式紅源當場抓到）

G3 的職責是「上限不能被偷偷放寬」。第一版寫成

```js
assert(/const MAX_GAP440 = 800;/.test(fs.readFileSync(__filename, 'utf8')) && …)
```

紅源②把宣告改成 `5000`，套件卻**全綠**——因為那串字**也出現在 G3 自己那條 assert 的正則字面量裡**，
紅源只改了第一處（宣告），第二處還在，文本比對照樣命中。
**一條專門用來擋「偷偷放寬判準」的守衛，自己就能被偷偷放寬。**
改成比**值**：`MAX_GAP440 === 800` 且等於 `tools/arch_map.py` 解析出來的 `MAX_GAP`。
（同型錯誤今晚第四次：T428 G1 的 CSS 註解、T437 死錨點的 `some`、T434b G2 的更正註解、這一次。）
