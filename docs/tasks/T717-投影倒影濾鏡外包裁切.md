## 問題

T149 建築投影與 T163 水岸倒影，每次都用 `ctx.filter='brightness(0)'` 即時把精靈壓成黑剪影。
- T149 夜晚每棟建築畫一次，高畫質白天也畫；T163 在縮放 ≥1 時畫。
- Chrome 的畫布濾鏡每次都會開一層和目前裁切範圍一樣大的中間層。沒有裁切時就是整張畫布，畫完再合成回來。
- 成熟城夜晚每幀 56～170 次，每次都是整張畫布的開層、清空、合成。

量到的數字：
- macOS 真 GPU（T707 dispatch，run 39914014861，1280×800）：夜晚每幀平均 44 毫秒（約 23 fps），白天約 24 毫秒。
- 雲端真 Chromium（軟體繪圖，只看相對）：72 格成熟城夜晚，把中間層縮到剪影大小，每幀約快 5～6 倍。

## 做什麼（`index.html`）

- `clip717(g,dx,dy,dw,dh)`：
  - 把裁切縮到矩形 `(dx,dy,dw,dh)` 在裝置像素上的外接矩形（目前變換下的四個角，外擴 2px，整數像素邊界）。
  - `dw`／`dh` 可以是負的。
  - 用獨立的 `Path2D`，不動畫布目前正在累積的路徑。
  - 環境沒有 `getTransform` 或 `Path2D`（測試用的假畫布）就不裁切。
- T163 倒影：
  - 原生程式在 `translate(ax2,ay2);scale(1,-.35)` 之後畫 `(-rs.ax*z,-rs.ay*z,rs.w*z,rs.h*z)`；
  - 換回外層座標就是 `(ax2-rs.ax*z, ay2+.35*rs.ay*z, rs.w*z, -.35*rs.h*z)`，用這個呼叫 `clip717`。
- T149 投影：原生程式畫 `(bx+SHOX*z, by+s.h*z-shH+SHOY*z, s.w*z, shH)`，在原生 `const shH` 之前用同一條式子另算一次。
- 兩處都是 `if(c717){ctx.save();clip717(...);}`，原生程式照舊，接著 `if(c717)ctx.restore();`。
- 閥：`t717On()`。`?noT717=1` 或 `window.__noT717` 時完全不包，和改前逐字同一條路。登記在 `docs/APPROVED_ART.json` 的 `valves`。
