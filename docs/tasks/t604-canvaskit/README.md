# T604 CanvasKit whole-night candidate

This isolated feasibility branch starts at verified Pages main `329f660` and applies the clean approved T603 art from `23564a8`. It does not merge or deploy PR #5. Main remains unchanged. Source inversion verifies that game logic, simulation, RNG, save handling and art are identical to that candidate outside four renderer hooks; the SW change only adds self-hosted renderer assets.

CanvasKit 0.42.0 is pinned to the official npm archive, SHA-512 integrity, archive SHA-256/SHA-1 and per-file SHA-256. Its BSD-3-Clause license travels with the packaged files. The browser loads no runtime CDN. The JS/WASM/license add 7,439,857 uncompressed bytes before application/renderer files. The archive is fetched only by the build and is not committed.

The opt-in URL is `?renderer=canvaskit`. Game command generation runs once. CanvasKit consumes the ordered commands on one WebGL surface; an unknown operation rejects the entire frame before paint and replays that same packet through native Canvas. All recording, validation, resource/upload, rendering and fallback costs belong to the candidate. An inactive fallback does not qualify as GPU success. Mutable source canvases retain per-frame versions; self-copy uses a prefix snapshot and explicitly falls back. Native text and active Canvas shadows currently require whole-frame fallback. Existing pre-baked sprites remain unchanged.

Stage one uses the established headed `macos-15` Chrome display qualification. It compares a true original native page with the candidate, using independent native/GPU/GPU/native five-second live windows on the same 956-root seed-22 night scene. No tracing runs during those windows. CPU attribution follows timing. A measurable benefit requires both GPU samples to exceed both native samples by 10%, with no fallback frames. The original 55 FPS target is reported independently and is not waived.

Before timing, full compositor images expose native recording differences and new backend differences on identical stars, dust, actors, camera and clocks. A wrong-sky GPU negative control and exact restoration prove comparison sensitivity. No pixel is masked. New visual results require review; the old zero-difference gate remains reported. Replay audits check no RNG/model advancement. Native recorder microcases cover gradient transforms, path clips, blend/text fallback, mutable sprite canvases and self-copy.

The candidate package uses the already verified main save/cache namespace and preserves Lab keys. The browser experiment records cold WASM initialization, network resource bytes, cache sizes and official WASM hash, then tests full-network-offline reload, Continue and save/load with Lab namespace sentinels. Loopback is a secure context, not a production HTTPS deployment claim.

Run focused tests with `CANVASKIT_DIR=/path/to/package node docs/tasks/t604-canvaskit/player.test.cjs`; these 25 software-surface tests do not claim WebGL equivalence. `node docs/tasks/t604-canvaskit/run604.cjs --check-overlay` checks harness composition without launching a browser. The Mac workflow is an experiment, not full release acceptance. No measurable whole-frame benefit is a stop condition; failures and artifacts are retained. Whole-game regression, additional scenes/platforms, image review and the original performance/pixel requirements are outstanding before any release.
