## 5. 一個需要先想清楚的設計問題（不是實作細節）

新守衛擋的是「刪除既有條目」。但**合法的刪除**確實存在：
例如本卡自己若要把某條寫錯的歷史條目改正，就會產生 `-` 行。

本卡採取的規則（寫在這裡，不寫在程式註解裡——T428 教訓 27）：
> **預設拒絕刪除**；要刪除必須在**同一個 commit 的訊息**裡出現 `CHANGELOG-CORRECTION:` 開頭的一行，
> 並在該行說明刪哪一條、為什麼。守衛讀 commit message，不讀程式註解，也不讀卡面
> ——因為卡面可以事後改，commit message 不能。

這條規則本身也要有紅源：造一個「有 `-` 行但 commit message 沒有 `CHANGELOG-CORRECTION:`」的案子必須紅。
