| 事實 | 數字 |

**兩件事共用同一個主張：玩家找不到東西。** 分組解決「掃描成本」，指令面板解決「查找成本」。

## 1. 落地

### A. HUD 分組（純 CSS／DOM 順序，零事件改動）
13 顆按鈕包進四個 `.hudGrp552`，群間以間距＋細分隔線區隔，順序依使用頻率：
1. **檢視**：📊 統計・❓ 指南・🏆 成就・🔔 通知
2. **世界**：▶ 速度・🤖 AI・🔄 旋轉・🚇 地鐵圖層
3. **編輯**：↩️ 撤銷・🛠 目標
4. **系統**：💾 存檔・🆕 新局・🏠 主選單・🔊 音效

按鈕的 id、onclick、DOM 物件全部原封不動——只加包裹層。

### B. 指令面板 `Ctrl/Cmd+K`（也接受 `/`）
**核心紀律：它是路由器，不是第二套實作。** 沿用 T517 判例——
「絕不自己寫狀態，只 `.click()` 既有控制項」。三個索引來源、三條路由：

| 來源 | 筆數 | 路由方式 |
|---|---|---|
| 建築工具 `TOOLS` | 153 | 先 `.click()` 對應的分類鈕（工具鈕**只在其分類啟用時才存在於 DOM**），再 `.click()` `[data-tid]` |
| 面板與動作 | 13 | `.click()` 對應的 HUD 按鈕 |
| 政策 `SCI451` | 51（有 polKey） | `.click()` `#bStats` 渲染面板 → `.click()` `#polDomId514(key)` 的 checkbox（T517 同款） |

互動：輸入即篩選、↑↓ 移動、Enter 確認、Esc 關閉、點面板外關閉。
`z-index:40`（高於 HUD 30、低於 `#start` 50 ⇒ **開始畫面不可能被它蓋住**）。

**接線要點**：第 22070 行「修飾鍵一律早退」會吃掉 Ctrl+K，故開啟判定必須插在該行**之前**；
Esc 目前綁「選回第一個工具」，面板開啟時必須先攔截並 `return`，不得落到那條。

## 2. 為什麼這張卡是安全的

HUD 分組是包裹層；指令面板是純疊加的 overlay，所有動作都轉交既有控制項。
兩者都不在 `tick()` 路徑、零 `R()/ri()` 消耗、不動存檔格式 ⇒ **六哨兵位元恆等**。

## 3. 驗收計畫

- **G1（靈魂）路由不自己寫狀態**：面板的動作實作內不得出現對 `tool=`／`pol[`／`toolCat=` 的直接賦值，
  只能出現 `.click()`（機械掃函式體）。這條擋的是「指令面板變成第二套真相」。
- **G2 工具路由行為釘**：造境選一個**不在當前分類**的工具（如 `hospital` 在服務類、當前為 base），
  經面板後 `GV.tool()` 必須等於該 id ⇒ 證明「先切分類再點」這條鏈成立。
- **G3 索引涵蓋**：三個來源的筆數皆 > 0 且工具數等於 `TOOLS` 可見筆數；搜尋「醫院」必須命中。
- **G4 HUD 分組**：13 顆按鈕全部落在 4 個 `.hudGrp552` 之內（一顆都不許漏在群外）；
  所有既有 id 仍在 `#hud` 之內。
- **G5 鍵盤接線**：Ctrl+K 判定必須早於修飾鍵早退行；面板開啟時 Esc 不得落到「選回第一個工具」。
- **G6 層級**：`#cmdk552` 的 z-index 必須 >30 且 <50（在 HUD 之上、開始畫面之下）。
- **G7 零亂數**；**G8 六哨兵位元恆等**。
- **行為證明**：真瀏覽器跨視窗——面板可開可關、搜尋命中、選取後工具真的切換；HUD 分組後不增加列數。
- 紅源：①路由改成直接寫 `tool=` → G1 應紅；②Ctrl+K 判定移到修飾鍵早退之後 → G5 應紅；
  ③拆掉一顆按鈕的群包裹 → G4 應紅。

**刻意不做**：科技樹 36 節點不進索引——選中特定節點沒有既有的可點控制項可路由，
硬做就會變成「第二套實作」，違反 G1 的主張。留待科技面板自己提供節點錨點後再收。
