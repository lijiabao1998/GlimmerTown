## 目標跑法

主線只有一條落地路：**GitHub PR → 機器閘門 → main → 部署前閘門 → Pages**。本機 `C:/dev/glimmer-town` 的 master 只當 origin/main 的快轉鏡像。

1. **觸發**：CI 一律由 pull_request（含轉 ready）、推 main、手動觸發三種；不再手動 dispatch、不再把分支名寫進工作流。轉 ready 會重跑一輪，Codex 審查結構上一定比合併早到；合併前把 P0／P1 在 PR 上一行回覆，不要求照修（文章：對抗式審查會過度防衛）。
2. **道別**：改動全是 `.md` 走文件道（validate＋帳本閘，約 5 分鐘、不部署）；其他一律全道。卡頭機讀欄 `families`、`valve`、`removed_asserts` 在第一個 commit 後凍結，`owner_ok` 只准從空變成業主原話。`gpt/` 分支碰守衛或規則路徑，CI 判紅。守衛路徑新增寫死的 40 位提交 SHA，判紅。
3. **閘門**：`gate` 是唯一必要檢查（放在不給任何人繞過的規則集，業主按）；部署等 gate 綠。部署前要過：原有各道＋scene602＋PASS 棘輪（不准少於 base）＋簽核欄＋CHANGELOG 只增不減＋像素指紋（釘版 Chromium 實算＝倉庫值、觸及家族＝卡頭宣告）；T648 起再加整幀比對（非美術卡畫面零變、改圖時 CI 自動出接觸表）。
4. **合併**：只用 merge commit，不要求分支先更新到最新（照文章，靠合併後、部署前的測試擋）。main 紅了，由讓它紅的那次合併的作者先開純 revert PR，不在 main 上疊修補賭綠。
5. **分工**：業主給一句方向、看 CI 接觸表點頭（＝`owner_ok`）。Claude 定約束、開工巡檢、寫守衛與規則、把方向拆成待辦。GPT 照佇列一項一 PR；能自己合的只有文件、畫面零變的本體、卡頭有業主原話的美術；佇列空了或碰停手條件就停，不自己出題。

## 不採用（與理由）

- 換掉 git／Scion／伺服器端合併：主線 9 天 23 個 PR，瓶頸在 CI 與人工儀式，不在 git；文章自己也說不是通用替代品。
- merge queue、全域鎖、分支須先更新到最新：個人帳號倉庫；照文章改用合併後＋部署前測試，加 revert 程序。COLLAB 的強制串行一併拿掉（T645）。
- 合併前硬等 Codex：改成轉 ready 重跑讓審查先到，P0／P1 一行回覆。
- GPT 自己出題的無限迴圈：主線嚴格紀律，題目由 Claude 依業主方向拆，待辦空了就停。
- 實驗線的 `paths-ignore docs/**`：主線守衛腳本與 SPR_PINS 都在 docs/ 底下；改用「全部是 .md 才走文件道，validate 照跑」。
- 實驗線「非全局美術可先合、業主事後看」：主線美術一律合併前 `owner_ok`。
- squash／rebase 合併：祖先檢查與卡頭凍結都依賴完整歷史。
- 新批次併進 SPR_PINS：多處寫死「1586 鍵」，改另存 ART_PINS.json（T646）。
- CODEOWNERS、required reviewers、拆帳號：所有工具共用一個帳號，靠身分擋不住；改靠 gate、commit 作者名與巡檢。
- 每日巡檢的 Superfan Claude、每週排程：遊戲沒有遙測；改成開工時跑一次唯讀巡檢（T642）。
- 自動 bisect、自動合 revert；平衡配對比較搬上 CI；拆 index.html；退掉 merge_bay（它仍是 8123 唯一的發佈路）。
