## 0. 這張卡挑的是哪兩條債

`docs/ARCH.md` §10「有規矩但沒有機器守著的」列了 16 條。本卡收兩條**機械可查、且會直接影響玩家**的：

> **§10.9**　工具列顯示價 vs `placeCost` 實扣沒有一致性斷言（`oneway`／`light` 兩處是字面值硬編碼）。
>
> **§10.10**　鐵律17（`SPR` 撞名）與鐵律6（`hw` 必為偶數）都沒有機器守。
> 實測 `SPR` 有 110 個頂層鍵，4 個被賦值兩次（`police`／`hospital`／`clinic`／`waterTower`，
> 全是 T151/T162 刻意的「後寫後贏」），但沒有任何測試能區分**刻意覆蓋**與**撞名事故**。

§10.9 的玩家後果很直接：**按鈕上寫 $20，實際扣的可能不是 $20**，而且沒有任何東西會發現。
目前絕大多數 `pr` 已經寫成 `'$'+COST.x` ⇒ 天然同源；缺口是 `oneway`／`light` 兩個**兩邊各寫一份字面值**。

## 4. 施工紀錄（Claude 全鏈；起點 master `fdd16ea` → v11.79，PASS 4,922）

### 4.1 §10.9：對帳結果是**乾淨的**

`COST` 補 `oneway:20`／`light:60`，`TOOLS` 與 `placeCost` 都改引它；
`GV` 加兩個唯讀鉤子 `cost443(k)`／`placeCost443(id,x,y)`，讓 Node **真的跑定價公式**。

窮舉守衛在乾淨平地（無樹、無路、無建物、非水面）對 **105 個**工具對帳：**0 項不一致**。
紅源把 `light` 的顯示價改成 `$61` ⇒ 守衛紅並點名 `light 顯示 $61 實扣 $60`。

跳過的 17 個逐條註明理由：道路系逐格地形計價、地形筆刷逐格累加、分區已有時為 0、
`doze` 隕石坑另計 $120、`rail`／`tram` 有橋樑價、`pan` 不施工。

### 4.2 §10.10：鐵律17 收口，鐵律6 做成計數釘

- **鐵律17**：頂層 `SPR.<鍵>=` 重複賦值必須列在白名單並註明理由。
  掃到 94 個頂層鍵、4 個重複（`police`／`hospital`／`clinic`／`waterTower`，T151/T162 刻意的後寫後贏），
  白名單外 0 個。（ARCH §10.10 原文寫「110 個頂層鍵」——那是另一種口徑，本卡的掃描器只數頂層直接賦值，
  **數字不同不是誰錯，是母體定義不同**，已在 ARCH 註明。）
- **鐵律6**：實測既有違規 **20 個**，全是既有美術。修它們＝改 20 處 sprite 像素＝**觀感決定**，
  不是守衛可以順手做的事。所以凍結成計數釘，新增即紅；清單見 §4.4，交業主。

### 4.3 寫這條守衛時被自己抓到的三件事

1. **母體是照轉述建的。** 我依 ARCH §10.10 的「`hw` 必為偶數」去掃 `isoBox`／`boxUnit`，
   而鐵律6 的原文（`docs/RULES.md:13`）點名的是 **`dia()` / `diaEdge()`**——那兩個我第一版一個都沒掃。
   （`isoBox`／`boxUnit` 會把同一個 hw 轉手交給 `dia`，所以它們也在範圍內，但主母體不是它們。）
   **這是 T441「全檔唯一」的同型錯，這次在出貨前抓到。**
2. **引數不能用 `split(',')` 切。** 引數裡有陣列或巢狀呼叫就整排錯位。改成深度感知切分，
   並加「括號切不出來的呼叫必須為 0」當自檢。
3. **唯讀鉤子被我插進了 `chain346()` 的回傳物件裡。** 我拿 `upCost364:…}),` 當錨點，
   以為它是 `GV` 的成員，其實它是那個巢狀物件的最後一員 ⇒ `GV.cost443` 是 `undefined`，
   守衛整圈 `continue` 而**對帳 0 項**。
   **是 G1 自己那條「對帳項數 ≥90」把它擋下來的**——沒有那條，這會是一片安靜的假綠。
