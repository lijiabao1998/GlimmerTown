# T34 診所系統

## 目標
在醫院（T33）之外新增較小型的健康設施「診所（clinic，k=13）」，形成醫療梯度：診所便宜、覆蓋半徑小；醫院貴、覆蓋半徑大。兩者不可互相取代，玩家需依城鎮規模與財政搭配使用。

## 需求

### 1. 常數與工具列
- `COST.clinic = 250`。
- `KNAME[13] = '診所'`。
- `TOOLS` 在醫院工具後插入診所；快捷鍵 `c`（clinic）。
- 小地圖建築色表擴充到索引 13，使用與醫院同色系但稍亮的顏色（如 `#f27e7e`）。

### 2. 建造邏輯
- `canPlace` / `placeCost` / `doPlace` 支援 `clinic`：僅陸地、非道路、無建築。
- `doPlace` 建立 `t.bld = {k:13, lv:1, v:ri(3), age:0, pw:true, h:1}`。
- 拆除邏輯正確清除診所。

### 3. 模擬邏輯
- tick「生病」段調整：
  - 住宅是否被健康設施覆蓋的判定改為「半徑 6 內有診所 **或** 半徑 12 內有醫院」。
  - 未被任何健康設施覆蓋的住宅每天小機率生病（現有 `.001*b.lv` 不變）。
  - 被診所覆蓋（但無醫院）的生病住宅：康復機率較低，例如每天有 50% 機率康復（醫院覆蓋仍為次日必康復）。
  - 被醫院覆蓋的生病住宅：維持次日康復。
- 經濟段：診所計數 `clinics`，每日維護費 `clinics * 2.5`；統計面板 `fin.upC` 顯示診所維護費。
- 診所也提供少量就業，例如 `jobs += clinics * 4`（比照學校/體育場的 jobs 設計）。

### 4. 視覺
- `buildSprites()` 尾端追加診所 sprite：72×112，外觀為小型診療所（白牆、紅十字、小門廊、夜間窗燈），3 變體。
- `draw()` 物件層正確繪製 `k=13`。
- 生病住宅的紅十字標記已由 T33 實作，無需改動。

### 5. UI
- `inspect()` 加診所分支：「🏥 診所｜半徑 6 健康覆蓋｜就業 4｜維護費 $2.5/天」。
- `showStats()` 計數加 `nC`、維護費行加「🏥 診所 -$fin.upC.toFixed(1)」、建築行加「診所${nC}」。
- `showHelp()` 追加診所說明一行。

### 6. 存檔
- 診所是正常 1×1 建築，k=13 已透過 `bl` 陣列儲存，無需新增欄位。
- 生病標記 `sk` 已在 T33 實作，無需改動。

### 7. 測試
- 新增 `test_t34.js` DOM mock 測試（沿用 T33 的 mock）：
  - 固定種子建造診所與住宅。
  - 強制生病後，診所半徑內住宅每天有機率康復（跑多天觀察）。
  - 無任何健康設施的住宅保持生病。
  - 存讀檔後診所與生病標記保留。

- `node test_t34.js` PASS。
