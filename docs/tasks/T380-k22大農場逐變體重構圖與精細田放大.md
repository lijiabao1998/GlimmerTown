## 出卡前的偵查（全部是實測，不是推論）

偵查用 `t380probe` worktree（`9927d65` 且**停用 k22 的 doFarm**），在 atlas 逐像素量地面真值。
方法：地墊由 `plate(g,ax,ay,'#8a9a5a',2)` 產生 ⇒ 地面色恰為 5 色
（`#8a9a5a` 與 `shade(±10/±20/+8)` = `#809050/#92a262/#768646/#94a464`），非這 5 色即美術。
**自我檢核：地墊菱形格數必須等於 4161，實得 4161 ✓**（第一版我把范數半徑寫成 128 而非 64，
整張畫布上半部都被算成地墊，數據全錯；此處的自我檢核就是為了擋這個）。

### ② 繪製順序（本卡的關鍵，T378 事故的根）

```
[4467-4584 / 7313-7397] 16 個變體塊：plate() → 該變體自己的 fillRect 美術
[7544]                  doFarm('22_1_'+v, 68,148, 30,15, CCLASS[v]) → field() + plantGrid()
[7557+]                 stampKit / farmstead(...) 農莊套件
```

⇒ **田蓋得到變體美術（T378 就是這樣壞的），但蓋不到農莊套件（套件畫在田之上）。**
所以「田能做多大」的唯一約束是**變體專屬美術**，套件不是約束。
（我一度把套件也當約束，算出 hw39 的假上限；記在這裡免得覆核時重犯。）

### ③ `cy=ay-16` 不是 bug，是 T353 定的慣例

index.html:7546-7549 的 T353 註釋明寫：「k22 的慣例是 cy = footprint 中心 +16
（＝最前一格的中心）」，並且 T353 已為 k53 解過同一題 —— 拒用同慣例的 cy=178，
因為「y152..204 那一帶正是 base 自帶的雙筒倉/農舍/乾草捆，田會把它們蓋掉」，改放前緣空地 cy=206（傳 ay=222）。
**移動田位的手法就是傳不同的 ay，這是 T353 建立的既有做法，不需要加參數。**
`doFarm` 內 `gax/gay` 取自 `SPR.bld[key]`（7530-7531），所以改傳入的 ay **不會**動到精靈錨點 metadata（T353 守衛保護的正是這點）。

### ④ 為什麼「只移動田」不夠 —— 三條路都量過了

| 約束 | 最大田 | 面積比現況 |
|---|---|---|
| 完全避開該變體自己的美術（逐變體各自最佳） | hw18~22 | **0.36~0.54×**（平均 0.42×，比現在**小**） |
| 全 16 變體共用一組參數且完全避開美術 | hw17 | **0.32×** |
| 維持現有侵入量（平均 235px／變體） | hw30~34 | **1.06×**（等於沒有增益） |

**現有的 hw30 已經大於任何「不蓋美術」的擺法。** 田沒有地方可以移過去變大 ——
除非**美術本身讓位**。這就是本卡與 T379 的分界。

### ⑥ 這推出本卡的設計決定（**業主可在此否決**）

**16 個變體自己那塊小作物補丁是重複的** ——`doFarm` 本來就收 `CCLASS[v]`，
`plantGrid()`（7496）已經按變體畫該作物。變體塊裡再畫一塊小作物只是把田的工作做兩次。

所以：**移除變體塊裡與作物重複的補丁，讓精細田承擔全部作物表現**；
少數有「招牌建築」的變體（v2 溫室最明顯）用**逐變體參數**保留它、田讓開一點。

代價講明：v0 的小穀倉、v2 的溫室這類「變體自帶建築」若無處可放就得移除或縮小。
農莊套件（農舍＋紅穀倉＋筒倉＋圍籬＋乾草＋拖拉機）每個變體都有、且畫在最上層，
所以移除變體自帶建築**不會**讓農場看起來沒有建築。

### ⑦ 亂數與色票（實測）

- **`field`/`plantGrid`/`stagePlant`/`P` 表整段（7475-7550）零亂數 token**
  （`rand(` / `spriteTexRand` / `R()` / `ri(` / `Math.random` / `mulberry` 皆 0 次），繪製原語只有 `px1`/`drawImage`。
- **16 個變體塊各含恰好 1 個 `plate(`、0 個 `rand(`/`spriteTexRand`/`windows(`/`speck(`/`R()`/`ri(`**
  ⇒ 變體美術全是純 fillRect，搬動/刪除**零亂數風險**。
  但 `plate()` 自己經 `speck` 消耗 `spriteTexRand`（固定 78 draws）⇒ **每塊必須保留恰好一個 `plate`，不得增減。**
- 作物顏色是 T229/T353 季節重映射表的**鍵**。新作物顏色必須登記到 `SUM353/AUT353/WIN353`，
  否則換季時該色失效（T274 有逐位元凍結測試）。**能不加新色就不加。**

### 1. `index.html` — 逐變體田參數表

把 7544 那一行的固定參數換成逐變體表（沿用 T353 的「傳不同 ay」手法，**不加新參數**）：

```js
/* T380：田移到地墊真中心並放大。[ax,ay,hw,hh]；ay 是傳給 doFarm 的值，實際田心 cy=ay-16。
   預設 (68,144,40,20) ⇒ 田心 (68,128)、hw40 ＝1.78 倍面積；保留招牌建築的變體可個別縮讓。 */
const F22=[/* v0 */[68,144,40,20], /* …16 筆… */];
for(let v=0;v<16;v++){const f=F22[v];doFarm('22_1_'+v,f[0],f[1],f[2],f[3],CCLASS[v]);}
```
