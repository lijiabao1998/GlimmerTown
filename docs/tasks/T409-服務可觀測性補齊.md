# T409 — 消防/警察/垃圾可觀測性補齊(服務效果接線 第一波;零模擬影響)

業主指示「服務效果接線(垃圾/消防/警察+預算)」。偵查(wf_4fb63211 三向)後**重寫了題目框架**,
本卡是第一波:**先把量測做出來,再動模擬**(T408 的教訓:沒有飽和期觀測量就會誤判)。

## 偵查改寫的三件事

1. **垃圾早就接了效果,不是「只顯示」**:超載時 `pen=(garbRatio-1)*.15` 逐棟扣住宅幸福
   (`b.h=clamp(b.h-pen,.05,1)`),另有離垃圾場過遠(BFS 道路距 >18)固定扣 .045,
   還進城市評分 `garbScore`、AI 也依 garbRatio 蓋設施。
   **真缺口是玩家看不見**——這兩條扣分都繞過 `happyParts` 直接改 `b.h`,
   幸福構成面板裡沒有垃圾這一項。
2. **警察派遣幾乎是死碼**:覆蓋是**布林完全免疫**(擲骰前 `continue`)⇒ 犯罪只發生在**未覆蓋**格;
   而 `updPoliceCars` 候選是 `b.crime&&(COV.police[i]>0||COV.police2[i]>0)`⇒**只收已覆蓋格**。
   本卡不修(那是第二波,會破兩釘),但**本卡的觀測量讓這個 bug 在遊戲內直接現形**。
   **(施工後實測更正)**初稿寫「兩集合互斥、警車永無目標」——**過強,已被本卡自己的量測推翻**:
   兩集合在**時間上**不互斥,案件可以「先犯罪、後被新蓋的派出所覆蓋」而落入派遣範圍。
   seed301 AI 400 天實測:可出勤數在第 100/200/300 天皆為 **0**,第 400 天才是 **4/23**。
   正確表述=**新發生的犯罪永遠不在派遣範圍內,警車只撿得到「覆蓋追上來」的殘案**。
3. **消防才是真沒有容量概念的**:滅火在幀路徑(`updFireTrucks`),tick 不知道今天處理了幾場;
   `svc.fire` 只有 {stations,hq,trucks} 純計數,無 cap/ratio/queued;
   且**消防總局 k61 不在出車站名單**(`sts=listBldK(6).concat(listBldK(30))`),只貢獻覆蓋半徑,
   面板卻把 hq 與 stations/trucks 並列,誤導玩家以為它能出車。

## 設計(全部照 T387b/T145 的「tick 區域計數器」模式:零全域、零存檔、零守衛面、零亂數)

計數搭**既有經濟迴圈** `for(const i of tickBld)`(`let income=0,upkeep=0,…,fireStations=0,…` 之後)——
該迴圈在火災段(起火)與犯罪段之後,故計到的是**當日結算後**的真實狀態;
且 `fireStations/policeStations/policeBoxes` 在同一迴圈累加 ⇒ **同日即可算容量,不需昨日快照**
(避開 T387b 當初被迫用快照的 TDZ 陷阱)。

新增量(全為 tick 區域 let,命名 409 尾綴):
- `fireN409` 當日火災總數;`fireSvc409` 其中**可出勤**數(條件逐字照抄 `updFireTrucks`:
  `COV.fire[i]>0||COV.fire2[i]>0||COV.fireHQ[i]>0`)⇒ 差值=**永遠等不到消防車的火場**。
- `crimeN409` 當日犯罪總數;`crimeSvc409` 其中可出勤數(逐字照抄 `updPoliceCars` 條件)。
- `garbPen409` 本日超載扣分值(**只記錄既有 `pen` 變數,不改計算位置**);
  `garbFar409` 吃到距離懲罰的住宅數(搭 `computeGarbLocal` 既有迴圈)。

容量(同日算,與 `updDispatch` 的 `Math.min(cap,sts.length)` 逐字同構):
- 消防 `cap = Math.min(svcFleet.fire, fireStations + fs2)`(k6+k30,**不含 k61**)
- 警察 `cap = Math.min(svcFleet.police, policeStations + policeBoxes)`(k11+k52)

快照與面板:`flowStat384.svc` 三族**加欄不改既有欄**(T391 斷言為 `>=0`/有限性,加欄相容);
面板加 bar 與 warn 文案,消防列另加「覆蓋外 N 場」、警察列加「可出勤 N 件」。

## 驗收

1) 兩釘恆等 + 套件全綠(零模擬影響的機器證明);
2) 守衛:三組計數器在場且為 tick 區域、可出勤條件與 `updFireTrucks`/`updPoliceCars` **逐字一致**
