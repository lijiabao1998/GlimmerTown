### 為什麼守衛沒抓到

`T371b` 只驗「錨點字串能不能在 `index.html` 找到」，**不驗行號**。
所以行號可以全面過期而套件照樣全綠——文件的可信度來自一個**和內容脫鉤**的欄位。
這就是「地圖騙人」的機制本體，而 T371b 當初正是為了治這個病才立的。

## 1. 做什麼

**① 一次性重測**：每一列的行號改成**實測的錨點行**，範圍用「本錨點行 → 下一個錨點行 − 1」導出
（這個定義寫進表頭，任何人都能重算）。無法定位的死錨點單獨標出，不猜。

**② 做成可重生的**：新增 `tools/arch_map.py`
- `--check`：逐列 grep 錨點，報告「找不到」與「行號與實測不符」的列，回傳非零。
- `--fix`：把行號欄重寫成實測值。
⇒ 下一張卡改完 `index.html` 只要跑一次 `--fix`，地圖就不會再爛掉。

**③ 補一條守衛**：`test_fixde.js` 釘「ARCH 表格裡的 grep 錨點**全部**能在 `index.html` 找到」
（死錨點數 = 0）。這比 T371b 強在它掃**整張表**，不受 T371b 的列格式盲區影響。

**不做**：不補測那 4,084 行的新分節（那要逐段判斷屬於哪個子系統，是另一張卡的工作量）。
本卡只保證「表上已有的列，行號是真的」＋「以後不會再爛」。
