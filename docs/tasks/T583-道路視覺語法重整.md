## 1. 進場探針與問題定義

道路不是空白素材；現況至少已有 T146／T277／T359／T427／T572 多層疊加。本卡先盤點再落筆，
不以「全部重畫」冒充全面更新。

審計面共 **146 鍵**：

- `SPR.roadClass[0..3][0..15]`：64（巷道／支路／次幹道／主幹道）
- `SPR.roadDeco`：46（curb 16、zebra 16、lane 2、街具 12）
- `SPR.hwy[0..15]`＋`SPR.hwyBridge[0..15]`：32
- `SPR.oneway[0..3]`：4

146 是「逐鍵看過」的範圍，不是「146 鍵都必須變」的 KPI。沒有視覺缺口的鍵應留下「合格不動」理由；
已有正確語意的 T582 軌道／輕軌／架空線與 T572 街具互斥不在本卡重畫範圍。

要解的不是單一像素，而是四種結構失調：

1. 四級一般道路共用太多同色／同標線語彙，遠景不易讀出道路層級。
2. 直線有標線、彎道與路口卻突然失去視覺連續性；箭頭／斑馬線／車道線各自存在，但沒有共同秩序。
3. 高速與高速橋有路面，缺少能讀出「高速／橋面」的反光標、伸縮縫與護欄節奏。
4. 夜間已有燈具與光錐，但道路自身沒有與燈位一致的近地受光回應；不得用全路發亮的假夜圖解決。

## 3. 設計語法（由低到高，不追求滿屏細節）

1. **巷道 rc1**：最安靜、無中心線；只保留暗邊、接縫與極稀疏修補痕，不假裝多車道。
2. **支路 rc2**：單一中心虛線＋清楚路緣；端點要有收頭，轉角不塞滿斑馬線。
3. **次幹道 rc3**：雙向車道節奏、入口短標線與反光點；與支路在縮放 1 倍仍可區分。
4. **主幹道 rc4**：雙黃中心語彙／路口導流短線；中央分隔只在有足夠空間的遮罩出現，不能堵住彎道。
5. **高速 rc5**：冷色路面、雙白線、外側反光標；高速橋另有伸縮縫、護欄影與反光件。
6. **單行道**：箭頭保留四向語意，輪廓加強但不得改 `(direction + viewRot) & 3` 的旋轉公式。
7. **夜間受光**：只在真實 `drawStreetLampPick572`／橋燈成立的格產生，位置與燈具共用；無燈格必須零新增夜光。

所有加蓋均使用整數像素與現有等距軸，顏色取自既有路面／標線色系；不引入寫實貼圖或高飽和霓虹。

## 5. 驗收：先證明「畫對」，再證明「沒拆家」

### 5.1 Node／像素台架

- G1 清冊：146 鍵完整存在，尺寸／錨點不變；實際變動鍵列白名單，其餘逐鍵指紋不變。
- G2 層級：同一個直線遮罩下，rc1..rc5 的識別色／標線計數形成預期差異；不得只驗函式存在。
- G3 連續性：直線、端點、轉角、丁字、十字五類遮罩逐類真跑，標線均在菱形內且不畫到非連接邊。
- G4 方向：四張單行箭頭各有不同重心／尖端，旋轉四次回原方向。
- G5 高速橋：伸縮縫、護欄影、反光件各自有像素；陸上高速不得誤得橋墩／橋縫。
- G6 夜光：同一場景有燈格新增受光、無燈格零新增；受光中心必須由實際 lamp sprite 掛點計算。
- G7 kill-switch：`__noRoadGrammar583=true` 時 146 鍵與 T582 基線逐位元相同，且 draw-time 受光為零。
- G8 零亂數與零模擬：新增段機械掃零亂數；六哨兵逐字相同；`GV.stats()` 繪製前後逐字相同。
- G9 效能：T523 空城／300 天城均在既有紅線內；另記本卡前後同場景落筆差，不改紅線討好結果。

### 5.2 破壞性證明

至少六案，每案都要記 `exit code`、首個 FAIL／stderr；**首紅必須等於目標釘**：

1. 拿掉 rc3 的層級標線 → G2 紅。
2. 把轉角標線畫到非連接邊 → G3 紅。
3. 讓四張單行箭頭共用同一方向 → G4 紅。
4. 拔掉高速橋伸縮縫 → G5 紅。
5. 讓無燈道路也受光 → G6 紅。
6. 新增段注入一個亂數呼叫 → G8 紅。

紅源恢復後 sha256 必須回到交付位元；只看到 `exit=1` 不算，必須核對首紅。

### 5.3 真實瀏覽器

固定流程：`127.0.0.1:8126`、槽 3、清 SW／Cache、帶 cache-bust。

- 同一座道路測試城：巷道→支路→次幹道→主幹道→高速，含端點／彎道／丁字／十字／一般橋／高速橋。
- 白天＋夜間、rot 0/1/2/3、zoom 0.5/1/2/3；桌面與窄視口至少各一輪。
- 驗頁面身份、非空白、無遮罩阻塞、console 零 error；實際切日夜、旋轉與縮放後再截圖。
- 美術判準：1 倍能讀層級，2 倍能看標線秩序，0.5 倍不成噪點；夜間只有燈下有回應。
