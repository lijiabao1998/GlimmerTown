**連災害最重的城也只拿回保費的 25%**；打平需要每 500 天毀 257 戶（實測最高 64）。
這不是 AI 限制——玩家無法讓災害毀更多房子來讓保單回本（刻意縱火屬退化玩法）；
蓋好消防覆蓋的玩家理賠更少＝**玩得越好保單越虧**。而卡片上只寫四個字：「保費換理賠」。

**理賠機制本身是完整的**（順帶盤點）：隕石／龍捲風／火災燒毀三處直接理賠，
地震與煽火經起火→燒毀間接覆蓋，理賠 toast 會進通知中心。機制沒壞，是**帳不透明＋定價失衡**。

## 1. 本卡只做「不騙玩家」那一半（T530 模式）

**不動 $18/$35**——重新定價是設計值判斷（業主層級，數據在帳本調查筆記八）。
本卡讓玩家看得見真帳：

1. 兩個計數器 `insPrem535`（累計保費）／`insPaid535`（累計理賠），
   保費在 `upReg` 收費的同一個 tick 位置累加（恰一次/日）、理賠在 `insPayout` 內累加。
   **純觀測、不改任何金流計算。**
2. 保單卡片的 fx 動態化：有帳時顯示「保費換理賠｜本局已付 $P・已獲理賠 $C」，
   零帳時維持原靜態文字。
3. 存檔：可選欄位 `ins535:[prem,paid]`，**兩者皆零不落欄位**（T364b 慣例＝既有存檔 bytes 不變）；
   舊檔缺欄位容錯 0/0（鐵律9）；三處歸零（鐵律7）。

## 2. 驗收計畫
- **G1 保費**：投保跑 N 天 `insPrem535===18N`；未投保恆 0。
- **G1b 理賠**：造一次燒毀 ⇒ `insPaid535` 增加且與 `money` 增量一致。
- **G2 對帳單**：`insFx535()` 有帳時含「已付/已獲理賠」、零帳時逐字等於原靜態文字；渲染行走 ternary（原文釘）。
- **G3 存讀往返**：計數器經 save/load 保真；舊檔缺欄位＝0/0。
- **G4 零狀態位元穩定**：從未投保的存檔**不含** `ins535` 欄位。
- **G5 鐵律7 三處歸零＋零亂數＋六哨兵位元恆等**（純觀測，不碰模擬）。
- 紅源：①拿掉理賠累加（對帳單少報）→ G1b／②計數器不入存檔 → G3／③fx 退回恆靜態 → G2。
