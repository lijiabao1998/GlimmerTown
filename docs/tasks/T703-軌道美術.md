**claim**：Claude；分支 `claude/town-train-702`（延續，未另開分支）；base `eacb7ff`（v11.245）。

## 問題

T702 之後，**列車的動態**（逐節轉向、進彎減速、端點停頓折返）已達標，但**軌道本身**仍是舊素材：

| 問題 | 現況 | 應該 |
|---|---|---|
| 彎道 | 用直軌拼成 L，沒有真曲線 | 專用彎軌貼圖（內外弧對齊軌距） |
| 軌距 | 兩條細線，與車身比例不符 | 軌距 ≈ 車輪內緣，車身外擴 ≤ 0.1 格 |
| 枕木 | 稀疏、放大後像白色小棍 | 密度 ×2，顏色壓暗、與道碴同色系 |
| 道碴 | 一整片褐色帶 | 有邊緣不規則與明暗顆粒 |
| 交叉／端點 | 無專用貼圖 | 交叉段與止衝端點 |

## 做法

1. **素材**：新增 `SPR.rail703` 一組——直（4 向以旋轉覆蓋 2 向 + 斜向 2）、彎（4 種轉向）、交叉、端點止衝。尺寸對齊現有 64×32 格（2:1 等距）。
2. **繪製**：以 `t.rail` 的方向位元選貼圖；位元為 0 或不足時退回舊 `SPR.rail`（逃生路徑）。
3. **車身**：`SPR.trainLoco/trainCar` 以繪製時縮放（0.85 寬）對齊軌距，**不改原素材**（避免指紋基線大變）。
4. **閥**：`?noT703=1` 或 `window.__noT703` 時完全走舊軌道與原車寬。

## 驗收

- [ ] 直線、彎道、交叉、端點四種段在遊戲內對得上（相鄰格接縫無錯位）。
- [ ] 車輪落在鋼軌上（左右各差 ≤ 1px @ z=2）。
- [ ] `?noT703=1` 時逐位元回舊外觀。
- [ ] `test_fixde`／`verify.py` 全綠；`frame`／`fp` 綠（新素材入 ART_PINS）。
- [ ] 效能：整地圖 400 段軌道不掉幀（可量 render 時間）。

## 施工證據（第一階段：程式化改進）

**已完成（`c27c8a9` ＋ 本 PR）**

- 鋼軌三層加厚：軌頭亮、軌腰暗、外側陰影（原本只有 1px 線）
- 枕木密度：每 2 步 → 每 1.5 步
- 軌距（半）3.4 → 4.4、枕木半長 5.2 → 6.2
- 車身繪製縮 0.85 並以錨點置中，讓車輪落在鋼軌上
- **轉角貝茲弧**：`railTrack` 內偵測「相鄰兩向」的 bitmask（xor 3/6/9/12），以二次貝茲取代兩段直軌硬拼；沿弧取樣 20 段畫道碴、枕木、雙鋼軌

**已知限制（誠實記錄）**

1. 弧只有約 10px（32px 格子內），縮小視角下與直軌差異有限
2. 沒有專用「彎軌／交叉／端點」貼圖——TheoTown 那些是**手繪素材**，本 PR 是程式近似
3. 車身 32px vs 軌距 8.8px 仍約 3.6 倍，比鐵道實車比例（約 3 倍）略寬

**後續（下一張卡，若業主要求達 TheoTown 級）**

- 手繪 4 段 × 4 向軌道貼圖（直／彎／交叉／端點）
- 列車四向 × 4 幀 × 日夜 sprite 重畫（現有 32×22 偏小）
- 或採「繪製解析度加倍再縮半」的程序化路線（不需美術資產）
