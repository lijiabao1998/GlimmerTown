# T402 — 視覺層消耗模擬亂數:全面盤點與收斂評估(不施工=評估文檔)

發現於農業美術三期 R5 偵查(2026-08-02):幀驅動的視覺/載具層在消耗種子化模擬亂數
`R()`/`ri()`。這是**鐵律2 精神的既有系統性違背**,但屬遠古遺留(T15/T77 時代),
後期卡(T155/T289/T361 等)已刻意迴避新增消耗,唯獨舊債未清。

## 為什麼至今沒炸(三個真相)

1. **headless 套件永不跑幀路徑**:兩釘(4153/4550)與 12 種子回歸全是 tick-only 真值,
   視覺層消不消耗亂數它們都不會察覺。守衛體系對此天然盲區。
2. **雙埠像素協定是同步執行**:`newWorldSeeded(7);step(30);forceDraw()` 單線程一氣呵成,
   中間零 rAF 幀 ⇒ 零視覺消耗 ⇒ 雜湊穩定。協定僥倖繞過了問題。
3. **玩家看不見**:單機城建,軌跡不可重現不影響體驗——但這正是溫水煮青蛙之處。

## 實際後果

- **真瀏覽器同種子軌跡不可重現**:載具按幀時序消耗 R(),插在每日 tick 之間的位置
  隨機器/幀率而異 ⇒ 同種子兩次遊玩,模擬軌跡分岔。
- **headless 驗證的結論不能外推到真遊戲**:T394a 平衡數據、12 種子回歸、兩釘,
  嚴格說只對「無渲染宇宙」成立。
- 任何未來的重播/挑戰模式/種子分享功能都被此堵死。

## 修復方向(若業主核准,獨立施工卡)

**把上表 18 處 `ri(...)` 全換成視覺層專用亂數**(`Math.random` 系,同 T159 慣例)。
收益巨大:視覺層歸零消耗後,**瀏覽器 tick 消耗序列與 headless 完全一致 ⇒ 兩釘與
12 種子數字在真遊戲裡成立**,同種子遊玩可重現,重播/種子分享從此可能。

**風險與前置(不可輕率動手的原因)**:
1. `GV.advanceN` 走幀路徑——**先查明測試套件是否有依賴種子化載具行為的斷言**
   (如「seed X 第 N 幀車數/位置」),有則逐條改造。
2. 換源後車流視覺分布會變(但每車已有 streetHash 決定性外觀,變的只是位置時序)。
3. 一次全換,不可分批——分批=消耗序列半新半舊,狀態更混亂。
4. 驗收:兩釘照常(headless 不變);新增「瀏覽器軌跡=headless 軌跡」驗證
   (真瀏覽器 newWorldSeeded+自然跑幀 400 天,pop 必須===4153——修復前這個測試會紅,
   修復後綠,**本身就是最強的紅源驗明**)。
