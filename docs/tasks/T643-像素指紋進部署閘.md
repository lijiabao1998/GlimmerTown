## 起因

- `tools/fp_snapshot.py` 只認 Windows 的 Chrome，不在任何 CI 裡。標準 3.2「既有像素指紋零變動」對雲端寫入者（GPT）沒有機器把關。
- T549 G2b 要求 `SPR_PINS.__meta.ver` 等於 `GAME_VER`。實況是：v11.211 起 11 次改動 SPR_PINS，除了 ver 什麼都沒變；其中 T635 的 3 次多了一個 fp_snapshot 從不寫的結尾換行，可見是為了過 G2b 手改的。它守的是字串，不是像素。
- SPR_PINS 是 53KB 的單行檔，任兩個要改它的 PR 必定整檔衝突。
- scene602 的像素段比的是 v11.210 凍結夾具：1580 鍵不准變，外加恰好 6 個 art602。升為部署閘後，任何改清冊的美術都會紅，等於又一個寫死的錨點。

## 做什麼

1. `tools/fp_snapshot.py`：
   - Chrome 依序找 `CHROME_PATH`、Windows 兩條路徑、`/usr/bin/google-chrome`、`/usr/bin/chromium`；Linux 加 `--no-sandbox`。
   - Chrome 死掉時立刻失敗並附原因（不再空等 300 秒）。
   - `--check` 在基線缺漏或無法解析時判紅（原本放行）。
   - assert 換成明確的 exit，`python -O` 不會把守衛拿掉。
   - 輸出改成一鍵一行、鍵排序、結尾換行；`__meta` 只留 `count`。
   - 新增 `--out PATH`；寫回 `docs/SPR_PINS.json` 要明講 `--write`，所以 Windows 上跑只是預覽。
2. `docs/SPR_PINS.json` 換新排版，內容逐鍵相等（解析後比對）。
3. test_fixde 退役 T549 G2b 和它的 GAME_VER 前置（2 條 PASS；G2a／G2c／G2d／G2e 保留）。
4. 新 `tools/fp_diff.py`（純 Python，不開瀏覽器）：
   - head 的 SPR_PINS 必須在、可解析、count 自洽，否則判紅。
   - 實算的指紋必須逐鍵等於 head 的檔案。
   - 比 base 與 head 的 SPR_PINS，依 `/` 前的家族名列出新增／變更／移除的家族。家族名逐字比對：42 個家族名是別的家族名的前綴，例如 park／parkA。
   - 碰到的家族必須是卡頭 `families` 的子集；碰到任何家族時 `owner_ok` 不得為空。
   - 純 revert 免家族與 owner_ok 檢查，等式照查。
5. 新 CI `fp` job（full 道）：在跑機上實算指紋，交給 fp_diff 判；rebake 結果做成附件保留 90 天。
6. scene602 拿掉讀凍結夾具的三條斷言：1580 鍵不變、恰好 6 個 art602、夾具 1580 鍵。保留「候選與 Chromium 相符」和其餘部分（舊存檔、手機 UI、遮擋）。夾具檔不刪：還有別的工具在讀。
7. 標準 3.2／6.2、AGENTS、COLLAB、ARCH §10.6 改寫：
   - CI 的 fp 是正本，Windows 上的 fp_snapshot 只是預覽；
   - 改圖的 PR 只准原封提交那一輪 CI 的 rebake 附件，不准手改；
   - SPR_PINS 衝突時取 main 的版本，等 CI 重烘。

## 和 T639 原計畫不同的地方（照實寫，放寬判準寫在卡面）

- **美術禁令延續到 T643b，不在本卡打開。** T639 寫「T643 落地之前，不開改 sprAtlas356 家族的美術卡」，暗示本卡落地就能開。實地盤點發現，scene602 之外還有三把凍結的 SPR 鎖：scene603.js:297／:307（1586 鍵、pinDiff 空、無新鍵）、release635.cjs:64（1586 鍵、逐鍵相等），可能還有 scene634.cjs:117。另外 scene603 還被雜湊與字面量焊死在 release-correctness 與 native-portability 診斷裡。這些鎖要另開 T643b 一起解，同時給 gpt/ 開 SPR_PINS 例外（T641 卡上的承諾，順延到 T643b）。
- **families 用「子集」，不用 T639 寫的「相等」。** T603／T634／T635／T638 的美術不在 SPR 清冊裡，fp 看不到。卡頭宣告了這些家族、fp 卻碰不到，不能因此判紅；只宣告不碰時發警告。這是對 T639 文字的放寬。
- **碰到家族就要 owner_ok。** 這不是新政策：T639 寫明「美術改動要業主同意的要求不變」，本卡只是讓機器第一次去查它。
- **釘版 Chromium 先量再定。** 主線 CI 現在所有像素 job 都用跑機內建的 google-chrome；playwright 只裝了驅動，沒裝瀏覽器。換成 Playwright 的 Chromium 等於多一個正本，所以先在同一輪跑兩個瀏覽器，逐鍵比較：
  - 跟倉庫 SPR_PINS 差 0 鍵、兩次恆等，才用它；
  - 有差就停手，fp 用跑機 google-chrome，釘版順延 T643b。
- **「fp 首紅」不會是唯一的紅。** 改一個像素時，scene603 的候選比對也會在 browser job 紅（T640 卡面已記過）。紅源寫成「fp 紅並列出鍵、browser 連帶紅」。

## 先量再上

第一輪 fp job 設 `continue-on-error`，不進 gate。量四件事：
1. 跑機上一次 fp_snapshot 要多久；
2. 釘版 Chromium、跑機 google-chrome、倉庫 SPR_PINS 三者逐鍵是否相等，跑兩次是否恆等；
3. 有沒有「有 nightCity 卻沒有 night」的鍵（T581 G4 把 index [1] 當夜間 CRC）；
4. Playwright 的 Chromium 在 ubuntu-24.04 加 `--no-sandbox` 能否啟動。

全過才轉成擋門；有差就停手回報，不登記豁免、不自動重烘。
