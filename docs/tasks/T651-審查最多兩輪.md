# T651 Codex 審查最多兩輪：之後的新意見登記後續、不再自己追，卡面要寫「範圍外」

**發卡／施工**：Claude。業主 2026-10-15 選「1」收尾 T648 後要求：「你『最多兩輪』正式寫進 AGENTS.md 和標準，讓 GPT 也照做」。
**claim**：Claude；分支 `claude/town-review-rounds-651`。

## 起因

T642 定的規矩是：合併前 Codex 必須審過最新那一版、P0／P1 必須回覆；但沒寫「幾輪後停」。每修一次就是新的一版 → 重審 → 又冒新意見。T647（#36）被連提 5 條 P2；T648（#37）三輪共 7 條 P1，每輪一次完整 CI（約 25 分）。業主在外面只看到一直在跑，兩次來問「為什麼這麼長」「無限迭代還是啥」。

原因有三：
- 流程沒有停止條件。
- Codex 每輪都把整份改動當新的重看，不知道卡的範圍；它的意見多半是「範圍還能再擴大」，卻一樣標成 P1。
- 卡面沒先寫「範圍外」，施工者（我）每條都當成必修。規矩其實允許 P1 只回一行理由，是施工者自己沒停。

## 做什麼

1. `AGENTS.md`「最常被忘的幾條」加一條「Codex 審查最多兩輪」：
   - 同一個 PR 修完兩輪後新冒的意見：P2 直接登記 REVIEW-FINDINGS；P1 先判斷——是這張卡承諾的東西壞了才修，只是擴大範圍就在 PR 上一行回覆理由、登記後續卡號；
   - 還不收斂就停手，把「收尾合併／再修／暫停」交業主；
   - 等 CI 超過十分鐘就主動告訴業主在等什麼、大概多久。
2. `docs/迭代不改壞標準.md`：
   - §1.3 卡面欄位加「範圍外」；
   - §7 加一條審查兩輪的停手規則；
   - §8 自檢清單加一條。
3. `docs/REVIEW-FINDINGS.md`：補登 #37 第三輪兩條 P1（懸停淡出幀、存檔夾具從 base 讀）→ T648b。

## Codex #38（第一輪）

- P1「第三輪以後的 P0 也能回覆了事、收尾合併」：照改。P0 不受兩輪限制，任何一輪都必須修好，修不了就暫停；AGENTS 與標準 §7、§8 都寫明。`--premerge` 只看 P0／P1 有沒有回覆，所以這條靠自律，不改工具（範圍外，見下）。

## Codex #38（第二輪，本卡最後一輪）

- P1「範圍外會被拿來豁免本次改動造成的回歸」：照改。範圍外只豁免「再擴大涵蓋」的建議；本次改動把原本好的東西改壞，一律修好或暫停。AGENTS、標準 §1.3 與 §7 都寫明。
- 依本卡規則，這是 #38 的第二輪修改；之後重審若再有新意見，P0 照修，P1／P2 照規則登記或交業主。
