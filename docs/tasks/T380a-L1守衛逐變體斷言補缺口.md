## 一句話

T380 的 L1 守衛用 regex 抓 `fillRect(ax±N,ay±N,w,h)`，**x 與 y 都必須是字面量**；
而 v5／v7 的招牌是迴圈算座標（`ax-24+i*12`、`ay-54+r*3`），**L1 一個都看不到**。
self-check 是「總數 ≥24」而非逐變體，所以兩個變體歸零仍然過。

## 要改什麼（兩處）

### 1. `test_fixde.js` — 把 self-check 改成逐變體

現況（總數）：

```js
assert(sigTotal >= 24, 'T380 L1：建築(//sig)矩形總數應 ≥24（每變體至少 1 招牌），實得 ' + sigTotal);
```

改成逐變體，並在訊息裡列出歸零的變體：

```js
const blind = perSig.map((n, v) => n === 0 ? 'v' + v : null).filter(Boolean);
assert(blind.length === 0,
  'T380a L1：每個變體都必須有 ≥1 個 L1 可解析的 //sig 矩形（x/y 皆字面量），' +
  '否則該變體的招牌不受守衛保護。歸零：' + blind.join(',') +
  '（修法：給該變體加一個字面座標的基床矩形，見 v0 的 //sig 基床）');
```

（`perSig` 就是 L1 訊息裡已經在算的那個逐變體矩形數，直接沿用，不要另寫一份幾何。）

### 2. `index.html` — v5／v7 各加一個字面座標的基床矩形

照 v0 的既有寫法（v0 已經有）：

```js
sg.fillStyle='#5a6a34';sg.fillRect(ax-28,ay-54,52,10); //sig 基床
```

v5（果箱列）與 v7（草莓壟）各補一個能罩住自己招牌的基床，**座標必須是 `ax±N,ay±N` 字面量**。
基床本身也是美術（v0/v10 的基床看起來就是田床/水田面），所以這不是為測試而加的死像素。

★3c／★3d 是刻意加的「應該綠」案 —— 只證明「會咬」不夠，還要證明它不是亂咬。

**我第一次的 ★3b 注入是錯的**：`F22` 有 16 筆，我只替換了第一筆，於是只有 v0 變大，
而 v0 的哨兵在 y94~103 不在 y104 ⇒ 綠。我一度以為是守衛缺口，查了才發現是注入寫錯。
重做（16 筆全換）後才看出真正的問題是 `t<=0` 的 off-by-one。

### 殘留限制（誠實邊界）

L1 的 regex 需 x/y **皆**字面量。只移動「迴圈座標畫的那部分」而不動哨兵，守衛看不到（案 4 實測綠）。
判斷不追：真實回歸是**田參數變大**（T378 就是），而哨兵擺在招牌最下緣、離田上緣 4px，
是田一長大最先被吃到的東西 —— ★3／★3b 證明這條路已封。
「只把某變體招牌的迴圈部分往下搬」不是事故形狀，是刻意編輯。
要徹底封需要求所有 `//sig` 的 y 為字面量 ⇒ 得改寫 v7／v12-v15 多個迴圈，代價不成比例。
