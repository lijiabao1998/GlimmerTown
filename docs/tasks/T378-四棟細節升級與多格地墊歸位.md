## ⚠️ 全卡最重要的一條：三條亂數流的位元契約

`buildSprites`（1309-8141）內共存三條流，**全部是單一順序流，插入或刪除一次消耗，
其後同流全部消費者逐位元漂移**（鐵律 2）：

| 流 | 定義 | 消費者 | 一次消耗量 |
|---|---|---|---|
| 共用 `rand` | `mulberry32(20260712)`（1316） | 夜窗 `windows()`（1139：`if(ng&&rand()<litP)` 每窗 1 抽）＋手寫窗迴圈（如 k6 的 1781） | 每窗 1 抽 |
| `spriteTexRand` | 1175 定義、1310 重設 | **全檔僅 9 個 `speck` 消費點**；`plate()` 每呼叫固定吃 **78 抽**（26 點×3 抽：yy/xx/選色） | 78 抽/plate |
| 世界流 `R` | 替身接管、8140 還原 | 精靈區不得碰 | — |

**殘酷事實（實測）**：純流位移的 mutant（在 k63 段插 3 個 `rand()`）跑 `test_fixde.js` = **3080 全綠**。
Node 端對流位移**失明**，唯一的網是 atlas 指紋人工比對。所以本卡的紀律是**靠構造保證零位移**：

1. 新增繪製一律零亂數（相位／`(x+y)&1` 棋盤／局部 LCG，先例 1822 `wrand`、4106）。
2. `plate()` → 全尺寸配方時，**`speck` 的 n 必須保持 26**（消耗=3n 與 hw 無關 ⇒ 78 抽不變）。
3. 不得增刪任何 `plate()` 呼叫、不得改任何既有 `windows()` 的幾何參數
   （hw/h/w/ht/gx/gy 決定窗數=決定抽數；實測 k7 的 hw 28→26 就從 6 抽變 5 抽，靜默漂移零警報）。

## B 部：地墊歸位（先寫 B，因為它定義了配方）

### 病灶

舊代精靈（大約 k19~k51 世代）用 `plate()` 畫地墊 —— `plate` 內部寫死 `hw=32`（1 格）：

```js
function plate(g,ax,ay,col){            // 1178
  dia(g,ax,ay-32,32,col);
  speck(g,ax,ay-32,32,[shade(col,-10),shade(col,8)],26,spriteTexRand);
  diaEdge(g,6,shade(col,-20),ax,ay-32,32);
  …
```

新代（k53 起）都用 `dia(g,ax,ay-32*sz,32*sz)` 正確覆蓋。斷層一覽（實測）：

| 病例 | sz | 覆蓋 | 位置 |
|---|---|---|---|
| **k19 機場** | 4×4 | **1/16** | plate 在 4337 |
| k22 農場 ×16 變體 | 2×2 | 1/4 | 4429-4546 ＋ T274 的 7276/7304/7324/7343 |
| k23 牧場 ×5 變體 | 2×2 | 1/4 | 4639/4645/4653 ＋ **T273 尾端 7232/7252（有特殊守衛，見下）** |
| k24 地標 ×3、k20 停車場、k31 監獄、k35-k47 文化線、k41、k45… | 2/3 | 1/4~1/9 | 各自區塊 |
| **k32 大學（hero 版）** | 3×3 | 1/9 | **5930（只准動 hero 塊這一行）** |
| **k42 市政廳（hero 版）** | 2×2 | 1/4 | **5937（同上）** |
| k48 綜合醫院 | 3×3 | 1/9 | 5600 |
| **k33/k34 摩天樓 ×4 鍵** | 2×2 | 1/4 | 5241（修完塔樓終於像真的佔 2×2） |

**名單以審計腳本為準，不以上表為準**（我自己的粗掃就誤判過 k68 —— 它其實是正確的
`dia( g, ax, ay-64, 64,…)`，只是寫法帶空格）。守衛 K4 會把審計寫成程式（見驗收）。

### 通用配方（一行換三行，零位移）

```js
// 原：plate(g,ax,ay,COL);
// 換成（hw = 32*sz；speck n 必須保持 26 ⇒ spriteTexRand 恰 78 抽，與 plate 逐位相同）：
dia(g,ax,ay-32*sz,32*sz,COL);
speck(g,ax,ay-32*sz,32*sz,[shade(COL,-10),shade(COL,8)],26,spriteTexRand);
diaEdge(g,6,shade(COL,-20),ax,ay-32*sz,32*sz);
```

（`sz` 手寫成字面量 64/96/128，不要引用 MSZ —— 精靈建構期拿不到它。）

三件已預先驗證、不必再擔心的事：
- **T291 clipBase 零裁切**：裁切判準是嚴格不等式 `|px-ax|>2*(ay-py)`，全尺寸地墊的每一列
  最遠像素**恰好落在界上**＝全數存活（實算 0 像素被裁）。
- **畫布餘裕足夠**：2×2 需 x∈[4,131]（畫布 136）、3×3 [8,199]（208）、4×4 [8,263]（272）、
  k33/34 塔 136×230 —— 全部裝得下。
- **T345 色環不用動**：色環讀 SZB 表（本來就是全腳印尺寸），今天就已經畫滿整個腳印下緣；
  地墊放大後兩者自動吻合。
