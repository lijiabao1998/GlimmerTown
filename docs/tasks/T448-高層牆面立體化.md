## 0. 這張卡為什麼存在

「更豐富的立體建築」在這個檔案裡有一個現成的、只用過一次的答案：
`boxUnit`（T425I，`index.html:1639`）的**五級色階牆面＋稜線體系＋斜邊節奏點**——
T425H 六技法、T441 剛把受光方向對齊全城（右受光）、零亂數（純 `shade()` 決定性）。
**它目前只有 `bld/65_1_0` 購物中心一棟在用。**

其餘 153 個程序化建築的主體牆面全是 `isoBox` 的**平面兩色**（左一色右一色）。
TheoTown 高樓的立體感很大一部分來自牆面的縱向明暗漸層——正是 boxUnit 已內建的東西。

**規模控制**：只動 **lv3 塔樓**（k1/k2/k3 各 12 變體＝36 基鍵＋財富衍生）。
lv3 是天際線的主角、離鏡頭最遠、最吃立體感；lv1-2 低層维持現狀（T449 另行處理屋頂）。

## 2. 事前已查的風險

- **兩釘**：純視覺（建圖產物），模擬零觸碰 ⇒ 位元恆等必須成立。
- **T383c 亂數 token 快照**：改動在 `buildSprites` 掃描範圍內，但**零 RNG token 增減**（boxUnit 純 shade）⇒ 快照應不動；若動，按 ARCH 記載的重釘程序處理並寫卡面。
- **T441 G5**：boxUnit 函式體不得有 RNG——本卡不動 boxUnit 本身，只加呼叫。
- **T446 G1**：不新增 `SPR.bld` 鍵 ⇒ parity 清單不動。
- **`art_wall` 量測**：主體 via 分佈會變（36 鍵改記 `boxUnit`）——量具是報告不是釘，如實記錄新分佈。
- **顏色語義**：同參數下 boxUnit 的左右面色基與 isoBox 互換（左=wl[0] 暗階、右=wl[1] 亮階），
  整體仍右受光；**觀感以樣張為準**，不合適就在施工中調參數順序（cL/cR 對調即回 isoBox 色基）。
