## 1. 手法：worker_threads 並行，主執行緒原位重放

1. 檔頭：非主執行緒時靜音 `console.log/error`（**否則 worker 的 PASS 行會流進 stdout、灌大 PASS 棘輪＝作弊**）。
2. helper 段尾：主執行緒立刻 `t578Spawn` 三個 worker；每個 worker 重跑同一份 bootstrap（lines 1..eval(js)＋helper），
   從 `__filename` 依 `/* @@T578:BEGIN name */…/* @@T578:END name */` 標記**抽出區塊原文**用 `eval` 執行——
   同一份程式碼，不複製；worker 內的 `assert` 是**錄音機**（記 `[ok,msg]`，首紅即停），完成後 `postMessage`＋`Atomics.notify`。
3. 原斷言位置：主執行緒 `t578Replay(name)`——`Atomics.wait` 阻塞到 worker 完成、`receiveMessageOnPort` 取回錄音、
   **逐筆呼叫真的 `assert(ok,msg)`**＝PASS 行文字、順序、數量、首紅即停全部與原本逐字相同。
4. 逃生閥 `T578_INLINE=1`：三個區塊在原位 inline 跑（同一段原文），供等值證明與除錯。

**原型已證等值**：T341 區塊 inline 與 worker 各跑一次，`{towerDay:119, megaDay:1159, mroot:[20,50], mk341:105,
pop:3208, money:215830, day:1161}` **逐項相等**（IDENTICAL=true），各 ~90s。

**原型踩到並記入設計的坑**：遊戲 bootstrap 內有 `setInterval`（250ms rAF 後備、25s 自動存檔），
worker 事件迴圈永不自然結束——主執行緒**不可等 `exit`**，收到 `message` 後主動 `terminate()`。

預估：主執行緒 327−183≈144s；最長 worker（T341）≈106s 與主執行緒重疊；**約 160s**，滿載 3.4× 也在 900s 內。
