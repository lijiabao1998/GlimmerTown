# T406 — 天際線梯度(TheoTown 觀感對標 第二刀)

T405 砍掉徽記後,兩張圖剩下的結構差異是:TheoTown 有**市中心高塔叢向外遞減**的天際線,
我們的城**高矮混雜、看不出核心**。

## 偵查定案(wf_abea8b7c D 組)

- 住宅/商業/工業各 3 級,同一級的 **12 個變體樓高有實質差距**
  (住宅 lv3:68~84px、商業 lv3:76~84px、工業 lv3:60~68px)。
- **但變體 `v` 是純 `ri(12)` 亂數,與位置零相關**——同一街廓相鄰兩棟 lv3 的高低差純屬擲骰,
  所以無論城市怎麼長,天際線永遠是白噪音。
- 地價 `LAND` 公式裡**沒有任何「離市中心距離」項**(上限 192、實測 ~176、空圖恆 128),
  只被拿去調升級機率,**沒有任何一條繪製路徑讀它**。
- `den`(道路等級密度 1-5)同樣算好了沒人讀。

## 設計:讓 `v` 由「中心性」決定,而非擲骰

1. **樓高排名表 VRANK406**:在 `tasks` 展開迴圈**內**順手記錄 `d.h+d.hw`(=isoBox 視覺高),
   於同一份 task 清單產生 ⇒ 與實際建造的 sprite 同源、美術改動自動跟隨、**永不漂移**。
   排序後得每個 `(k,lv)` 的「由矮到高」變體序列。
2. **中心性評分**(決定性,零亂數):
   `score = 0.62×鄰域建築密度(半徑3) + 0.26×地價 + 0.12×決定性抖動(streetHash)`
   ——密度是真正的市中心訊號(地價動態範圍只有 0~+0.375,單用太弱);抖動避免機械感。
3. **鐵律2 保全**:`ri(12)` **照樣呼叫**(當作 `pickV406` 的參數求值,消耗次數與順序逐位不變),
   只是回傳值被覆寫。任一路徑失敗即回退該 `ri(12)` 值。
4. **兩釘保全**:`v` 對 k1/2/3 **只被繪製/倒影/煙點掛點/存檔序列化讀取**(已逐點核對),
   不進 POPS/稅收/需求任何公式 ⇒ pop/money/happy 逐位不變。

## 紅線

- 亂數消耗次數與順序零位移(鐵律2);兩釘 4153/4550 恆等。
- 不改 DRAFTS 幾何、不改 sprite 像素、不改存檔欄位。
- 排名表必須在 tasks 迴圈內產生(不得另抄一份高度表)。
- 排名表殘缺(非 12 項)時必須回退擲骰值,不得拋錯。

## 驗收

1) 守衛:排名表在 tasks 迴圈內建立+排序正確性(真跑算術驗高度單調)+`ri(12)` 仍在兩個寫入點
   +picker 零亂數+殘表回退;
2) **梯度實證**:AI 城跑 260 天後,取所有 lv3 住宅,算「鄰域密度前 25%」與「後 25%」兩組的
   平均樓高,前者必須顯著高於後者(白噪音下應無差異);
3) 破壞性:picker 拆掉→紅;`ri(12)` 換成常數→紅;排序反向→梯度斷言紅;
4) 套件全綠 + 兩釘恆等;
5) 樣張:同城同視角,T405 之後 vs T406 之後的天際線對照。
