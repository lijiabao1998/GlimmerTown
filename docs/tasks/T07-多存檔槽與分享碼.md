# T07 多存檔槽＋匯出/匯入分享碼
版本：v1.2 ｜ 難度：★★★ ｜ 前置：T11 ｜ 建議模型：Opus

## 目標
3 個存檔槽（可存/讀/看概要）＋把存檔匯出成可複製的分享碼、從分享碼匯入。手機備份/換機神器。

## 允許觸碰
第 11 節 save/load（鍵名參數化）；第 10 節 💾 按鈕改開槽位面板＋新增面板函數；第 13 節啟動段（繼續按鈕、舊檔遷移）。

## 行為規格（實作方式由你設計，但行為必須完全符合）
1. 槽位鍵：`SAVEKEY+'.s1' / '.s2' / '.s3'`；目前槽記在 `SAVEKEY+'.slot'`（預設 1）。
2. 舊單一鍵 `SAVEKEY` 若存在且 s1 為空：啟動時自動搬到 s1 並刪除舊鍵（一次性遷移）。
3. `save()` 永遠寫目前槽；25 秒自動存檔與 visibilitychange 沿用，不改節奏。
4. 點 💾 → 面板（重用 #infoBody）顯示三個槽：有檔顯示「槽n｜鎮名｜人口 x｜第 y 天」，空槽顯示「槽n｜（空）」。每槽兩個操作：【存到此】【讀取】（空槽只有【存到此】）。操作後 toast 回饋並更新目前槽。
5. 面板底部兩個操作：【匯出分享碼】＝目前槽 JSON → `btoa(unescape(encodeURIComponent(json)))`，優先 `navigator.clipboard.writeText`（成功 toast「已複製」），失敗則 `prompt('複製此分享碼',code)`；【匯入分享碼】＝`prompt()` 貼入 → `decodeURIComponent(escape(atob(code)))` → JSON.parse → 驗證 `v===1 && ter.length===N*N`，通過則寫入目前槽並立即讀取，失敗 toast 錯誤，**絕不拋未捕獲異常**。
6. 開始畫面「繼續上次的小鎮」：讀目前槽（`.slot` 記錄的）；判斷有無存檔改為「任一槽有檔」。
7. `load()` 改為可讀指定槽（無參數＝目前槽），讀取後行為與現有完全一致（recalcAllMasks/computeFoam/townName/title 等）。

## 硬性不變量
- 讀檔任何異常 → 回傳 false → 不崩潰；GV 不刪；存檔 JSON 格式本身零變更（只是換了存放的鍵）。
- 面板按鈕事件不要用內聯 onclick 字串（CSP 風險），用 addEventListener 或事件委派。
- 只准動「允許觸碰」列的三個區域；面板重用 #info 容器與現有 .row 樣式，不新增 CSS。

## 本卡驗收（Console＋UI）
1. 舊檔遷移：先確保 `localStorage['glimmerville.v1']` 有值（可先手動 setItem 舊格式），重新整理 → 值出現在 `.s1`、舊鍵消失。
2. 💾 面板：三槽概要正確；存到槽 2 → `.s2` 有值、`.slot`=2；讀取槽 1 → 城市切換、`.slot`=1。
3. 匯出 → 得到分享碼字串；清空槽 3 → 匯入該碼（先切到槽 3）→ 城市一致（用 GV.stats() 對比 buildings/pop/day）。
4. 亂輸入「abc」匯入 → toast 錯誤、遊戲不崩。
5. 重新整理 → 繼續 → 讀的是 `.slot` 指的槽。
6. VERIFY.md 全套（存讀檔項用新槽位驗）。
