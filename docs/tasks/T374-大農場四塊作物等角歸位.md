## 問題（已實測，兩組獨立計算交叉驗證）

大農場 `SPR.bld['53_1_0']`（`index.html:4547-4572`）的四塊作物，全部是**軸對齊 `fillRect` 矩形**畫在等角菱形地面上：

```js

g.fillStyle='#3f7a34';g.fillRect(ax-52,ay-164,56,30);                     // 玉米田 L4555
g.fillStyle='#6b4a30';g.fillRect(ax+18,ay-148,52,28);                     // 菜畦   L4557
```

腳印菱形：`ax=164, ay=242, sz=5` ⇒ 中心 `(164,162)`、半寬 `160`、半高 `80`。
（`L4549` 自畫的地基 `dia(g,164,82,160)` 與此完全吻合，地基本身沒問題。）

實測結果（解析法：逐單位像素對菱形四條半平面做 Sutherland–Hodgman 裁剪＋鞋帶面積，全程有理數；

## 目標

四塊作物各自改成**一塊 2:1 等角平行四邊形田**（＝地面上的矩形地塊），躺在地基菱形內，
犁溝／作物行沿等角軸走，不是水平條紋。

### 既有正解可抄（手法，不是呼叫）

| 手法 | 位置 | 要點 |
|---|---|---|
| 菱形掃描線 | `index.html:7368-7383` `field()` | `rh = Math.floor(hw*(1-Math.abs(yy)/hh))`，逐列 `for(xx=-rh..rh)`；中心是 `(ax, ay-16)` |
| 等角犁溝相位 | 同上 | `ph = (((xx-2*yy)%6)+6)%6`，三色分 `ph<1` 溝底／`ph<4` 土面／其餘亮脊。`xx-2*yy` 沿螢幕向量 (2,1) 恆定 ⇒ 條紋自動是等角直線。另一條軸用 `xx+2*yy` |
| 等角格網植株 | `index.html:7407-7416` `plantGrid()` | 雙基向量 `dx=c*3+r*5, dy=c*2-r*2`，配界內守衛 `|dx|/(hw-2)+|dy|/(hh-1)>0.96 → continue` |
| 小貼片手寫 2:1 | `index.html:3851-3854`（T355 花圃） | 每往下一列半寬變 2px：`w2 = 9-Math.abs(dy2)*2`，上半亮下半暗 |
| 等角軸帶狀 | `index.html:1058-1112` `railTrack()` | 沿軸 `(±2,±1)`，橫向用**另一條等角軸**而非螢幕垂直（T344a 血淚註解在 1050-1057） |

### 建議佈局（**起點，不是規定**）

我已用等角格座標搜過並逐項驗證：四塊皆在界內（L1max = 0.950）、皆避開建築與 T279 田、四塊互不重疊。

等角格座標定義（`cy = ay - 16*5 = 162`）：

```
a = (y-162)/2 + (x-164)/4
b = (y-162)/2 - (x-164)/4
逆變換：x = 164 + 2*(a-b),  y = 162 + (a+b)
```

在 (a,b) 空間中，**5×5 腳印菱形恰好是 `max(|a|,|b|) <= 40` 的正方形**（每格 8 單位 × 5 格），
而**畫布上的等角平行四邊形恰好是 (a,b) 空間的軸對齊矩形**。

|---|---|---|---|---|
| 麥田（後方左） | a −38..−27, b −29..−6 | (146,95) (168,106) (122,129) (100,118) | 1.38×2.88 格 | 0.950 |

| 果園（右翼） | a 22..38, b −38..−22 | (284,146) (316,162) (284,178) (252,162) | 2.00×2.00 格 | 0.950 |

## 不變量

1. **界內**：四塊田的**每一個上色像素**都滿足 `|x-164|/160 + |y-162|/80 <= 1.0`。
   （四頂點在內不等於整塊在內；但對等角平行四邊形，四頂點在內⇒整塊在內，因為菱形是凸的。）
2. **等角**：每塊田在 (a,b) 格座標下是**軸對齊矩形** ⇒ a 恰好兩個相異值、b 恰好兩個相異值。
   軸對齊 `fillRect` 轉進去會得到 4 個相異 a、4 個相異 b，直接紅。
3. **非退化**：每塊田在 a、b 兩方向的邊長都 ≥ 6 單位（0.75 格），不得縮成線或點。
4. **互不重疊**：四塊在 (a,b) 空間的包圍盒兩兩分離。
5. **零亂數**：`spriteTexRand` 消耗次數與改動前完全相同（`L4550` 那次不變，作物區零次）。
6. **色票不變**：改動後 `L4547-4572` 出現的 hex 集合 ⊆ 改動前的集合。
7. **PASS 只增不減**：2897 → 2897 + 新守衛數。

## 驗收清單

### 1. 守衛（寫進 `test_fixde.js`，新增；不得刪改既有斷言）

樣板抄 **T355 k112**（`test_fixde.js:430-480`）—— 它就是「從原始碼解析座標再自行計算幾何」這一路的標準寫法。
**三段式，一段都不能少**：正則抓字面量 → **先斷言抓到幾個** → 再逐個算幾何。

中間那步是整個設計的命門。`test_fixde.js:463` 的 `assert(ells112.length >= 4, ...)` 沒有的話，
正則抓不到東西時 for 迴圈跑 0 次、斷言全部空過（vacuous truth），守衛就變成純綠燈裝飾。
T355 在 448／455／463／473 四處都重複了這個動作，T353 的執行期守衛（`test_fixde.js:419`）
也用 `aud.pairs > 0` 做同一件事。**你的守衛必須通得過「把作物那幾行整段刪掉，測試要紅」這個檢驗。**

至少要有下列四咬，缺一不可：

- **咬法一 — 格座標矩形性（最咬得住）**：解析出四塊的頂點，用上面的 `toCell` 轉到 (a,b)，
  斷言 `max(|a|,|b|) <= 40`、a 集合大小 `=== 2`、b 集合大小 `=== 2`、邊長 `>= 6`。
- **咬法二 — 等角斜率**：每條邊 `|dx| === 2*|dy|` 且 `dy !== 0`。`dy !== 0` 就是「不能是 fillRect 換皮」的判準。
- **咬法三 — 面積上下界＋互不重疊**：鞋帶公式算面積，單塊給上下界（只有下界則一塊撐爆整個菱形也過，
  只有上界則縮成一點也過），四塊合計佔菱形的比例給區間，再做 (a,b) 包圍盒兩兩分離。
- **咬法四 — 沙箱重放（若你選了掃描線寫法，這條變成必須）**：掃描線的實際座標根本不在原始碼裡，
  只有迴圈參數在，字面量解析從根本失效。此時用 `vm.runInNewContext` 造假 ctx，
  錄下每一次 `fillRect`／`px1` 的實際座標，**逐像素驗界內**。這是直接證明，不是代理。
  記得先 `assert(rects.length > 0)`。

另外補一條硬錨點（防悄悄回退）：斷言區塊內帶 `T374` 註解字樣，並斷言
`/g\.fillRect\(ax-118,ay-148,52,28\)/` **不再存在**。
