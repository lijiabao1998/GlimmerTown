# T528 讀檔不得憑空編造世界（第一刀：草地變體變成 x&3 條紋）

**日期**：2026-08-19　**發卡**：Claude（業主授權：自己玩→出卡→施工→合併）

## 0. 為什麼現在查存讀

T527 證明遊戲**每 25 秒自動存檔一次**。這件事把「存讀」從偶爾用到的功能，
變成**每個玩家每天都在走的路**——關掉再打開就是一次 `load()`。
所以存讀保真度值得一次認真的量測。

**第一版量測幾乎是空跑的**：我猜的鉤子 `GV.tiles()` 不存在，
整個地塊層默默沒被比較，只比到 `stats()` 的 16 個數字就報「1 項不一致」。
**觀測面太小的綠不算綠。** 換成寬觀測面（逐格全欄位 + 逐棟全欄位 + 20 個 GV 鉤子遞迴攤平，
共 **183,124 個觀測項**）之後，才看得到全貌。

## 2. 本卡的缺陷

`t.gv` 是草地貼圖變體（`SPR.grass[t.gv&3]`，四種），世界生成時 `gv:ri(4)` 每格隨機。

- `save()` **不存 gv**。
- `load()` 第 ~21996 行寫 **`gv:i&3`**。

地圖 `N=72`，而 **72 % 4 === 0** ⇒ `i&3 === (y*72+x)&3 === x&3`
⇒ **讀檔之後每一列固定一種草地貼圖**，全圖變成 4 格週期的規律重複。

**實測（seed 528、120 天、3,198 格草地）**：

| | 「整列同一變體」的列數 | gv 分佈 |
|---|---|---|
| 存檔前 | **0 / 72** | [834, 815, 736, 813] |
| 讀檔後 | **72 / 72** | [809, 812, 791, 786] |

`gv === x&3` 命中 **3,198 / 3,198（100%）**。

**視覺量級如實說**：四種草地變體的差異是零星細節像素（草叢/小花的位置），
所以在正常縮放下**不刺眼**；3 倍放大開闊草原時**可以看出細節沿對角線規律重複**。
這是一個「正確性明確、視覺訊號細微」的缺陷，不是刺眼的破圖——卡面不誇大。

## 3. 落地

1. **存**：新增可選通道 `gvc`，每格一字元 `'0'`-`'3'`（沿用 `tre` 的 `String.fromCharCode(48+n)` 先例）。
2. **讀**：有 `gvc` 就照存的還原；**舊檔沒有這個通道**就改用 `streetHash(x,y,salt)&3`
   取代 `i&3`——`streetHash` 是既有的座標決定性純雜湊（T146，**不消耗 `R()/ri()`**，鐵律2 安全），
   這樣**舊檔也一併從條紋變回隨機外觀**（含業主自己的存檔）。salt 取未使用值並在原文註明。
3. 鐵律9 遵守：只新增可選欄位，舊檔缺欄位有容錯。
4. 不動 tick、不動任何模擬語意 ⇒ **六哨兵應位元恆等**（哨兵是純 tick，不經存讀）。

## 4. 驗收計畫

- **G1 往返恆等（本卡靈魂）**：存檔前後逐格 `gv` 必須**完全相同**（不是「看起來像隨機」，是**同一個值**）。
- **G2 舊檔回退**：拿掉 `gvc` 通道的存檔讀進來，`gv` 不得等於 `x&3`（不准退回條紋），
  且必須決定性（同一存檔讀兩次結果相同）。
- **G3 零亂數**：新增碼不得消耗 `R()/ri()`（機械掃，非條件跳過）。
- **G4 鐵律9**：舊檔（無 `gvc`）必須能讀、不報錯。
- **六哨兵位元恆等**。
- **像素證**：修後「讀檔畫面」與「存檔前畫面」在草原區逐像素比對，差異應趨近 0。
- 紅源：①存了但讀不回（讀端寫死）②舊檔回退改回 `i&3`③新增碼裡插 `R()`。
