# T536 貸款按鈕的防線只在渲染層（同族病第五例）＋銀行額度 toast 謊報

**日期**：2026-08-19　**發卡**：Claude（業主授權：自己玩→出卡→施工→合併）

## 0. 實測

貸款按鈕的防重複**只在渲染層**（有貸款時整顆按鈕換成「還款中」文字），
**點擊處理器本身沒有 `!loan` 防線**——而 AI 內部的兩條貸款路徑（地鐵購車、服務車輛）都有：
```js
if(allowLoan&&!loan){...}   // AI 兩處都防
if(lb)lb.addEventListener('click',()=>{ money+=...; loan={...}; ... })  // 玩家按鈕沒防
```

**可達的真實窗口**：城市面板開著（按鈕在），遊戲照跑，tick 裡 AI 自動貸款讓 `loan` 變非空
——面板不會自動重繪 ⇒ 按鈕還在 ⇒ 真點擊觸發處理器 ⇒ **AI 的債被覆蓋歸零＋再拿一筆本金**。
實測（以 stale 元素等價重現該窗口）：有貸款在身時觸發處理器，
資金 +$6,000（三次）、債務仍只剩一筆 20×120＝**前面的債全被洗掉**；
逐日觸發 10 天＝**+$19,700 純白拿**。

**第二件（顯示謊報）**：銀行（k86）解鎖 $5000/40 天額度，toast 卻寫死「🏦 貸款到帳 $2000！」。

**同族病第五例**：T518（DOM id）→ T530（RDEP）→ T533（存檔形狀）→（T535 順修 insToastDay）→
**T536（貸款防線 AI 有、玩家按鈕沒有）**。同一條規則兩處各寫一份，其中一份必被忘記。

## 1. 落地（兩行修）
1. 處理器開頭加防線：`if(loan){toast('已有貸款在身，先還清再借','bad');showStats();return;}`
   （渲染層防線保留＝雙層；處理器防線堵 stale 面板窗口）。
2. toast 金額誠實：依實際額度顯示 $2000 或 $5000。

## 2. 驗收計畫
- **G1 行為**：有貸款在身時觸發處理器 ⇒ 資金不變、債務不變、出現「先還清再借」提示。
- **G2 正向**：無貸款時照樣借得到（防線不得把功能鎖死）。
- **G3 toast 誠實**：銀行城借款訊息含 $5000、無銀行城含 $2000。
- 六哨兵位元恆等（按鈕處理器不在 tick 路徑）。
- 紅源：①拿掉處理器防線 → G1／②toast 改回寫死 → G3。
