# T141 通勤/就業 agent（比 TheoTown 更真的因果）
版本：v3.9 ｜ 難度：★★★ ｜ 前置：T129（壅堵場）｜ 建議模型：Sonnet

## 目標
住宅簇每 tick 生成少量通勤 trip 沿路網往最近就業區，計入壅堵 load；不可達或過長者拉低該樓財富/幸福。讓壅堵與財富有真實成因——可宣稱「比 TheoTown 更真」的深度差異（判準 8）。

## 定位錨
- 道路網 BFS（`busBFS` 多站尋路先例）、壅堵 `roadLoad`（T129）
- `judgeWealth`（財富判定）、jobs/就業區、happyParts
- **叢集級 agent 計數**（非逐人尋路，控成本）

## 允許觸碰
- 每 N tick 對住宅簇級別算通勤：從住宅代表格 BFS 到最近就業區（商業/工業/辦公），沿路段累加 `roadLoad`（與 T129 壅堵場耦合）；距離/可達性快取（避免每 tick 全城 BFS，用衰減式更新或分批）。
- 通勤結果影響：不可達（無路連到就業）或路徑過長（>閾值）→ 該住宅 `judgeWealth` 扣分、happyParts 新增「通勤」項扣幸福。
- `GV.commuteLoad`/`GV.commuteAt(x,y)` 鉤子（可觀測 trip 對 load 的貢獻，判準17）。

## 硬性不變量
- 通勤計算**不消耗 R()**（確定性，或用專用不影響主流的隨機源）。
- **無道路/無就業區時通勤零效果，同種子 30 天位元回歸與基準一致**（通勤項在無路網時恆 0）。
- 叢集級近似，效能可控（大城不掉 tick，用快取＋分批 BFS）。
- 運行時通勤場不入存檔（重算）。

## 本卡驗收
1. 三件套照常。
2. 住宅遠離就業區＋單一道路連通→通勤 load 沿路上升（GV.commuteAt 驗）、該區財富/幸福受距離拉低；就近建就業區→通勤負擔下降、財富回升。
3. 不可達住宅（孤島）→通勤懲罰最重。
4. 無路網/無就業城 30 天位元回歸；大城效能不掉 tick（幀時間採樣）。
