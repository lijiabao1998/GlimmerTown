# T366 — 工具鏈小修二合一：atlas 認 sc＋merge_bay 控制台編碼

狀態：**出卡提案，待業主發卡與指派施工者。**
提案者：Kimi（2026-07-27）；發卡：待業主
前置：T364（sc 管線與十三建）、T358/T358.1（交易式工具鏈）、T365 已進 master。

## 背景（兩筆已記錄的技術債）

1. **atlas.html 不認 `sc` 欄**：T364a 為新波建築引入 sprite metadata `sc`
   （raw 2× 畫布＋`sc:.5` 繪製），但圖鑑頁仍以 raw 尺寸渲染——k121–133 在 atlas
   顯示為遊戲內 2 倍大，錨點十字也偏移（純展示問題，遊戲內正確；T364 CHANGELOG 已記）。
2. **merge_bay.py 在 GBK 主控台炸 U+FFFD**：Windows 中文主控台（cp936/GBK）下，
   印出 verifier 輸出中的非 GBK 字元直接 `UnicodeEncodeError` 中斷交易
   （T364b/T364c/d 兩輪合併都撞到，靠 `PYTHONIOENCODING=utf-8` 繞過；已記 CHANGELOG）。

## 子項

### T366a atlas.html 支援 sc 顯示

- `sprAtlas356()` 的 entries 本就帶 `sc`（T364a 起），atlas 渲染處對有 `sc` 的條目
  以 `w*sc × h*sc` 顯示、錨點十字同步乘 `sc`；卡片標註 raw 尺寸與 sc 值（資訊不丟）。
- 指紋（CRC32）計算**維持對 raw 畫布**，不得因顯示改動影響既有指紋值與匯出格式。
- 無 `sc` 的既有條目渲染逐像素不變。

### T366b merge_bay.py 控制台編碼防炸

- CLI 入口對 `sys.stdout`/`sys.stderr` 做 `reconfigure(errors='replace')`
  （或等價包裝）：任何環境下印出非主控台編碼字元時替換為 `?`，不拋例外。
- 不改任何交易邏輯、日誌內容語義、檔案寫入（journal/receipt 本來就是 UTF-8 檔案，
  不受主控台編碼影響）；POSIX 環境行為不變。
