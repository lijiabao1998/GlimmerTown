## 問題（Kimi 於 T368 施工期讀碼查明，業主已確認屬實）

T367 把 12 處移動實體的 dep 換成 `viewDep()`，但 **objs 主迴圈的地格 dep 沒轉**：
`index.html` objs 地格迴圈（`const objs=[];` 之後）——

```js
const dep=(t.bld&&(t.bld.k===9||t.bld.sz>=2))
  ?((t.bld.ref?x:(t.bld.sz?x+t.bld.sz-1:x+1))+(t.bld.ref?y:(t.bld.sz?y+t.bld.sz-1:y+1))+y*.001)
  :x+y+y*.001; // T39-T60 多格建築深度以 SE 角計
```

後果（rot≠0）：南北相鄰格遮擋順序錯（實數推導：rot=1 下 A(10,10)/C(10,11)
世界 dep 20<21、view dep 71>70 正好相反）；地格（世界 dep）與實體（viewDep）
兩套基準混排。密集城市旋轉時建築/樹/裝飾與車船會互相穿模。
rot=0 不受影響（`viewDep(x,y)===x+y` 恆等）。

## 修法（業主已裁定方向，不得更改）

1. **單格**：`dep = viewDep(x,y) + y*.001`（小數尾碼保留世界 y——rot=0 精確等於舊值）。
2. **多格（k9／sz≥2）**：對 footprint 每格取 `viewDep` 的**最大值**作 dep
   （比照 13568 行錨點修正的同一掃描；k=9 掃其 2×2）。rot=0 時最大值即舊 SE 角公式
   `(x+sz-1)+(y+sz-1)`／k9 的 `(x+1)+(y+1)`——**rot=0 逐位元不變是硬不變量**。
3. 尾碼統一保留 `+y*.001`（世界 y，非 view y），避免 rot=0 排序漂移。
