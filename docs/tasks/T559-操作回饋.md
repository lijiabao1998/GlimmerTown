# T559 操作回饋（靜默失敗要說話：框選單擊拒因＋分區被覆蓋提示）

**日期**：2026-08-25　**發卡**：Claude（馬拉松；T554 撤卡的唯一倖存真問題＋P3-1）

## 0. 病灶（兩個，同屬「操作沒有回音」家族）

1. **框選工具單擊無效格零回饋**（T554 判決實驗量到的唯一真問題）：
   點放型建築走 `doPlace(silent=false)` 本來就會 toast 拒因；但 `zr/zc/zi/doze/park/tree/fill`
   七個框選工具的單擊走 `commitRect`，對無效格 `continue` 靜默跳過——實測對路格點住宅區：
   zones／money／toast 計數（notif526.total）**三軸全不動**。新手沿路畫區點到路緣就是這個。
2. **大建築壓分區無警告**（P3-1）：大建築（太陽能等）置放會直接 `ct.zone=0` 清掉已畫分區，
   無提示、分區費不退。**43 個 `ct.zone=0` 案點散在 doPlace 各 case**——逐案插裝是同族病溫床。

## 1. 落地（各一個單點，零 per-case 改動）

1. `commitRect` 尾端：`done===0 && single` 時，把 **`canPlace` 的拒因原樣 toast**
   （`'道路上不能建造'` 等既有文案，零新字串）＋`sErr()`。
   **框選（多格）零落地維持靜默**——掃過無效格不吵是框選的既定語意，卡面明記。
2. `closeUndo()` 單點：手勢收束時掃 `undoGroup.snaps`，統計「快照時 zone≠0、現在 zone=0」
   的格數 N；`N>0 && tool!=='doze'` → toast `⚠️ N 格分區被覆蓋（可 Ctrl+Z 復原）`。
   - **為什麼掛 closeUndo**：快照本來就在每個清 zone 的案點寫入（undo 機制的既有義務），
     單點讀快照＝43 個案點全覆蓋、未來新案點自動納入。
   - **doze 排除**：拆除是明示刪除，提示是噪音。
   - **重畫分區不觸發**：zr 蓋 zc 是 zone 值替換（≠0），不會計入。
   - 「可 Ctrl+Z 復原」是真話：快照裡的 zone 由 undo 原樣還原。

## 2. 為什麼這張卡是安全的

兩個掛點都在**手勢路徑**（pointerup／commitRect），不在 `tick()`；toast 走既有 notif526 管線；
零 `R()/ri()`。⇒ **六哨兵位元恆等、像素指紋 0 變更**（無精靈改動）。
**動 index.html** ⇒ bump v11.179、arch --fix、fp_snapshot 重跑、合併 --deploy。

## 3. 驗收計畫（套件檔尾 T559 塊，用既有 `pointer()` 手勢模擬器）

- **G1 拒因說話**：選 zr、pointer 單擊路格 → notif526.total +1 且 zones/money 不變。
- **G2 覆蓋提示**：畫 zone、蓋大建築於其上（手勢路徑）→ toast 計數 +（含置放本身的提示則
  以差分斷言）、快照法數出的 N 正確。
- **G3 無噪音**（對稱釘）：pointer 單擊**可建格** → 放置成功且**不多出**拒因/覆蓋 toast。
- **G4 doze 排除**：doze 拆分區 → 不出覆蓋提示。
- **G5 零亂數**：新增碼機械掃。
- **G6 六哨兵位元恆等＋像素指紋 0 變更**。
- 紅源：①拿掉 commitRect 拒因分支 → G1 紅；②拿掉 closeUndo 覆蓋統計 → G2 紅；
  ③把拒因條件改成無條件（valid 也 toast）→ G3 紅（防「用噪音修靜默」的反向失敗型）。

**明確不動**：框選多格的靜默 skip 語意；43 個 `ct.zone=0` 案點一行不碰；分區費不退的
經濟語意（另屬決策項）；doPlace 的點放 toast 路徑。
