# T148 手繪像素英雄建築（手繪素材混合）
版本：v4.1 ｜ 難度：★★★ ｜ 前置：無 ｜ 建議模型：Sonnet

## 目標
把最重要的地標級建築從「純演算法生成」升級為「**親手編寫的像素資料表**」——由施工代理逐格設計、以調色板索引字串編碼進原始碼，再由既有管線上色/夜燈/雪化。這是視覺品質最大的一次躍升，也是「手繪素材混合」的具體形態。

## 紅線（不可違反）
**所有像素資料必須原創**，由你逐格設計。**嚴禁**參考、描摹、轉換任何 TheoTown 或其他既有遊戲的素材。畫風要與本作既有等距像素風一致（64×32 基底、2:1 斜率、同調色邏輯），但構圖與細節全部自創。

## 目標建築（挑 4 座英雄建築）
`k=24 地標`、`k=51 太空研究中心(3×3)`、`k=42 市政廳(2×2)`、`k=32 大學(3×3)` —— 這四座是玩家最會盯著看的。

## 定位錨
- `buildSprites` 絕對尾端；既有多格建築 sprite 生成區塊（機場/大學先例）
- night 圖層合成、冬季雪化規則、`SPR.bld` 鍵慣例

## 允許觸碰
- 新增像素資料格式：如 `const HERO_PIX={ '24_1_0': {pal:['#000','#c8b48a',...], rows:['..AABB..','.ABBCC.',...] } }`（每字元一個調色板索引，`.`＝透明），置於資料區；配套 `drawHeroPix(key,ctx)` 解碼繪製。
- 於 `buildSprites` **絕對尾端**：四座英雄建築改由 `HERO_PIX` 解碼生成（覆蓋既有程序化版本的同鍵），並沿用既有管線加 night 窗燈層與冬季雪簷。
- 尺寸須與既有同 k 佔格對齊（2×2/3×3 的 footprint 與錨點不變，否則放置對不齊）。

## 硬性不變量
- **只替換這四個鍵**，其餘 SPR 鍵 checksum 與改動前**位元一致**（`__noHero` 開關證明零亂數位移）。
- footprint／錨點（ax/ay/w/h）與替換前一致——放置、多格 ref、doze、小地圖皆不得錯位（實機放置驗）。
- night 層與冬季版同步存在（入冬 `GV.setDay(310)` 零錯誤、雪化正常）。
- 像素資料完全原創（在 summary 明確聲明逐格自創、未參考任何既有遊戲素材）。

## 本卡驗收
1. 三件套照常。
2. `__noHero` 開時全鍵位元一致；關時四鍵 checksum 改變且非透明像素數合理（有實體內容）。
3. 四座實機放置：位置對齊不錯位、多格 root+ref 正確、拆除整棟消失、小地圖色正確。
4. 夜間窗燈可見；`GV.setDay(310)` 入冬雪化正常零錯誤。
5. 視覺品質：區域取樣色彩多樣度較替換前上升（手繪細節更密）。
