**日期**：2026-08-19　**發卡**：Claude（業主授權：自己玩→出卡→施工→合併）

## 0. 實測（帳本調查筆記五的完整數據）

唯一完成過的都是 `transit400`。

## 1. 兩個發單側的根因（都不在模擬層）

**根因一：發單不看城市有沒有能力做。**
鋼材/燃料四條委託（**$10,200 獎金池**）需要 `k122 鋼鐵廠`／`k121 煉油廠`；
而這兩座**不在 AI 的 78 條 `wants` 清單裡**，玩家也很少主動蓋
⇒ 城裡鋼材/燃料恆 0，這四張單發出去只有一個結局：過期。
（給錢手動蓋齊後這條鏈**是通的**——鋼 2/日、燃料 3/日、工業稅乘數 ×1.12 確實啟動、
`ct_fuel80` 其實可達；礦脈約 240 天耗盡＝有時限的加成。所以**機制沒壞，是發單沒看條件**。）

**根因二：合格委託 ≤3 時根本不抽選。**
```js
const elig=CMS385.filter(...);
if(elig.length<=3)return elig.slice();   // ← 直接全回，沒有抽選
```
低階城市（`minRank` 過濾後只剩 ≤3 條）每次都拿到**完全相同的三張**
⇒ 過期後又抽到同一張。實測 seed528 `trade1200` **連續過期三次**、
seed301 `techC6` 過期兩次。玩家視角＝遊戲一直塞同一張你做不到的單。

## 2. 為什麼這張卡是安全的

`cmsOffers385()` 全檔只有三個呼叫點：`cmsAccept385`（玩家動作）、委託面板 UI、`GV` 鉤子。
**tick 裡沒有任何呼叫** ⇒ 改發單邏輯對模擬**零影響** ⇒ **六哨兵應位元恆等**。

## 3. 落地（只動發單，不動任何目標值、不動 AI、不動 tick）

1. **可行性閘門**：每條委託標一個 `feas` 判定（純讀現況、零亂數）：
   - `steel*` / `ct_steel60` → 城裡有 `k122`
   - `ct_fuel80` → 城裡有 `k121`
   - `trade*` → 城裡有貿易站（`k?` 由 COST/工具反查，不手抄）
   - `transit*` / `happy*` / `tech*` → 無結構前提，恆可行
   不可行者**不進發單池**。城市蓋了加工廠，那幾張單自然出現＝**引導而非懲罰**。
2. **不連發剛過期的那張**：記 `lastExp`（不入存檔、鐵律7 三處歸零），
   發單池排除它；若排除後池空則放行（**永不讓池變空**＝不准靜靜關掉整個系統）。
3. **抽選在池 ≤3 時也要動**：`elig.length<=3` 那條早退拿掉，讓 `lastExp` 排除生效。

**刻意不做**：不動任何目標值。`happy80` 的 .78 高於我實測的幸福峰值（.74），
但我的數據**全是 AI 城**——手玩城市可能達得到，**憑 AI-only 數據去調目標值是不誠實的**，
如實記在卡面與帳本，留給業主或後續有玩家數據時再定。

## 4. 驗收計畫

- **G1（靈魂）發單池永不為空**：任何城市狀態下 `cmsOffers385()` 至少回 1 條
  ——這條擋的是「可行性閘門寫太嚴，把整個系統靜靜關掉」。
- **G2 可行性**：沒有加工廠的城市，發單池不得含 steel/fuel 四條；
  蓋了 `k122` 之後 steel 系必須出現（雙向）。
- **G3 不連發**：剛過期的 id 不得出現在下一次發單池（除非池會因此為空）。
- **G4 零亂數**：發單側新增碼不得消耗 `R()/ri()`（機械掃，非條件跳過）。
- **G5 六哨兵位元恆等**（發單不在 tick 路徑）。
- **行為證明**：重跑「見單就接」500 天 × 三城，**過期率必須顯著下降**，
  且完成件數不得下降（不准靠「不發單」把分母做小＝G1 的鏡像）。
- 紅源：①閘門寫成把所有單都濾掉（G1 應紅）②沒有加工廠也發 steel 單（G2 應紅）
  ③連發剛過期的單（G3 應紅）。
