## 0. 問題（親手實測，不是推論）

在 master `59b785a` 上跑 `docs/tools/art_diff.html`（8141 埠，headless Chrome，虛擬時間預算 900s）：

```
a=/index.html  entries=0 families=0 skipped=0  畫布台帳：相異 canvas 0 張 / 0 px（其中 img 0 張 / 0 px，night 0 張）
MISSING bld/25_1_0
—— 量測完成 ——
```

**1 秒就跑完，讀到 0 個素材，然後用綠字宣告「量測完成」。**

### 根因（逐行定位）

`docs/tools/art_diff.html:57`：

```js
const tick = () => { const w = f.contentWindow; if (w && w.GV && w.GV.sprAtlas356) return res(w); setTimeout(tick, 250); };
```

- `window.GV={…}` 在 `index.html:21196` 建立、`sprAtlas356` 在 `:21327` 定義——**兩者都在解析期**。
- 真正把素材畫出來的 `bootstrap426`（`index.html:21034`）是 **async**，
  分段呼叫 `buildSpritesS1..S9`（`:2063`／`:2176`／`:2205`／`:2520`／`:2603`／`:3135`／`:5182`／`:6079`／`:9528`），
  `SPR.bld` 要到 S3 之後才有東西。
- ⇒ 就緒條件在**圖集完全空的時候**就為真。

這支工具的就緒條件寫於 T420（當時開機是同步的），T426 把開機改成 async 分段，
**沒有人回頭改它**，於是它從 v11.62 起就一直在量空氣。

### 為什麼這是「綠字失敗」而不是「壞掉」

它不會報錯、不會 exit 非 0，它印一行綠色的「量測完成」。
本專案已經有兩次同型事故：T421 的 harness `fillRect` 是空殼（像素完全不可觀測卻全綠）、
T428 的探針有五條假綠通道。**這是第三次，而且這次壞的是「唯一的像素證據來源」。**

## 7. 帳本（施工實錄）

### 挖到的比預期深：有**兩個**根因，第二個更硬

| # | 根因 | 證據（我親手量的） |
|---|---|---|
| 1 | **就緒條件在解析期就為真** | `art_diff.html:57` 舊寫法 `w.GV && w.GV.sprAtlas356`；而 `window.GV={…}` 在 `index.html:21196`、`sprAtlas356` 在 `:21327`，都在解析期。master `59b785a` 實測輸出 `entries=0 families=0 skipped=0 … MISSING bld/25_1_0` ＋ 綠字「量測完成」，1 秒跑完 |
| 2 | **遊戲在「不繪製」的環境裡根本開不了機** | 直接量 `__boot426()`：headless iframe 停在 **pct=5**（`初始化像素素材引擎…`）、Browser 面板未顯示時停在 **pct=2**，`buildSpritesS1()` 從來沒被呼叫。原因是 `bootPaint426`（`index.html:21011`）是**雙重 `requestAnimationFrame`**，而 rAF 在離屏／隱藏文件裡不觸發 |
| 2b | **工具自己把量測 iframe 放在螢幕外** | `iframe{position:absolute;left:-9999px;width:64px;height:64px}`——離屏 iframe 會被節流 rAF。即使在**可見**瀏覽器裡也會卡住 |

### 落地的修改
1. 就緒條件改用 bootstrap426 的**顯式完成訊號** `__boot426().ready`（`index.html:21053` 設、`:21063` 曝露），
   fallback 是「清冊非空」，**永遠不接受「清冊為空」當就緒**。
2. 逾時改用**輪詢次數**而非 `Date.now()`——虛擬時間會把牆鐘快轉，第一版就是這樣把自己誤判成逾時。
3. `entryMap()` 自我防呆：`entries===0` 或 `bld` 家族為空 ⇒ **拋錯**。
4. `main()` 補 `.catch`：把失敗印成紅字並掛 `window.ART_DIFF_ERROR`，**絕不印「量測完成」**。
5. iframe 改成頁面內、900×640、可見（修 2b）。

### 驗收現況（如實）

| 判準 | 結果 |
|---|---|
| **A3 退回舊就緒條件必須被攔下** | ✅ **實測通過**：輸出 `✘ 量測失敗…素材清冊為空（entries=0）`，且**沒有**「—— 量測完成 ——」 |
| A2 餵空清冊必須紅 | ✅ 同一條防呆路徑（A3 已證），但因根因 2 導致該變體在無頭下卡在開機、未取得獨立輸出 |
| **A1 修好後讀到非零素材** | ❌ **本卡當下做不到** → ✅ **已由 T434b 解除（見下方「後續更正」）** |
| A5 三檔位元不動 | ✅ |
| A6 閘門 ALL GREEN／PASS 恰 4,810 | ✅ |

**A1 需要一個會真正繪製的瀏覽器**。試過且無效的路：`--disable-gpu` 的有無、
`--disable-background-timer-throttling`／`--disable-backgrounding-occluded-windows`／
`--disable-renderer-backgrounding`／`--run-all-compositor-stages-before-draw`、
把 iframe 放大到 900×700、虛擬時間 900s。
也試過走 `index.html:21064` 的同步分支當退路，但 `buildSprites`／`buildSpritesS1` **沒有掛在 window 上**
（實測 `typeof w.buildSprites === 'undefined'`），`GV` 的 213 個鉤子裡也沒有可強制建圖的入口。

**所以本卡的定位要說清楚**：它把一個**綠字失敗**變成**大聲的紅字失敗**——這是嚴格的改善，
但它**沒有**讓 art_diff 在無頭環境下可用。要讓後續美術卡真的有像素證據，還缺一步，見下。
