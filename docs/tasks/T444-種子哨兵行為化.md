`assert(window.GV.stats().pop === 3781` 的**文字**，哨兵會數到 1；
貼兩行就數到 2，**閘門全綠而釘子一根都不在**。

## 4. 施工紀錄（Claude 全鏈；起點 master `5e74f93`，**不動 `index.html`**，PASS 4,922 → 4,928）

### 4.1 落地

- `test_fixde.js` 新增 `seedPin444(name, seed, days, expect, actual, note)`：斷言照舊，
  另印一行機器可讀的 `SEEDPIN name seed=… days=… expect=… actual=…`。
- 兩根既有釘（`seed301=3781`、`seed22=4550`）改走它。
- **第三根釘 `seed7=251`**（真跑量出來的值）。選它是因為它與另外兩根**分屬不同族群**：
  seed301 是拮据城、seed22 是健康城、**seed7 是一張低成長地圖**——釘子涵蓋到「難開的圖」那一端。
- `tools/verify.py` 的哨兵改成讀 `SEEDPIN` 行：驗根數 ≥ `MIN_SEED_PINS`（2→**3**）
  且每一根的 `actual === expect`；重複 name 只算一次。

實測輸出：`seed pins ran and matched: 3 (seed22=4550, seed301=3781, seed7=251)`。

### 4.2 方向證明（這張卡真正的重點）

舊哨兵 grep 的是原始碼字面 `assert(window.GV.stats().pop === <數字>)`。
紅源④把**三根釘全部拔掉**、再在註解裡貼三行同樣格式的文字：

| | 舊哨兵 | 新哨兵 |
|---|---|---|
| 數到幾根 | **3 根** | 0 根 |
| 閘門 | **全綠** | `exit=1` |

也就是說舊制擋的是「有人把釘子寫得更好」，擋不住「有人把釘子拔掉」。

### 4.3 其餘紅源

| 紅源 | 結果 |
|---|---|
| 拔掉第三根釘 | `verify` exit=1（`seed pins=0 below baseline 3`）＋套件 `T444 G2b` 紅 |
| 把 `seed22` 的釘值改成 4551 | `verify` exit=1：`seed pins RED: seed22 reported actual != expect` |
| 把 `MIN_SEED_PINS` 偷偷改回 2 | 套件 `T444 G3` 紅 |

① 的哨兵讀到 0 而不是 2，是因為套件是 fail-fast 的：`T444 G2b` 這條靜態守衛在跑到執行期釘子之前就先紅了，
所以那一輪一行 `SEEDPIN` 都沒印出來。**如實記下這個機制**，不要讓人以為它「數到 2」。

### 4.4 這張卡被自己的閘門擋了一次（拆成兩步的理由）

第一次送合併，`merge_bay.py` 直接擋下來：

```
[FAIL] seed pins=0 below baseline 2
[FAIL] bay verification failed; master is unchanged
```

原因是 `merge_bay.py` 用的是 **canonical verifier**——`C:\dev\glimmer-town\tools\verify.py`，
也就是 **master 上那一份舊的**。車位把釘子改走 `seedPin444` 之後，
舊哨兵去 grep 車位的 `test_fixde.js`，數到 0 根。

**擋得對，而且擋得很有意思**：這正是這張卡在講的那個缺陷，
在它自己身上示範了一次——舊哨兵擋的就是「有人把釘子寫得更好」。

換閘門的標準做法是**先放寬、再收緊**，所以拆成兩步：

| | 內容 | 為什麼能過 |
|---|---|---|
| **T444a** | 只改 `verify.py`：舊 grep 或新 `SEEDPIN` **任一成立**即可，門檻維持 2 | 車位的 `test_fixde.js` 還是舊寫法 ⇒ 舊路徑成立 |
| **T444b** | 釘子改走 `seedPin444`、加第三根、門檻升 3、**拿掉 legacy 路徑** | canonical verifier 已經看得懂 `SEEDPIN` |
