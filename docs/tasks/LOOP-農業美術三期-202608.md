## R1-R2 小結(2026-08-02)

**T395 落地**:網格感的三個真來源已查明(高對比田埂框/壟週期與等距格不可公度/鄰田作物必不同),
本輪修掉前兩個——壟週期 6→8 使南北向 −64 的相位增量歸零、株格點改 (4s,2s)/(−4s,2s) 使
(±32,16) 成為其整數倍,**零額外 sprite、零記憶體代價**(相位變體法需 ×3 烘焙 +26MB,已否決)。

**T396 撞牆,結論有價值**:離線樣張證實鋪滿後九塊田確實連成一片,但直接放大會埋掉
base 自帶招牌建築 5403px,而 T380a 已把該門檻收到 0(二值不變量,有 T378 事故實測背書)。
**根因不是參數而是物件設計:k22 中央被農舍佔著,田在它身上永遠只能是配角。**
兩條出路(田避開招牌矩形 / 新增純農田地塊)寫在 T396 卡面,推薦後者。

**方法論產出**:離線樣張渲染器(scratchpad/t395_render.js)——抽 index.html 的 field/plantGrid
原文 eval + 30 行 mock canvas + zlib PNG 編碼,可在 node 內直接渲染多格拼接圖做新舊對比,
不需瀏覽器、不需傳輸 base64。美術卡的「人眼軌」從此有低成本樣張來源。

## 美術卡的驗收特殊性(與功能卡不同,先寫明)

功能卡靠斷言證明「對」;美術卡的「美」無法斷言,因此雙軌:
1. **機器軌**(我負責,必須全綠):零亂數守衛(新繪製碼禁 R()/ri() 字面量)、
   像素回歸(改動前後同種子同視角雜湊——**美術卡預期雜湊會變**,故改為「基線重釘+
   逐項差異說明」而非恆等)、決定性重繪(同狀態畫兩次必須逐位相同)、
   四季×晝夜×四旋轉不炸、畫質檔位降級路徑不炸、效能不退(幀時間量測)。
2. **人眼軌**(業主裁決):每卡收束附樣張(同一塊田的四季/晝夜/遠近),業主一句
   「行/不行/再密一點」即定案;不行就退修,不進 merge。

**與功能卡的關鍵差異**:像素雜湊不再是恆等鐵證,而是「變更範圍證明」——
必須證明**只有農業相關格變了**,城市其他部分逐位不動(用不含農地的種子/視角做對照)。
