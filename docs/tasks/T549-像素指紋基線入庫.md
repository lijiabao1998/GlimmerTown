# T549 像素指紋基線入庫（ARCH §10.6 收口：亂數位移全圖重繪的最後盲區）

**日期**：2026-08-21　**發卡**：Claude（業主授權：自己玩→出卡→施工→合併）

## 0. 債的現況（ARCH §10.6 原文）

「sprite 像素在 Node 套件裡根本測不到……真正的像素指紋（CRC32）在 `atlas.html`，
但**倉庫裡沒有提交任何指紋基線檔**，也不在任何自動閘門裡。
亂數流位移造成的全圖重繪，機器測不出來。」

業主 loop 清單四條 §10 債中，§10.9（T443）、§10.10（T443）、§10.14（T444）已收口——
本卡收最後一條。順帶更正清單過期三項（帳本記）。

## 1. 落地設計

1. **`tools/fp_snapshot.py`**：無頭 Chrome 探針模板（ThreadingHTTPServer＋拋棄式 profile＋槽3 紀律）
   載入 index.html iframe，經 `GV.sprAtlas356()` 清冊逐條 CRC32（img／night／nightCity 三列，
   與 atlas.html `bPins` 同算法同格式 `{fam/key:[crc,...]}`）→ 寫 `docs/SPR_PINS.json`
   （`__meta:{ver,count}`——**不含時間戳**＝可重現）＋ **印出與舊基線的 added/removed/changed 差異**。
2. **基線檔 `docs/SPR_PINS.json` 入庫**（先驗證：連跑兩次 CRC 必須逐鍵恆等＝確定性前提）。
3. **自動閘（套件守衛）**：讀基線檔——存在、可解析、`__meta.ver === GAME_VER`（**強制每次 bump
   重新產生**＝指紋差異必經人眼）、`count` 與鍵數自洽、鍵數 ≥ 現值下限（防基線被砍半）。
4. **ARCH §10.6 更新為已收口**（含操作步驟：收束順序插入「bump → arch --fix → ARCH 行 →
   **fp_snapshot（審差異）** → 套件」）。

**為什麼這樣就夠**：套件閘強制每卡重跑工具；工具強制把像素差異印在收束者眼前——
意外的亂數位移全圖重繪從「機器測不出來」變成「不看一眼就過不了收束」。
未動 index.html 模擬/渲染任何一行 ⇒ 六哨兵位元恆等（本卡 index 僅可能加 GV 鉤，若需要）。

## 2. 驗收計畫

- **G1 確定性前提**：工具連跑兩次，指紋逐鍵恆等（不恆等就不准入庫，卡面如實記哪些鍵漂）。
- **G2 閘門行為**：套件斷言基線存在／ver 同步／count 自洽／鍵數下限。
- **G3 差異可見**：工具對「舊基線 vs 新指紋」印 added/removed/changed（atlas bCmp 同語義）。
- 紅源：①基線 ver 改舊 → G2 應紅；②基線刪鍵（count 不一致）→ G2 應紅；
  ③工具端 CRC 表初始化改錯（多項式壞掉）→ G1 兩次恆等照過但與**舊基線全變**＝G3 差異爆量
  ——這條驗的是「差異可見性」而非套件紅，如實聲明其守法不同。
